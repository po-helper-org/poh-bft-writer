# HOWTODEMO — автономная система БФТ (8 шагов владельца)

Приёмочный сценарий: свежий человек проходит путь установки до validated
БФТ по этому документу, без подсказок извне. Автоматическая часть —
`./acceptance.sh` и `python3 smoke-e2e.py` (demo-профиль, без ключа);
живой fast-прогон — шаг 5 — требует реальный ключ Z.AI.

## 0. Предусловия

Docker (OrbStack/Docker Desktop), 6+ ГБ RAM, свободные порты 3080/3456/8008/8090.
Репозиторий poh-bft-writer (этот).

## 1. Установка и выбор режима

```bash
bash install.sh        # вопрос «Каким режимом будете пользоваться?» → 1 (UI)
```
CLI-режим (2) — прежний контур скиллов IDE-агента, не нужен для демо.

## 2. Подъём под ключ

```bash
cd harness && ./start.sh --demo
```
Скрипт сам: сгенерирует секреты → поднимет 9 сервисов → дождётся здоровья →
напечатает ссылку с токеном → посеет Трекер (проект «БФТ 2026-Q4», лейблы,
вебхук) и Шлюз (агент bft-box, демо-заказчик customer-demo, smoke-комната).
Демо-флаг подменяет LLM двойником — ключ не нужен.

Откройте напечатанную ссылку (или `cat .last-url`).

## 3. Онбординг (первый вход)

Пять слайдов → на пятом: вставьте ключ Z.AI (форма `id.secret`) →
«Проверить» → «Готово» → подсказка о рестарте:

```bash
docker compose restart harness-web
```
(без ключа — «Пропустить»: всё, кроме fast-прогона, работает; демо-модель
закрывает проработку). Голосовой ввод: браузерный или локальный (whisper).

## 4. Интейк — ввод требования

Откройте «Управление требованиями» (✎-кнопка в сайдбаре харнесса):
строка ввода — текст; 🎤 диктовка; 📎 файлы/фото/PDF (ложатся в
`workspace/bft/uploads/…`); ссылки-чипы «Источники».

## 5. Fast-скоринг ≤ 1 минута (нужен ключ Z.AI)

«Отправить →»: сессия со скиллом `/bft-fast` разбирает вводные → карточка
результата: скоринг, контакты (Заказчик/PO/Техлид — email из текста),
открытые вопросы. **Запустить проработку →** — инициатива уходит в Коробку
(Total): конвейер стартовал.

(Без ключа: шаг 6 стартует инициативу так же через демо-модель — см. smoke.)

## 6. Конвейер и указания

- Сайдбар: секция **«Указания»** — решения PO (кнопка «Ответить»), статусы
  диалогов с сотрудником (Трекер) и заказчиком (Matrix).
- Доска: **«Стадии | Конвейер»** — 4 колонки; клик по инициативе — панель
  процесса: светофор качества, «ждём: …», ссылки на Temporal-процесс,
  комнату заказчика и задачи.
- Сотрудник: `http://<host>:3456` — задача «сборочная/верификационная» с
  маркером инициативы; закрытие задачи продолжает конвейер (вебхук).
- Заказчик: `http://<host>:8090` (Element, логин customer-demo, пароль из
  вывода сида) — комната `#bft-…` с вопросом; ответ в чате фиксируется
  договорённостью (слушатель → submit).

## 7. Validated

Когда требования собраны (светофор зелёный) и все указания закрыты —
карточка на приёмке; PO принимает (кнопка в панели указаний или smoke) →
**stage=validated** — БФТ готов как контракт следующего этапа.

## 8. Автоматическая приёмка (гейты)

```bash
cd harness
./acceptance.sh            # сервисы, токен-ссылка, API, панель, Трекер, Шлюз — exit 0
python3 smoke-e2e.py       # полный конвейер до validated на demo-модели — exit 0
```

Ручной чеклист шагов 1–7 прогоняет человек; автоматика закрывает каркас.

## Эксплуатация

- `./update.sh` — обновление (git pull + rebuild, данные в томах).
- Ключи/секреты — только в `harness/.env` (в git не попадает).
- `--debug` — temporal-ui на `127.0.0.1:8233`.
