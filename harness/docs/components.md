# Как компоненты взаимодействуют: карта продукта

Один источник правды о взаимодействиях. Модули и термины — в GLOSSARY;
решения — в ADR 0001–0005. Диаграмма ниже — верхний уровень: детали
implementation (temporal, worker, postgres, светофор) спрятаны внутри Коробки.

## Модули (4 + 2 внешних)

| Модуль | Что это | Интерфейс (всё, что нужно знать вызывающему) | Implementation (спрятано) |
|---|---|---|---|
| **Харнесс** `harness-web :3080` | Интерактивный слой: PO/аналитики | URL в браузере; 6 плагинов; скиллы `/bft-*`; upload-API | dsh-ядро (npm-пин), код poh-bft-plugin, whisper, DSH_HOME |
| **Коробка** `box` (внутр. сеть) | Процессный слой: детерминированный владелец конвейера | **5 эндпоинтов**: `start · submit · board · initiative · control` + Bearer `ui` | temporal, box-worker, светофор качества, postgres, сценарии |

## Матрица взаимодействий

| Откуда → Куда | Протокол | Что передаётся | Когда |
|---|---|---|---|
| Харнесс → Коробка | HTTP `start` | бриф fast-результата (`contacts:`, источники, скоринг) | кнопка «Запустить проработку» |
| Харнесс → Коробка | HTTP `submit` | ответ человека на указание / итог агентного хода | карточка указания; конец хода сессии |
| Харнесс → Коробка | HTTP `board/initiative` | состояния конвейера, указания, таймлайн | поллинг панели (тихий, 30 с) |
| Коробка → Трекер | REST | создать задачу (4 типа), назначить, эскалировать | активности сценариев |
| Коробка → **Шлюз** | matrix-nio | создать комнату `#bft-<slug>`, выдать аккаунт заказчика, написать, напомнить | сценарии верификации |
| Коробка ← **Шлюз** | слушатель комнат | ответ заказчика в комнате | воркфлоу фиксирует договорённость |
| Заказчик → Шлюз | Matrix-клиент (Element из коробки или свой) | ответы на вопросы верификации | верификация |
| Коробка ← Трекер | **вебхук** | задача закрыта/коммент человеком | воркфлоу продолжается без опроса |
| Харнесс (агенты) → Трекер | REST | итог сессии комментом в задачу, статус | конец агентного хода (плагин) |
| Харнесс → z.ai | OpenAI API | fast-прогоны (glm-5-turbo), агентные сессии | интейк, руки |
| Коробка → z.ai | OpenAI API | deep-итерации пакета (worker) | сбор |
| Харнесс ↔ Воркспейс | файлы | uploads, чтение артефактов, frontmatter | всегда |
| Сотрудники → Трекер | UI | статусы, комменты, ответы | верификация |
| Харнесс → Трекер | ссылки | deep-link задачи с detail-страницы | просмотр |

Ключевой инвариант: **никто не ходит в Коробку, кроме Харнесса; Коробка ходит
только в Трекер, Шлюз (Matrix) и z.ai; агенты не знают про Коробку вообще** (их итог субмитит
плагин — ADR-0003 rev 2). Наружу во внешний контур ведёт один путь — Шлюз (ADR-0006).

## Три сквозных сценария

**S1. Запрос → конвейер.** PO вводит в интейке (текст/голос/файлы/ссылки) →
сессия fast (glm-5-turbo, ≤1 мин): письмо, csv, документ-шапка, `contacts:`
→ карточка результата → кнопка «Запустить проработку» → `start` → Коробка
создаёт инициативу (состояние **запрос**) и задачи сбора в Трекере →
конвейер пошёл.

**S2. Верификация (человек в цикле, два контура).** Сбор дал светофор → воркфлоу переходит в **верификацию**: внутренний контур — верификационные задачи в Трекере по адресатам (сотрудник, PO-руководитель) + карточки указаний в UI; внешний контур — Шлюз создаёт комнату `#bft-<slug>`, выдаёт заказчику приглашение, задаёт вопросы сценария → сотрудник отвечает в Трекере (вебхук), заказчик — в Matrix (слушатель) → `submit` → договорённости зафиксированы; молчание — таймер → напоминание → эскалация → чек-лист validated закрыт → **validated**, БФТ — контракт для следующего этапа.

**S3. Агентная задача (рука).** Сценарий создаёт сборочную задачу (например,
разведка) → карточка в Харнессе «В чат» → сессия с handoff-черновиком
(`/bft-recon …`) → ход окончен → плагин: `submit` в Коробку + коммент-итог в
задачу Трекера → воркфлоу читает исход как вход итерации (не замену светофора).

## Поверхности людей

| Поверхность | Кто | Где | Вид |
|---|---|---|---|
| Конвейер | PO | PO-доска плагина | 4 колонки: запрос/сбор/верификация/validated |
| Доска документа | PO | PO-доска плагина | 9 стадий (артефакты), как сегодня |
| Доска задач | сотрудники | Трекер | Backlog→В работе→Ждёт ответа→Готово, swimlane по типу, фильтр `bft:<slug>` |
| Интейк/указания | PO | Харнесс | форма ввода; карточки действий |

## Карта репозитория (итог)

```
poh-bft-writer/
├── install.sh            # выбор режима: UI | CLI
├── commands/ skills/     # CLI-контур (не трогаем)
├── plugin/               # Харнесс-половина: интейк, указания, доски, онбординг
├── box/                  # Коробка (вендор poh-bft-box): конвейер, сценарии, качество
├── tracker/              # обвязка Трекера: вебхук-приёмник, сид кварталов, роли
└── harness/              # развёртывание: compose (6 сервисов), профиль, start.sh
```

Compose-сервисы (8): `harness-web · box-mcp · box-worker · temporal · postgres ·
tracker · matrix · element` (+профили `debug`: temporal-ui, `demo`: llm-demo).
Минимум RAM — 6 ГБ (ADR-0006).
