# ADR-0012: Минимальный контур — портал до БФТ-документа

Статус: принято (2026-11-12)

## Контекст

Коробка выросла до 11 сервисов (портал, harness-web, коробка на Temporal,
Matrix/Element, трекер, разбор материалов, Кортекс, LLM-двойник), а основной
путь заказчика до БФТ-документа так и не собран целиком. Владелец сузил
фокус до одного сценария:

1. Заказчик отправляет требования.
2. Требования фиксируются (заявка в трекере).
3. Собирается bft-fast.
4. Собирается bft-deep.
5. Документ БФТ скачивается в .docx / .md / .pdf.
6. Заказчик видит свою заявку.
7. Видны все заявки.

## Решение

- **В запуске по умолчанию** — пять сервисов: `customer-web` (портал),
  `tracker` + `postgres` (Vikunja — заявки, вложения, «все заявки»),
  `context-ingest` (голос и документы заказчика), `cortex` (память
  организации). Плюс одноразовый `tracker-init`.
- **Профиль `legacy`** — коробка (`box-worker`, `box-mcp`, `temporal`),
  Matrix/Element, `harness-web`. Определения и тома не удалены:
  `./start.sh --legacy` или `docker compose --profile legacy up -d`.
- **bft-deep собирается в портале** — фоновым прогоном навыка по документу
  bft-fast, как сейчас собирается bft-fast; коробка для этого не нужна.
- **Настройки — внутри портала за паролем**: ключи провайдеров и плагины
  через штатные «Настройки» dsh, без правки `.env` и конфигов.
- **Кортекс остаётся**: раздел «Чьи зоны затрагивает и к кому обращаться».

## Последствия

- `start.sh` ждёт здоровья портала и печатает его адрес; сид Matrix — только
  с `--legacy`.
- Плагин harness-web (раздел «Требования» PO) работает только с коробкой и
  уходит вместе с ней.
- Порядок работ: bft-deep в портале → выгрузка .docx/.md/.pdf → страницы «моя
  заявка» и «все заявки» → настройки за паролем → сквозная отладка шагов 1–7.
