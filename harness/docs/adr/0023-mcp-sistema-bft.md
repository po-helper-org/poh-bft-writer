# ADR-0023: MCP «Система БФТ» — полный цикл для внешних ИИ-агентов

Статус: принято (2026-11-24).

## Контекст

Портал ведёт заказчика от идеи до БФТ в своём чате, моделью портала. Владелец
хочет, чтобы любой внешний ИИ-агент (Claude Code, Cursor, корпоративный агент)
подключался к коробке по адресу `/mcp` и проходил тот же цикл по методологии:
заявка → бриф → полный БФТ → форма вопросов → Confluence.

Решения владельца (2026-11-23):
- **Токены модели — того, кто подключается.** Тексты пишет модель агента. Знания
  и качество остаются в коробке: методология и шаблоны, память организации
  (Кортекс), ИТ-ландшафт, Jira/Confluence, проверки канона, хранение.
- **В Confluence публикует сам агент** своим Atlassian MCP; портал на запись в
  Confluence не выходит (шлюз источников по-прежнему только на чтение, ADR-0015).
- **Доступ — личные токены.** На сервере личность — из корпоративного входа
  (Authentik); в коробке без Authentik — минимальное управление пользователями.

## Решение

- **MCP-сервер в узле портала** (`mcp-server.ts`): Streamable HTTP без сессий,
  JSON-RPC (`initialize`, `ping`, `tools/*`, `prompts/*`, `resources/*`), ответ
  application/json. Без SDK — протокол мал, зависимостей у портала нет (как у
  клиента MCP в data-sources). Маршрут `/api/customer-form.mcp`; на сервере —
  `/bft/mcp` (nginx, без Authentik, заголовки Authentik вычищаются).
- **Инструменты цикла** (`mcp-bft.ts`), те же шаги и проверки, что у чата
  (общие схемы — `request-flow.ts`):
  `bft_start_request` (заявка + что знает организация) → `bft_add_customer_words`
  (стенограмма) → `bft_get_context`, `bft_search_confluence`,
  `bft_attach_confluence_page` → `bft_set_acceptance_demo` → `bft_submit_request`
  → `bft_create_brief` (шаблон bft-fast, primaryErrors) → `bft_approve_brief` →
  `bft_prepare_full_bft` → `bft_submit_full_bft` → `bft_create_form` →
  `bft_export_for_confluence` → `bft_record_publication`; `bft_get_request`,
  `bft_list_requests`. Промт `bft_full_cycle`, ресурсы `bft://guide`, навыки
  bft-fast и bft-deep, образец канона.
- **Полный БФТ без модели портала.** Сборка разделена (`bft-deep.ts`):
  `deepJudge` — задание (системная инструкция с правилами и образцом + вход) и
  приёмка текста (автоправки, bft-lint.py, проверки канона); `finishDeep` —
  страница ревью и deep.json. `bft_prepare_full_bft` проводит разведку по Jira и
  Confluence по запросам агента (без запросов и триажа моделью портала), собирает
  тот же контекст, что у модели портала (`deepContextInput`: слова заказчика,
  ответы формы, правки PO, Кортекс, находки), и отдаёт задание. Агент пишет канон
  и сдаёт его в `bft_submit_full_bft`; ошибки возвращаются списком, с третьей
  сдачи мягкие правила уходят в замечания (как у модели портала), после шестой —
  сборка неудачна.
- **Модель портала на заявки MCP не тратится**: сессия `mcp-…` — `startDeep`
  отказывает (кнопка «Да, согласен» на странице, ответы формы, «Собрать заново»);
  пересобирает агент — повторным `bft_prepare_full_bft`.
- **Доступ** (`access.ts`, `access-page.ts`):
  - `PORTAL_AUTH=sso` (сервер) — личность из `X-authentik-username`;
    `local` (коробка, по умолчанию) — пользователи портала: администратор заводит
    их на `/api/customer-form.users`, вход — `/api/customer-form.login` (scrypt,
    подписанная кука на 12 ч, 10 попыток за 10 минут).
  - «Доступ для ИИ-агентов» (`/api/customer-form.mcpAccess`): человек сам
    выпускает себе токен `bftmcp_…` (показ один раз, на томе — SHA-256, до 10
    действующих), видит последнее использование, отзывает. Страница даёт готовый
    конфиг клиента и команду `claude mcp add`. Открывается из меню портала
    (кнопка «Меню» на главной → «Доступ для ИИ-агентов»).
  - Заявки MCP принадлежат владельцу токена: чужую заявку инструменты не
    открывают. Отключённый пользователь (local) теряет и токены.

## Последствия

- Качество MCP-заявки зависит от модели агента, но планка та же: канон не
  принимается, пока не прошёл линтер и проверки портала.
- Заявки MCP видны PO там же, где все: трекер, «Управление БФТ», Инбокс.
- Публикация в Confluence — на стороне агента и его прав; портал записывает
  ссылку в заявку (`bft_record_publication`).
- Короткий адрес `/bft/mcp` — после разового шага владельца
  `install-nginx-bft.sh` и `BFT_MCP_PUBLIC=1`; до него адрес — маршрут портала.
- Портал в коробке по-прежнему открыт для заказчиков без входа; вход нужен
  только для выпуска токенов MCP и страницы пользователей.
