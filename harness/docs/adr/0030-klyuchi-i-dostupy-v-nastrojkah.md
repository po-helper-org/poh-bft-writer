# ADR-0030: Ключи и доступы — в настройках портала

Статус: принято (2026-11-25). Дополняет ADR-0012 (администратор, «Настройки»), ADR-0015 (шлюз
источников), ADR-0028 (отправка в Confluence).

## Контекст

Ключи портала разбросаны: ключи моделей — `harness/.env` и «Настройки → Модели», токен шлюза
источников выпускает свой скрипт, ключ агента ревью — свой скрипт или «Настройки → Портал»,
ключ записи в Confluence — ещё один скрипт, Google — только `.env`. Ответить на вопрос «какие
ключи заданы, откуда, когда менялись и работают ли» можно только по ssh. Владелец решил:
настройку всех ключей и доступов вывести в харнесс; ключ записи в Confluence взять из
окружения ИИ-агентов на том же сервере, где доступ к Confluence уже есть.

## Решение

1. **Раздел «Настройки → Ключи и доступы»** (только администратору, как «Портал»). Все ключи
   портала по группам: модели, источники (чтение Jira/Confluence), публикация в Confluence,
   трекер, материалы (Google), ИИ-агенты, вход. У каждого: задан или нет, откуда (настройки
   портала / окружение сервера), когда менялся и кем, последняя проверка связи.
2. **Значение — только на запись.** Поле пароля; сервер принимает значение в POST и никогда
   его не возвращает — ни в ответе, ни в журнале (там только имя ключа и действие), ни в
   истории Temporal. Несекретные настройки (адрес Confluence) показываются как есть.
3. **Хранилище** — `<том данных>/portal-keys/keys.json` (каталог 700, файл 600), общий том
   портала и исполнителя публикации. Заданное в настройках главнее окружения сервера;
   «Вернуть из окружения» снимает его. Портал при старте и после сохранения подставляет
   значения в своё окружение — потребители, читающие ключ при использовании, видят новый без
   перезапуска; исполнитель публикации читает хранилище перед каждой активностью.
4. **Что задаётся здесь, а что нет.** Здесь — ключи, которые потребитель читает при каждом
   использовании: ключ записи и адрес Confluence, Google Drive API, ключ агента ревью. Не
   здесь, со ссылкой «где»: ключи моделей (их хранит ядро dsh — «Настройки → Модели»),
   токен шлюза источников (выпускает `install-sources-gateway.sh`, шлюз хранит только хэш),
   пароль служебной учётки трекера и секрет входа администратора (создаёт `start.sh`).
   Статус этих ключей виден всё равно.
5. **Проверка связи** — у ключей, где она возможна без записи и без затрат: Confluence
   (вход под ключом у исполнителя публикации, workflow `ConfluenceCheck`; анонимный ответ —
   «не принят»), шлюз источников (доступность с токеном), Google (неверный ключ — 400,
   верный — 404 на несуществующий файл). Итог запоминается с датой.
6. **Перенос ключа из окружения агентов.** `harness/deploy/set-confluence-publish-key.sh
   --from-env <файл> <переменная>` — шаг владельца на сервере: файл и имя переменной
   называет он сам, значение не печатается и не попадает в аргументы команд, после записи —
   проверка входа. Агент сам по чужим окружениям ключи не ищет.
7. **Скрипты остаются только там, где без них нельзя**: nginx (`install-nginx-bft.sh`, sudo),
   шлюз источников (systemd на хосте, выпуск токена), первичный подъём (`start.sh`). Скрипты
   ключей (`set-confluence-publish-key.sh`, `set-review-agent-key.sh`) — запасной путь без
   браузера; основной — раздел настроек.

## Рассмотренные варианты

- **Писать ключи в `harness/.env` из браузера.** Контейнер не видит файл хоста, а
  перезапуск сервисов из портала дал бы браузеру власть над контуром.
- **Показывать последние символы ключа.** Удобно сверять, но это часть секрета в браузере;
  хватает «задан / откуда / когда / проверка».
- **Держать ключи моделей тоже здесь.** Их читает ядро dsh, у него свой раздел «Модели» с
  тем же полем только на запись; второй путь к тем же ключам запутал бы, какой главнее.

## Последствия

- Секреты, заданные в настройках, лежат на томе данных портала (файл 600) — в том же
  классе защиты, что и `harness/.env` на хосте; резервные копии тома их содержат.
- Новый ключ портала добавляется строкой в `KEY_SPECS` (`customer-form/src/keys.ts`).

## Проверка

- `customer-form/test/keys.test.mjs`: права файла и каталога, статус без значений, порядок
  «настройки → окружение» и сброс, маршруты только администратору, значение не возвращается,
  нередактируемый ключ — 409 с подсказкой, проверка связи запоминается, проверка Google.
