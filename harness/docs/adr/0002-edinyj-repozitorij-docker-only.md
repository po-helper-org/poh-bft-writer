# Один репозиторий: poh-bft-writer, коробка вендорится

Лишние репозитории убраны: poh-bft-writer — единственный источник истины.
Код исполнителя (poh-bft-box) переносится копией в `box/` и дальше развивается
здесь; репозиторий poh-bft-box замораживается. poh-harness больше не нужен:
его роль (готовый контур dsh с профилем) выполняет `harness/` — профиль
dsh-стека живёт в `harness/profile/`, версия пинится (как в poh-harness,
`0.1.7-rc.2`), обновление — `git pull && ./harness/update.sh`.

Развёртывание UI-режима — только Docker: `harness/docker-compose.yml` поднимает
harness-web (dsh), box-mcp, box-worker, temporal, postgres. CLI-режим не меняется
и Docker не требует. Решение владельца 2026-10-23, раунды grilling 1–2.

## Considered Options

- Git submodule / subtree на poh-bft-box: оставляет зависимость от второго
  репозитория и синхронизацию, которую планируется ломать доработками. Отклонено.
- poh-harness как отдельный контур развёртывания: два места правды для одного
  сценария установки. Отклонено.
- Чистая копия `box/` + NOTICE о происхождении: код разойдётся с апстримом
  («довести до ума»), двусторонняя синхронизация стала бы балластом. Принято.

## Consequences

- Версии dsh-стека пинятся в `harness/profile/package.json.tpl`; API плагинов
  харнесса — alpha, обновление версии — отдельное решение с прогоном.
- ADR коробки (`docs/adr/0001-0002` из poh-bft-box) переносятся в `box/docs/adr/`
  с пометкой о вендоре; новые ADR коробки пишутся в `harness/docs/adr/`.
- `harness/` — только развёртывание и его настройки; код живёт в `plugin/`,
  `box/`, `skills/`, `commands/`.
