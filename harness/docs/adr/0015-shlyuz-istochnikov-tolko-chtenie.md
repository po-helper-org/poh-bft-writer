# ADR-0015: Шлюз источников — Jira и Confluence только на чтение

Статус: принято (2026-11-18). Заменяет в ADR-0013 OAuth и служебный токен
шлюза агентов, в ADR-0014 — выпуск токена `issue-sources-token.sh`.

## Контекст

Плагин `data-sources` (ADR-0013) ходил в большой MCP-шлюз агентов — сервер с
сотнями инструментов, среди них запись в Jira и Confluence, сообщения, память
и `shell`. Портал вызывал только четыре инструмента чтения, но это держалось на
белых списках: своём в плагине и (для служебного токена) на стороне шлюза.
OAuth-подключение вообще давало порталу полный токен шлюза.

Требование владельца: портал **ни при каких условиях** не должен иметь
возможности вызвать что-либо, кроме чтения Jira и Confluence, — даже в
принципе, даже при ошибке в коде портала или конфиге шлюза агентов.

## Решение

- **Отдельный процесс «шлюз источников»** (`harness/sources-gateway/`,
  Python, fastmcp): маленький MCP-сервер ровно с четырьмя инструментами —
  `jira_search`, `jira_get_issue`, `confluence_search`, `confluence_get_page`.
  Он проксирует дочерний `mcp-atlassian` (stdio), запущенный с `--read-only` и
  `--enabled-tools` из тех же четырёх имён. Других серверов в шлюзе нет.
- **Слои защиты** — каждый сам по себе закрывает запись:
  1. Режимы самого `mcp-atlassian`: `--read-only` / `READ_ONLY_MODE=true`
     (инструменты записи не регистрируются) и `--enabled-tools` /
     `ENABLED_TOOLS` (только четыре). Права в Jira/Confluence — у учётки,
     чей personal token взят из конфига MCP-клиента на сервере; шлюз их не
     расширяет.
  2. Промежуточный слой шлюза: `tools/list` отдаёт только белый список,
     `tools/call` с любым другим именем (включая префиксы, регистр, пробелы)
     отклоняется; ресурсы и промпты пустые, их чтение запрещено.
  3. Вход в шлюз — статический bearer-токен; шлюз хранит только его sha256
     (`~/.config/bft-sources-gateway/token.sha256`, права 600) и сравнивает за
     постоянное время; без токена или с чужим — 401. OAuth-эндпоинтов нет.
  4. Сеть: шлюз слушает только `127.0.0.1:3086/mcp`; снаружи — один путь
     nginx `location = /bft-sources/mcp` (без Authentik: токен проверяет сам
     шлюз; потоковый прокси, тело до 1 МБ).
  5. Процесс: служба `systemd --user` `bft-sources-gateway.service` без sudo
     — `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`, домашний
     каталог только на чтение (кроме своих конфига и состояния), `MemoryMax`.
     Адреса и токены Jira/Confluence — в своём файле окружения
     `~/.config/bft-sources-gateway/env` (600); чужие конфиги агентов шлюз во
     время работы не читает.
  6. Портал: плагин `data-sources` зовёт только `READ_ONLY_TOOLS`, `call()`
     отклоняет любое другое имя ещё до сети; `tools/list` не зовёт.
- **Портал — только токен.** OAuth из `data-sources` удалён целиком: нет окна
  входа, приёмника возврата (порт 3081/3083), маршрутов
  `/api/data-sources.connect` и `.disconnect`, кнопок «Подключить» и
  «Отключить». Источник один — `atlassian`, «Jira и Confluence (только
  чтение)»: адрес `DATA_SOURCES_URL_ATLASSIAN`, токен
  `DATA_SOURCES_TOKEN_ATLASSIAN`; нет одного из них — «не настроен». Токен не
  пишется в журнал и не отдаётся ни в одном ответе API и в «Настройках».
- **Переход.** При запуске плагин удаляет из тома файлы прежних
  OAuth-подключений (`/data/data-sources/*.json`), в журнал — только число
  удалённых. `deploy-server.sh` убирает из `.env` сервера
  `DATA_SOURCES_URL_PO_HQ`, `DATA_SOURCES_TOKEN_PO_HQ`, `AGENT_GATEWAY_DIR`.
- **Установка на сервере** — `harness/deploy/install-sources-gateway.sh`
  (обычный пользователь, root запрещён): venv с закреплёнными версиями, файл
  окружения из конфига MCP-клиента (`SOURCES_MCP_CONFIG`, путь от домашнего
  каталога, и `SOURCES_MCP_SERVER` — имя сервера в `mcp_servers`; значения
  `${VAR}` — из `.env` рядом с конфигом), токен шлюза (в шлюзе — sha256, в
  `harness/.env` портала — сам токен, без вывода), служба `systemd --user`,
  проверка «без токена — 401», пересоздание `customer-web`. nginx — по-прежнему
  `install-nginx-bft.sh` с sudo (владелец перезапускает его один раз ради
  `/bft-sources/mcp`).
- **Разовые шаги владельца с sudo**: `install-nginx-bft.sh` (см. выше) и
  `sudo loginctl enable-linger <пользователь>` — без linger служба
  `systemd --user` останавливается после выхода из последней сессии, и портал
  получает отказ соединения. Скрипт установки проверяет linger и в конце явно
  пишет «НЕ ГОТОВО», если он выключен.

## Что портал может и чего не может

- Может: искать задачи Jira по JQL, читать задачу по ключу, искать страницы
  Confluence, читать страницу по id — с правами учётки Jira/Confluence шлюза.
- Не может: создавать и менять задачи, комментарии, страницы, вложения,
  спринты; звать любые инструменты шлюза агентов (`shell`, сообщения,
  память, доска) — шлюз агентов порталу больше не известен ни адресом, ни
  токеном; читать ресурсы и промпты MCP; получить токен Jira/Confluence —
  он есть только у процесса шлюза источников.

## Ротация и отзыв

- Ротация: `install-sources-gateway.sh --rotate-token` — новый токен,
  новый sha256, `harness/.env` и пересоздание `customer-web`. Шлюз перечитывает
  `token.sha256` при каждом его изменении, поэтому старый токен перестаёт
  приниматься, как только записан новый хэш (скрипт к тому же перезапускает
  службу). Без ключа скрипт оставляет существующий токен, если хэш и значение
  в `.env` совпадают.
- Отзыв: удалить `token.sha256` — работающий шлюз со следующего запроса
  отвечает 401 на любой токен, без перезапуска (испорченный файл — так же).
  Перезапуск без файла шлюз не переживает: служба не стартует, nginx отдаёт
  502. Остановить совсем — `systemctl --user disable --now bft-sources-gateway`
  (отказ соединения). Портал в обоих случаях показывает, что источник
  недоступен.
- **Разовый шаг перехода — прежние доступы портала к шлюзу агентов отозваны
  на его стороне** (выполнено при выкладке этого решения). Удаления ключей из
  `.env` и файлов OAuth из тома мало: копия (резервная, снимок тома, вывод
  `docker inspect`) открывала бы шлюз агентов. Поэтому в шлюзе агентов отозван
  служебный токен портала, сама поддержка служебных токенов из него убрана,
  удалены OAuth-клиенты портала и выданные им токены. У портала не осталось
  ни одной учётной записи, которую принял бы шлюз агентов.

## Почему не большой шлюз агентов

Белый список на стороне шлюза агентов — настройка общего сервера с сотнями
инструментов: её ошибка, обновление шлюза или OAuth-вход открывает порталу всё
остальное. Отдельный процесс, в котором кроме четырёх инструментов чтения
ничего нет (и дочерний `mcp-atlassian` в режиме только чтения), делает запись
невозможной по устройству, а не по настройке.

## Последствия

- Новый процесс на сервере (`127.0.0.1:3086`) и путь nginx `/bft-sources/mcp`.
- Локальный портал без шлюза источников — источник «не настроен», полный БФТ
  собирается без разведки (как раньше без подключения).
- Токен шлюза бессрочный до ротации; при утечке — `--rotate-token`.
