# Портал заказчика на :3080, харнесс PO — на :3081

Заказчик, открывая систему, видел интерфейс PO (харнесс) и дезориентировался.
Решение: вход системы (:3080) — отдельный лёгкий портал без dsh: «Введите
свои мысли». Харнесс PO переехал на :3081 (токен-ссылка прежняя механика).

Поток: форма (ФИО/email + текст/голос/файлы/ссылки) → задача-запрос в Vikunja
(<1с до ссылки; лейбл «запрос», вложения) → микродиалог на glm-5-turbo
собирает канон БФТ: заказчик, суть, ASIS, GAP, TOBE, HowToDemo, глоссарий —
виджет-скоркарта 7/7 в чате → finalize: Summary-комментарий + файл полного
контекста вложением → письмо (SMTP опционален). Дальше запрос забирает PO
(доска Vikunja) — в интейк/конвейер как раньше.

## Considered Options
- Форма как дефолтная вьюха dsh — остаётся хром харнесса, дезориентация.
- Отдельный SPA на реакт-стеке — оверхерк для одной формы; vanilla-страница.

## Consequences
- 11-й сервис compose (portal, FastAPI+uvicorn, ~256МБ); ZAI/TRACKER env.
- Грабли зафиксированы: Vikunja attachments = PUT с полем files; лейблы —
  отдельным PUT /tasks/{id}/labels (label_titles при создании игнорируется);
  `True and list` в scorecard → bool-обёртка.
- Email без SMTP пропускается молча; Matrix-уведомление — v2.

## Rev 2 (та же ночь, требование владельца): переиспользуем DSH UI

Отдельный сервис-портал (FastAPI) убран: своя дизайн-система не заводится.
Портал заказчика — **плагин customer-form** на контейнере dsh: визуальный
канон стартового экрана харнесса (центрированный композер, примитивы dsh,
CSS-переменные темы), полноэкранный оверлей закрывает хром. Второй dsh-инстанс
(customer-web, :3080) поднимает профиль только с customer-form; PO-харнесс
на :3081 как раньше.

Грабли двойного инстанса dsh (все в entrypoint/Dockerfile): `dsh web` жёстко
стартует profiles/web — сид всегда в profiles/web, контент по DSH_PROFILE;
cordis.patch.yml профиля и бандла обязаны быть top-level YAML-массивом
(комментарий-файл валил профиль молча); **пустой массив патчей у бандла =
бандл отбрасывается вместе с клиентской частью** — минимальная запись
`- insert: [- id, name]` обязательна; npm file:-симлинки обоих пакетов
заменяются копиями.

## Rev 3: две последние грабли + E2E HowToDemo-1

- `inject` клиентского модуля — имена СЛУЖБ cordis (`'slots'`, `'connection'`),
  не пакетов: полные имена пакетов загрузчик ждёт как несуществующие службы —
  вечное «pending (waiting for services…)».
- banner tsdown обязан нести id бандла (`customer-form`): копия конфига с
  чужим id регистрировала модуль не под тем именем («loaded without
  registering»).
- E2E `customer-form/e2e/first-request.spec.ts` (+`harness/e2e-customer.sh`):
  открытие ссылки → «Введите свои мысли» → ФИО/email/текст/ссылка-чип →
  «Отправить» → ссылка на задачу (замер, бюджет 5с) → задача в Vikunja с
  лейблом «запрос». Прогон: ✓ 851мс, ссылка 211мс.

## Rev 5: шаг 1 HowToDemo доведён (вход → обращение → ссылка < 1с)

- **Вход без кода**: browser-auth dsh пропатчен в образе (`isAuthenticated`
  → true, Dockerfile) для обоих инстансов; прокси-подстановщик токена удалён.
  Контур безопасности — публикация портов только на 127.0.0.1/LAN.
- **Модель по умолчанию — zai/glm-5-turbo** (`agent-default-model` в
  customer.patch.yml): дефолт dsh — deepseek-official без ключа → Send
  задизейблен. «Internal Testing Notice» подтверждён в том же патче
  (`ui-settings-general.welcomeNoticeVersion`) — dsh пишет его туда сам.
- **Скрытие сайдбара**: `display:none` выкидывает колонку из грида и центр
  схлопывался до 22px — центр растягиваем на `grid-column: 1 / 3`.
- **Workspace**: `uiWorkspace.openWorkspace` только на первом запуске (когда
  workspace ещё нет); дальше штатное восстановление dsh — иначе каждая
  перезагрузка плодила пустую сессию (гонка за writer-lock).
- **Заявка**: узел слушает `agent/inbox/claimed`; первое сообщение сессии →
  задача Vikunja (лейбл «запрос», email из текста) → `agent.inject` с
  «📌 Заявка #N … ссылка». Пузырь инъекции dsh рисует сразу и без модели (при
  исчерпанной квоте ссылка всё равно есть). Строку команды, запущенной из
  узла (`commands.execute`), dsh в ленте не рисует — только из клиента;
  `/request` оставлен как ручной повтор. Связь сессия→задача —
  `DSH_HOME/customer-form/tickets.json`.
- E2E (Playwright в контейнере, node на хосте не нужен): ✓, ссылка 196мс /
  50мс на повторе; задача сверяется в Vikunja по уникальному заголовку.

## Rev 6: путь заказчика целиком (HowToDemo заказчика п.1–10)

- **Пресет агента `customer`** (customer.patch.yml) — единственный: агент dsh
  видит только инструменты своего пресета (изолированная группа), поэтому
  глобальные выключатели tool-bash/tool-fs не действовали — модели были
  доступны bash, write, read, субагенты (а значит, и /proc/self/environ с
  ключами). Теперь у модели ровно `ask_user_question`, `web_fetch` (поиск
  выключен) и `submit_customer_request`; пресеты кодера выключены.
- **Каждый вход — своя новая сессия** (`sessions.create` + `openSession`).
  dsh web однопользовательский: восстановление и `openWorkspace`
  переиспользуют пустую сессию — два одновременных заказчика писали бы в
  один чат (поймано параллельным E2E).
- **Русский интерфейс** — штатный языковой пакет dsh-client-locale
  (`addLanguage('ru')` + словари conversation/question/chat/common),
  `locale.preference: ru` в профиле; заголовок героя — «Введите свои мысли».
- **Уточняющие вопросы** — штатная форма dsh (`ask_user_question`, п.8).
- **Вложения** любого сообщения → файлы задачи Vikunja (`fileHostPath` /
  `imageHostPath` службы attachments).
- **Сдача заявки** — инструмент `submit_customer_request` (плагин
  `customer-form/tool` в пресете): описание задачи — постановка по 7 пунктам
  (HTML: Vikunja хранит описание как HTML), комментарий-сводка, файл полного
  контекста `context-N.md` (п.9–10).
- Интерфейс кодера выключен: выбор пресета/режима доступа/модели/каталога,
  команды Goal/Plan/Compact/Feedback/Export, фоновые задачи, субагенты.
- **Оверлей оператора** `DSH_HOME/override.patch.yml` (entrypoint →
  `dsh --profile web --patch`): смена провайдера без пересборки.
- **E2E без внешней модели**: `harness/e2e-customer.sh` поднимает двойника
  (`customer-form/e2e/llm-double.mjs`, OpenAI-совместимый, стриминг и
  tool-calls), кладёт оверлей и всегда возвращает портал на zai. Два теста
  параллельно: ссылка ~200мс; диалог с вложением → форма → ИТОГ →
  подтверждение → задача с разделами, вложением, контекстом и сводкой.

Не закрыто: голос — штатный STT dsh (SenseVoice) не знает русского; email-
оповещение (п.11) — в стеке нет SMTP; качество живой модели (glm-5-turbo)
не проверено — квота ключа исчерпана до 27.10; dsh web остаётся
однопользовательским (список сессий общий, @-упоминание сессий доступно).
