# Четвёртый модуль — Трекер (Vikunja): накопитель задач и контекста, управляемый агентом

Один запрос — множество задач исполнения, коммуникаций с людьми и сессий
агентов; при 100+ БФТ/сутки это 1–5k задач/день, и им нужен надёжный дом с
UI для сотрудников и API для автономного агента. Трекер — четвёртый модуль
системы с реальным швом: пишут **трое** (Коробка — активности сценариев,
агенты — итоги ходов, сотрудники — статусы и ответы), читают все.

**Роль — зеркало, не источник истины.** Конвейерные состояния и метаданные
БФТ авторитетны в Коробке (Temporal+Postgres); Трекер — инструмент людей и
агентов. Поэтому отсутствие кастом-полей у Vikunja не критично: метаданные
живут в Коробке, в Трекере — лейбл `bft:<slug>` и связи.

**Выбор — Vikunja** (полное сравнение 9 кандидатов в components.md): единственный,
кто закрывает весь список задач при весе 1 контейнер+pg: полный REST (токены,
пагинация, поиск, bulk), связи задач (`blocked/blocks/related` — нужны сценариям
согласования), вебхуки (Коробка реагирует без опроса), канбан для сотрудников,
AGPL для внутреннего использования. Сильные альтернативы зафиксированы как
план роста: **Plane** (лучший UI, но self-host = 13 сервисов — против «сервер
тесный» из ADR-0002 Коробки), **OpenProject** (эталонный API, корпоративный
контур). REST-шов позволяет сменить адаптер без переделки вызывающих.

**Модель данных под 100+/сутки:** проекты по кварталам (`2026-Q4`), **задача =
БФТ-инициатива** (лейбл `bft:<slug>`), рабочие задачи 4 типов (ADR-0005) связаны
с ней `relates/blocks`. Проект-на-инициативу отвергнут: 36k проектов/год — мусор.
Закрытый квартал архивируется.

## Considered Options

- Без трекера: задачи в таблицах Коробки — управление задачами пришлось бы
  изобретать в трёх местах (таблицы + карточки плагина + отчётность людям).
  Deletion test не проходит.
- Backlog.md — файловый, один воркспейс, не multi-user: годен в CLI-контуре,
  не для сотен в сутки.
- Gitea (нет first-class связей), WeKan (слабый API), Kanboard (нет связей,
  UI), Redmine (UI), Taiga/Focalboard (мертвы), Huly (тяжёлый).

## Consequences

- В compose добавляется один сервис `tracker` (порт наружу — сотрудникам),
  БД — общий postgres.
- Сценарная активность «создать задачу / ждать закрытия / эскалировать» —
  обёртка над REST Трекера в box-worker.
- Вебхук Трекера → Коробка: закрытие верификационной задачи человеком
  продолжает воркфлоу без опроса.
- Сотрудники работают в UI Трекера (нормальные аккаунты); dsh web однотокенный —
  поверхность PO/аналитиков (интейк, указания, доски). Честное ограничение
  задокументировано.
