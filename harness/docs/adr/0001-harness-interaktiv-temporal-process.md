# Харнесс — интерактивный слой, Коробка — процессный; интерфейс Коробки — пять HTTP-эндпоинтов

Система — четыре модуля с маленькими интерфейсами (deep modules): **Харнесс**
(интерактив: люди вводят, читают, отвечают; агентные сессии — руки), **Коробка**
(процесс: детерминированный владелец жизненного цикла инициативы), **Трекер**
(накопитель задач и контекста, см. ADR-0004), **Воркспейс** (артефакты документов).

Ревизия 2 сужает шов rev 1: ревью по методу codebase-design (deletion test,
«один адаптер — гипотетический шов») показало, что rev 1 выставил наружу
детали реализации:

- **Temporal — внутренний шов Коробки**, не участник архитектуры. Что внутри
  (temporal, box-worker, светофор качества, postgres) — caller не знает.
- **MCP-протокол Коробки убран из v1.** Единственный вызывающий — плагин
  (host-слой Харнесса) по HTTP; результат агентного хода субмитит сам плагин
  (см. ADR-0003 rev 2). Второго адаптера нет — шов был гипотетическим. MCP
  вернётся, когда появится реальный второй вызыватель.
- **Порт Коробки не публикуется наружу:** плагин ходит изнутри compose-сети.
  В default-профиле наружу торчит один порт — 3080 (Харнесс).

Интерфейс Коробки целиком: `POST /api/start · POST /api/submit ·
GET /api/board · GET /api/initiative/{id} · POST /api/control` + Bearer
(`ui`-токен). Оркестрации в Харнессе нет и не будет: комбинированные сценарии —
активности воркфлоу Коробки.

## Considered Options

- Оркестрация внутри dsh — нет детерминизма и таймеров, переживающих рестарт.
- Temporal виден на верхнем уровне (rev 1) — перегружает архитектуру деталями
  реализации; сложность интерфейса ≈ сложности реализации (shallow).
- Выкинуть Коробку/Temporal из v1 — теряем детерминированные сценарии
  («ждать ответ N дней → эскалировать»), ради которых система и строится;
  deletion test Temporal проходит (таймеры/состояния/ретраи расползлись бы
  по вызывающим).

## Consequences

- Передача fast → процесс — явная кнопка «Запустить проработку» → `start`.
- Сессии dsh расходны: указание → сессия с handoff-черновиком → ход →
  `submit` плагином → сессия процессу больше не нужна.
- Замена implementation Коробки (temporal → что-то другое) не меняет ни одного
  вызывающего: интерфейс — 5 эндпоинтов.
- debug-профиль публикует temporal-ui `:8233` для admin-разбора — это профиль
  наблюдения, не участник архитектуры.
