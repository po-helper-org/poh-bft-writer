# speech-ru: распознавание русской речи для голосового ввода dsh

Микрофон композера (голосовой ввод dsh) на rev9 ADR-0007 распознавал речь
локальным GigaAM. Живая проверка владельца — «Речь не распознана»: в логе
5,4 с записи → 0 символов за 106 мс, то есть детектор речи не нашёл ни одной
фразы. Тихий сигнал причиной не был: GigaAM распознаёт текст даже при −45 дБ.
Скорее всего, в распознаватель пришла пустая запись (браузер пишет не с того
устройства или беззвучный поток), а заказчик увидел ничего не объясняющее
«Речь не распознана».

## Решение

Отдельный dsh-бандл `speech-ru/` регистрирует в `ctx.speechToText` провайдер
`ru-speech` и сам выбирает его по умолчанию. SenseVoice при этом выключается:
русского он не знает. Цепочка в одном провайдере:

1. **Уровень сигнала** — пик WAV ниже −50 дБFS считается тишиной. Заказчик
   видит «микрофон передал тишину. Проверьте, что в браузере и в системе
   выбран нужный микрофон…»; в сеть такая запись не уходит.
2. **Облако** — Requesty `POST /v1/audio/transcriptions`, модель
   `openai/gpt-4o-mini-transcribe`, `language=ru`, `prompt` с терминами
   (БФТ, JIRA, Confluence, 1С, ЗУП, HowToDemo). Ключ — `REQUESTY_API_KEY`,
   тот же, что у модели портала.
3. **Резерв** — GigaAM v3 в `context-ingest` (`POST /transcribe`), если облако
   ответило ошибкой, не уложилось в 20 с, вернуло пустой текст или ключа нет.

`mode: local-only` в конфигурации бандла — только GigaAM, запись не покидает
контур. Реестр dsh сам между провайдерами не переключается, поэтому резерв
живёт внутри провайдера.

| | gpt-4o-mini-transcribe (Requesty) | GigaAM v3 (локально) |
|---|---|---|
| 12 с заметки | 2,4 с, «Привет, это Ирина из отдела кадров…» | 0,8 с, тот же текст |
| В портале (9 с речи) | 1,6 с на сервере, 1,9 с до текста в поле | ≈0,9 с |
| Термины, имена | подсказка `prompt` | нет |
| Запись | уходит в Requesty → OpenAI | остаётся в compose-сети |

Облако — основной путь: так решил владелец; модель держит живую речь,
шум и термины из подсказки. Локальный GigaAM — резерв и режим для
закрытого контура.

## Проверка

- `speech-ru/test` (node --test, без сети, при сборке образа): тишина не
  уходит в сеть; в Requesty передаются `model`, `language=ru`, `prompt`;
  ошибка облака → GigaAM; `local-only` облако не трогает.
- E2E `voice-input.spec.ts`: подставной микрофон Chromium с
  `fixtures/memo.wav` → текст «…из отдела кадров…» в поле ввода.
- E2E `voice-silence.spec.ts`: подставной микрофон с `fixtures/silence.wav`
  → «микрофон передал тишину».

## Rev 2 — термины диалога и OCR сканов

Идеи взяты из готовых плагинов DSH: `@goodandready/dsh-voice` (термины из
диалога в подсказку распознавателю), `dsh-file-upload` и `dsh-doc` (OCR
картинок). Сами плагины не подошли: у них нет русского интерфейса, нет работы
через `ctx.speechToText`, а настройки открыты на изменение, что на портале
без входа небезопасно.

**Термины диалога в `prompt`.** Штатный API распознавания dsh получает только
запись, без сессии. Связь записи с диалогом устроена так:

1. Клиент customer-form переопределяет геттер `transcribe` у namespace-службы
   `remote.speech`. Перед распознаванием он сообщает узлу ключ записи
   (длина + FNV-1a 32 по байтам WAV) и свою сессию:
   `POST /api/customer-form.voiceContext`.
2. `speech-ru` даёт службу `ctx.speechHints`. customer-form регистрирует
   источник подсказок: по ключу записи он возвращает тексты этого диалога
   (сообщения заказчика и ассистента, разобранные материалы).
3. `speech-ru` выделяет из текстов термины: латиницу, аббревиатуры, слова с
   цифрами, имена посреди фразы, склеенные «Имя Фамилия». Без почты, ссылок и
   меток. Термины добавляются к базовой подсказке (не больше 900 символов).
   Источники ждём не дольше 0,5 с.

Чужие диалоги в подсказку не попадают: ключ записи знает только окно, из
которого она пришла. Если клиент не сообщил ключ, распознавание идёт с
базовой подсказкой. Живой прогон: `термины диалога: Ирина Петрова,
Битрикс24, 1С:ЗУП, Олег Сидоров`.

**OCR сканов и фото.** В `context-ingest` добавлены Tesseract `rus+eng`,
poppler и pillow-heif:

- картинки, включая HEIC с iPhone, переводятся в оттенки серого, мелкие
  увеличиваются до ширины 1600 px;
- PDF, у которого текстовый слой короче 80 символов на страницу, считается
  сканом: `pdftoppm` растрирует страницы в 300 dpi, Tesseract распознаёт их
  параллельно, не больше 30 страниц;
- модель получает такой источник с пометкой «скан — текст распознан OCR;
  возможны ошибки в цифрах и именах».

Замер: страница служебной записки в PDF — 1,4 с, фото — 0,24 с, текст совпал
с исходником.

Попутно найдено и исправлено: у моделей портала не был объявлен вход `image`,
и dsh выключал «Отправить», когда заказчик прикладывал фото. Haiku 5.5 (и
двойник в e2e) теперь объявлены как `input: [text, image]`, а вложения-картинки
тоже уходят в разбор материалов.

Проверка rev2: 11 юнит-тестов `speech-ru`, в том числе словарь, бюджет
подсказки и медленный источник. Новые e2e:

- `ocr.spec.ts` — PDF-скан и фото → черновик → в задаче распознанный текст
  с «Битрикс24» и «1С:ЗУП»;
- `voice-terms.spec.ts` — сообщение с терминами → диктовка. Раннер печатает
  строку `[speech-ru] термины диалога` из лога узла.

Весь набор — 7/7.

## Rev 3 — облачный резерв для файлов встреч

`gpt-4o-mini-transcribe` теперь и резерв расшифровки файлов (ADR-0007 rev10):
`speech-ru` экспортирует `transcribeCloud`, customer-form зовёт его на кусках
записи до 4 минут — ответ модели ограничен ~2000 токенами, и 15 минут целиком
обрезаются (проверено: 7,9 тыс. символов из ~11). Пример: «БФТ бра Юдин.m4a»,
15 минут → 4 куска → 9 тыс. символов за 10,8 с. Облако точнее в названиях
(«Тикетленд», «корзине»), GigaAM даёт метки по фразам; по умолчанию —
GigaAM, облако при сбое (`MATERIALS_AUDIO=cloud` — наоборот).

## Не закрыто

- Запись микрофона — до 120 с (ограничение API голосового ввода dsh).
- Файлы встреч (rev8 ADR-0007) по-прежнему расшифровывает GigaAM: нужны
  метки времени `[мм:сс]` и длинные записи. Перевести их на
  gpt-4o-transcribe — отдельное решение (лимит 25 МБ, нарезка).
- Перехват `remote.speech.transcribe` опирается на внутреннее устройство
  шлюза dsh 0.1.7-rc.2 (метод — геттер namespace-службы). При обновлении dsh
  его нужно перепроверить; e2e `voice-terms` покажет поломку в строке
  «термины диалога» (её не будет), а распознавание при этом продолжит работать.
- OCR рукописного текста и сложных таблиц Tesseract делает плохо.
