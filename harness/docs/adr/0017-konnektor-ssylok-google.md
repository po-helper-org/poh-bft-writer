# ADR-0017: Коннектор ссылок Google — Docs, Slides, Sheets, Drive как материалы заявки

Статус: принято (2026-11-19). Дополняет ADR-0007 rev8/rev10 (материалы
заказчика), ADR-0008 (OCR сканов и фото), ADR-0012 (минимальный контур).

## Контекст

Заказчики чаще присылают не файлы, а ссылки Google: документ с обоснованием,
презентацию, папку Drive с макетами. Портал читал ссылку как обычную страницу
(`ctx.web.fetch`): у Google Docs/Slides это оболочка редактора — в материалах
оставались заголовки без содержимого. Модель шла дочитывать сама через
`web_fetch`, и на живом прогоне это ломалось:

- экспорт Google отвечает редиректом на `*.googleusercontent.com`, а `web_fetch`
  не идёт за редиректом на другой источник («cross-origin redirect … is not
  followed»);
- `web_fetch` обрезает длинный документ на одном и том же месте;
- модель пробовала обходной путь через сторонний сервис-прокси (`r.jina.ai`) —
  это передача документа заказчика третьей стороне;
- повторный `read_customer_materials` отвечал «Новых материалов нет»: дочитать
  урезанный бюджетом источник было нечем.

## Решение

**Коннектор `customer-form/src/google.ts`.** Ссылка Google в сообщении
заказчика → `Materials.addLink` узнаёт её (`googleTarget`) и читает открытым
экспортом Google, без ключей:

| Ссылка | Что загружаем | Чем разбираем |
|---|---|---|
| Docs | `/export?format=md` | текст как есть; картинки внутри (data URI) вырезаем и читаем OCR (до 10) |
| Slides | `/export/pptx` (запасной — `/export/txt`) | MarkItDown: текст слайдов, заметки докладчика, подписи картинок |
| Sheets | `/export?format=xlsx` | MarkItDown |
| файл Drive | `drive.usercontent.google.com/download` (имя — из `content-disposition`) | как вложение: MarkItDown, OCR, речь |
| папка Drive | `embeddedfolderview` (HTML-список) или Drive API v3 | каждый файл как выше; подпапки — на один уровень; до 30 файлов |

- Байты разбирает **context-ingest** тем же `POST /ingest`, что и вложения:
  макеты и скриншоты — Tesseract (ADR-0008), документы — MarkItDown.
- Материал — один `<source>` на ссылку: метка («Google Slides — презентация,
  15 слайдов», «папка Google Drive — 16 файлов, картинки — OCR»), в начале —
  `Источник: <ссылка>`, у каждого файла папки — свой заголовок и ссылка на файл.
  Бюджет папки делится между файлами, чтобы вырезка середины не съела макеты целиком.
- **Закрытый файл** (редирект на вход Google, 401/403/404) — материал с ошибкой
  «откройте доступ „Все, у кого есть ссылка“ или приложите файл»; модель видит
  её и просит заказчика, остальные материалы не страдают.
- **Ключ API необязателен.** Если владелец задал `GOOGLE_DRIVE_API_KEY` в
  `harness/.env` сервера (пробрасывается в `customer-web`), список папки берётся
  из Drive API v3 (`files.list`, без разбора HTML, с постраничной выдачей).
  Без ключа — `embeddedfolderview`; на проверочных папках этого хватает.
  Ключ видит только открытые по ссылке файлы — доступа к закрытым он не даёт.

**Дочитывание вместо `web_fetch`.** `read_customer_materials` принимает `id`
(S1…) и `part`: полный разобранный текст источника отдаётся частями по 30 000
символов. Пакет по-прежнему урезан бюджетом (20К на источник, 60К на всё), а
пометка о вырезке теперь говорит, как дочитать.

**`web_fetch` у модели портала выключен** (`tool-web`: `fetch: false` в
`customer.patch.yml`). Ссылки заказчика читает портал — обычные страницы через
`ctx.web` dsh (сервис `dsh-web` остаётся), Google — коннектором. Модели не
нужно ходить в сеть самой, и ей нечем передать ссылку стороннему прокси.
Описание инструмента это тоже запрещает явно.

## Сеть и безопасность

- **Загружает портал (`customer-web`), а не context-ingest.** У context-ingest
  выхода наружу нет и не нужно (недоверенные файлы разбираются в контейнере
  без сети и ключей) — так и остаётся. У `customer-web` выход есть всегда: им
  он ходит к провайдеру модели и за обычными ссылками (`ctx.web`).
- **Сервер с выключенным bridge** (`"bridge": "none"`, ADR-0014): рабочие
  контейнеры сидят в собственной сети compose (явная подсеть `PORTAL_SUBNET`),
  и выход `customer-web` наружу — тот же, что у вызовов модели. Коннектору
  дополнительной сети, прокси или `network_mode: host` не нужно; если выход
  у портала когда-то пойдёт через прокси, его надо будет задать и для `fetch`
  Node (`NODE_USE_ENV_PROXY`/агент), как и для модели.
- **Только хосты Google.** Коннектор ходит на `docs.google.com`,
  `drive.google.com`, `drive.usercontent.google.com`, `www.googleapis.com` и
  `*.googleusercontent.com`; редиректы — вручную и только туда же. Ссылка
  заказчика не может увести запрос на внутренний адрес (SSRF): id файла — из
  регулярного выражения, адрес строим сами.
- Ограничения: файл до 50 МБ (`GOOGLE_MAX_BYTES`), до 30 файлов папки
  (`GOOGLE_FOLDER_FILES`), таймаут запроса 2 минуты.
- Содержимое ссылок в репозиторий не попадает: тесты — на вымышленных данных
  и двойниках `fetch` и context-ingest.

## Рассмотренные варианты

- **Оставить `web_fetch` модели и разрешить ему редиректы.** Пакет dsh
  `tool-web` не настраивается списком хостов; обрезка и прокси остаются.
- **Загрузка в context-ingest.** Пришлось бы дать сети наружу контейнеру,
  который разбирает недоверенные файлы, — отказались.
- **Docs через docx/pdf.** md-экспорт Google сразу даёт заголовки и таблицы
  Markdown; docx через MarkItDown не лучше, а картинки md-экспорта проще
  вынуть для OCR.
- **Описание макетов моделью со зрением.** Точнее OCR для схем без текста, но
  это расход ключа и отправка картинок провайдеру. Пока — OCR (как у фото
  документов, ADR-0008); описание можно добавить позже тем же местом.
- **Обязательный ключ Google API.** Не нужен для открытых по ссылке файлов;
  оставлен необязательным для папок.

## Последствия

- Заказчик вставляет ссылку на документ, презентацию или папку — в 📌 «Изучаю
  материалы», через секунды (документ, презентация) или минуту (папка с
  макетами под OCR) содержимое в материалах заявки, вкладке Information и
  в черновике/первичных требованиях. Длинный разбор не держит ход модели —
  механизм «Ещё разбираются» (ADR-0007 rev10).
- Модель портала больше не ходит в сеть сама.
- Не закрыто: файлы, закрытые доступом (только просьба открыть); видео в папке
  разбирается как запись (только речь); картинки слайдов Slides — только подписи,
  без OCR.
