# ADR-0013: Источники данных — Jira и Confluence как dsh-плагин

Статус: принято (2026-11-13), дополнено (2026-11-18: служебный токен шлюза);
подключение заменено ADR-0015 (2026-11-18: шлюз источников, только токен, OAuth удалён)

## Контекст

Полный БФТ (bft-deep, ADR-0012) опирался только на слова заказчика и Кортекс.
Связанные эпики, задачи и страницы требований в корпоративных Jira и
Confluence модель не видела, и «Зависимости», «Риски», «Якоря истины»
оставались `[УТОЧНИТЬ]` там, где ответ уже лежит в Confluence. Цель —
повысить качество и точность сбора данных из корпоративных ресурсов.

Доступ к корпоративным Jira и Confluence дают MCP-серверы. Сначала это был
большой MCP-шлюз агентов; с ADR-0015 — отдельный шлюз источников ровно с
четырьмя инструментами чтения. Адрес не зашит в код: он задаётся в конфиге
плагина или переменной окружения `DATA_SOURCES_URL_<ID>` (сейчас
`DATA_SOURCES_URL_ATLASSIAN`); не задан — источник «не настроен» и ни к чему не
обращается.

## Решение

- **Отдельный dsh-плагин `data-sources`** (пакет в корне репозитория, как
  `bft-manager`). Источники — список в его `cordis.patch.yml`; сейчас один —
  «Jira и Confluence (только чтение)» (id `atlassian`, ADR-0015). Другим
  плагинам он отдаёт службу `dataSources` (`ctx.provide`): `available`, `status`, `search`, `recon`.
- **Не штатный `dsh-mcp-client`.** Тот знает только статические заголовки и
  публикует агенту ВСЕ инструменты сервера, а у шлюза агентов была запись
  (`jira_create_issue`, `confluence_update_page`, `shell`, `send_message`…).
  Плагин — свой клиент Streamable HTTP с белым списком только чтения:
  `confluence_search`, `confluence_get_page`, `jira_search`, `jira_get_issue`
  (с ADR-0015 — последний из слоёв защиты: в шлюзе источников других
  инструментов и так нет).
- **Подключение — ADR-0015.** Первые версии подключали шлюз агентов по OAuth
  администратора (окно входа, приёмник возврата `127.0.0.1:3081/callback`,
  токены в томе), затем — служебным токеном шлюза агентов с белым списком на
  его стороне. Оба способа удалены: портал ходит только в шлюз источников по
  статическому bearer-токену (`DATA_SOURCES_TOKEN_ATLASSIAN`), маршрутов
  «Подключить»/«Отключить» и приёмника входа нет, файлы прежних
  OAuth-подключений плагин при запуске удаляет из тома. Токен не пишется в
  журнал и не отдаётся ни в одном ответе API.
- **Где используется — разведка перед полным БФТ.** После «Да, согласен»
  портал просит модель составить 3–5 поисковых запросов по заявке, ищет по
  Confluence и Jira, сливает и ранжирует находки (эпики и истории выше
  ошибок; без совпадения слов запроса и инциденты — вон; Confluence и Jira
  поровну), дочитывает лучшие и пишет карту находок `sources.md`. У каждой
  находки — готовая ссылка для БФТ: `[Jira KEY](url)` / `[Confluence:
  название](url)` — голые ключи и адреса bft-lint не пропускает (LN001/LN002).
  Карта идёт модели как указатель, не фактбаза: факт из находки — только
  если она про предмет заявки, со ссылкой; в «Якорях истины» — ранг R2. Карта уходит вложением в заявку
  (`<slug>-istochniki.md`). Источник не подключён — полный БФТ собирается
  как раньше; источник лёг целиком (одни ошибки, ни одной находки) — прошлая
  карта находок заявки не затирается, «Собрать заново» берёт её.
- Находка про ту же систему или поток данных — факт в «Зависимостях» и ФТ
  (R2), а не `[УТОЧНИТЬ]`; дефект Jira по той же функции — строка «Рисков».
  Относительные ссылки из карты Кортекса (`../../…md`) в документ заказчика
  не попадают — остаётся подпись.
- **Агенту чата заказчика инструменты источников не даются.** Токен шлюза —
  доступ PO к Jira и Confluence; отдать его любому посетителю портала значило
  бы открыть ему их с правами PO. В документ попадает только
  отобранное и со ссылками.

## Последствия

- Разведка добавляет к сборке полного БФТ до ~1,5 минуты (лимит 90 с).
- Портов у `customer-web`, кроме самого портала, нет (приёмник входа 3081
  удалён вместе с OAuth, ADR-0015).
- Токен шлюза источников бессрочный до ротации: при утечке —
  `install-sources-gateway.sh --rotate-token` (ADR-0015).
- Следующие источники добавляются строкой в конфиг плагина: MCP по
  bearer-токену, у которого инструменты чтения называются так же; любые
  другие имена портал не вызовет.
