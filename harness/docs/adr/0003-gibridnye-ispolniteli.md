# Гибридные исполнители: Коробка пишет тексты, агенты держат инструменты, люди решают

После старта процесса работу исполняют трое, и тип исполнителя определяет
активность воркфлоу, а не настройка человека:

- **Коробка пишет.** Deep-итерации пакета БФТ: box-worker сам зовёт модель
  (z.ai, OpenAI-совместимый API), светофор качества кодом, ретраи. Контур
  отлажен 28 контрактными эталонами — не ломаем.
- **Агенты держат инструменты.** Разведка Jira/Confluence (`/bft-recon`),
  доставка (`/bft-deliver`), правки файлов — сессией dsh по указанию. Ревизия 2:
  результат хода субмитит **плагин** по завершении хода (механизм существует —
  watcher `agent/status`), а не агент напрямую в Коробку. Агент не знает
  про Коробку вовсе — он просто выполняет скилл в своей сессии.
- **Люди решают.** `approve_plan`, `decide`, согласования, ответы: карточка
  в UI → `submit`. Продукт-человек — оператор и усилитель системы; финальное
  решение всегда за человеком.

Мозг — всегда Коробка: агентные исходы — вход итерации, не замена светофора.
Комбинированные сценарии — последовательности активностей воркфлоу, нового
слоя оркестрации нет.

## Considered Options

- Всю работу делают агенты — теряем отлаженный контур качества; каждый шаг
  hostage доступности сессии.
- Всю работу делает worker — нет пути к инструментам воркспейса без раздувания
  Коробки до «руки».
- Агенты зовут Коробку напрямую по MCP (rev 1) — второй адаптер шва, которого
  в v1 нет; сессия получает лишнее знание об инфраструктуре. Отложено до
  реальной необходимости.

## Consequences

- Карточка указания несёт тип исполнителя: «ответить человеку» / «работа
  агента» (кнопка открывает сессию с handoff) / «коробка пишет» (статус-прогон).
- Агентные сессии привязаны к задачам Трекера (ADR-0004): сессия открывается
  по задаче, итог хода пишется и в Коробку (`submit`), и в задачу (коммент).
- Качество пакета по-прежнему судит только Коробка.
