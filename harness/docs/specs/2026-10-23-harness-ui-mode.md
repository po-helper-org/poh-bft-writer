# Спека: автономный UI-режим poh-bft-writer (harness/)

## Problem Statement

PO установил poh-bft-writer как набор скиллов IDE-агента и получил конвейер
`/bft-*`, но не получил системы: чтобы фиксировать требование, смотреть статусы
и вести проработку, нужны IDE-агент, настроенный воркспейс, Backlog.md и
ручное слежение за файлами. Связка «после сбора требований — много
комбинированных сценариев» (написать, согласовать, ждать ответ, эскалировать)
вообще нигде детерминированно не живёт: чат не переживает рестарт, таймеров «ждать
ответ N дней» нет. Развёртывание размазано по трём репозиториям
(poh-bft-writer, poh-harness, poh-bft-box), и «поднять под ключ» не получается.

## Solution

Один репозиторий poh-bft-writer. Внутри — `harness/`: `docker compose up -d`
поднимает автономную систему: DeepSeek Harness (web-UI с плагином poh-bft-plugin)
как интерактивный слой и коробку на Temporal как процессный. PO открывает
браузер, проходит онбординг (5 шагов, провайдер Z.AI/GLM, ключ), вводит
требование в форму интейка (текст, голос, файлы, фото, PDF, ссылки), за минуту
получает fast-скоринг с зафиксированными контактами (Заказчик, PO, Техлид) и
кнопкой «Запустить проработку» — дальше инициативой детерминированно владеет
процесс Temporal: итерации, светофор качества, указания людям карточками в
сайдбаре, таймеры ожидания. Доска запросов показывает статусы всех БФТ,
детальный экран — полную форму требования и таймлайн процесса. CLI-режим
(скиллы в IDE-агенте) не меняется; после установки `install.sh` сам предлагает
выбор режима.

## Implementation Decisions

- **Один репозиторий.** Код исполнителя poh-bft-box вендорится копией в `box/`
  (NOTICE о происхождении; ADR-0002). poh-harness не используется: его роль
  берёт `harness/`.
- **Развёртывание — Docker-only** (ADR-0002): `harness/docker-compose.yml`
  поднимает сервисы harness-web (dsh), box-mcp, box-worker, temporal, postgres;
  temporal-ui — профиль `debug`; демо-двойник LLM — профиль `demo`. dsh-стек —
  npm-зависимость с пином версии (как poh-harness, `0.1.7-rc.2`), профиль в
  `harness/profile/`; обновление — `harness/update.sh`.
- **Два слоя (ADR-0001).** dsh — интерактив (интейк, мини-чат, агентные сессии,
  UI-карточки); Temporal — процессы (состояние инициативы, итерации, таймеры,
  ожидания). Шов — box-mcp: MCP-инструменты агентам, HTTP `/api/*` плагину,
  Bearer-изоляция. Оркестрации в харнессе нет.
- **Гибридные исполнители (ADR-0003).** Deep-итерации пакета — box-worker сам
  зовёт модель (z.ai, OpenAI-совместимый API); агентные сессии dsh — для работ
  с инструментами по указаниям. Комбинированные сценарии — последовательности
  активностей воркфлоу коробки, новый слой оркестрации не заводится.
- **Интейк** — новая клиентская вьюха плагина и дефолтный экран: строка ввода
  (текст; голос — Web Speech API с дисклеймером; вложения; ссылки) → сессия
  dsh со скиллом `bft-fast`, модель `glm-5-turbo`, рабочая папка — воркспейс
  БФТ. Контракт скилла не меняется: источник — путь.
- **Вложения** — upload-API плагина (`POST attachments`) кладёт файлы в
  `workspace/uploads/<ts>-<slug>/`; аудио расшифровывается `bft-transcribe`
  (whisper.cpp локально), PDF/фото читаются моделью как вложения сессии.
- **Контакты** — авторитет в frontmatter документа (`contacts:`: роль, имя,
  email для Заказчика/PO/Техлида); письмо fast и `personas.csv` — производные.
  Нераспознанный контакт — открытый вопрос, не заглушка.
- **Ссылки** — блок «Источники» в результате fast + пометка «требует изучения»
  в открытых вопросах; изучение содержимого ссылок — активность процесса, не
  интейка (v1).
- **Передача fast → процесс** — явная кнопка «Запустить проработку» на карточке
  fast-результата → `POST /api/start` с брифом из артефактов (ADR-0001).
- **Сайдбар** — первой секцией карточки указаний (адресат, суть, дедлайн,
  действия по типу), ниже — очередь требований; на кнопке раздела — бейдж
  количества ожидаемых указаний.
- **Доска** — девять стадий документа как сейчас; состояние процесса — чип на
  карточке; детальный экран — полная форма БФТ + таймлайн процесса итераций +
  `temporal_url` (профиль debug).
- **Онбординг** — 5 слайдов в клиентском коде плагина; флаг пройденности —
  settings плагина; провайдер v1 — только Z.AI (GLM); «Проверить» — тестовый
  вызов; ключ пишется в `harness/.env` через host-API плагина с подсказкой
  перезапустить harness-web; «Пропустить» — с предупреждением.
- **Бутстрап** — `harness/start.sh`: генерация `POSTGRES_PASSWORD`, `BOX_TOKENS`
  (`ui` для плагина, `agent` для MCP) при первом запуске; `ZAI_API_KEY` пуст →
  онбординг; ссылка с токеном dsh вытаскивается из логов harness-web, печатается
  и пишется в `harness/.last-url`.
- **Воркспейс** — volume `harness/workspace/`, стартует пустым; демо-данные —
  v2.
- **CLI-режим не трогаем**: `install.sh` получает только шаг выбора режима;
  скиллы и команды неизменны; независимость режимов проверяется как сегодня
  (`plugin/test-dual-mode.sh`).
- **Словарь и решения** — `harness/docs/GLOSSARY.md` и ADR 0001–0003 обязаны
  отражать реальность: правка терминологии или слоёв — правка глоссария/ADR.

## Implementation Decisions (дополнение, R7)

- **Коробочность** — принцип продукта: `docker compose up -d` на любой машине
  с Docker (Linux/macOS/Windows+WSL); всё локально, наружу — только ключ LLM.
- **Шлюз Matrix (ADR-0006)**: synapse (element-hq, федерация выкл.), Element Web
  из коробки, matrix-nio в box-worker; комната на инициативу; LAN-порты
  `:8008`/`:8090`; минимум RAM 6 ГБ (было 4).
- **Трекер в LAN** (`0.0.0.0:3456`, аккаунты Vikunja, TLS за фронтом владельца);
  Харнесс остаётся `127.0.0.1:3080`.
- **Голосовой ввод** — переключатель в онбординге: браузерный (Web Speech,
  дисклеймер) или локальный (MediaRecorder → upload → whisper).
- Канал «PO пересылает за заказчика» остаётся резервным: карточка указания
  всегда позволяет внести ответ со слов PO с фиксацией источника.

## Testing Decisions
Три шва, все существующие — новых не добавляется:

1. **Контракт коробки** (S1, без изменений): 28 эталонов `tests/contract/`
   вендоренного `box/` продолжают проходить; HTTP `/api/*` и MCP-инструменты
   не меняют схему (версия контракта 1.0.0).
2. **Чистое ядро плагина** (S2, расширяем): `node --test` без I/O — новые
   чистые функции: извлечение `contacts:` из frontmatter, модель карточек
   указаний, слияние стадии документа и состояния процесса для доски.
3. **Приёмка compose** (S3, новый скрипт `harness/acceptance.sh`): healthchecks
   всех сервисов, извлечение ссылки с токеном из логов, доступность
   `/api/board` (пусто — норма), smoke жизненного цикла коробки через профиль
   `demo` (существующий `scripts/smoke.py`), монтирование панели плагина в UI
   (curl главного бандла по маркеру). Живой fast-прогон с реальным ключом —
   ручной чеклист HOWTODEMO (ниже), автоматизировать его без ключа нельзя.

**HOWTODEMO (ручная приёмка)** — восемь шагов из сценария владельца: установка
→ выбор режима → онбординг с ключом → интейк с файлом и ссылкой → fast-скоринг
с контактами ≤ 1 мин → сайдбар с указаниями и топом → доска → детальный экран.
Полный текст живёт в `harness/docs/HOWTODEMO.md`.
