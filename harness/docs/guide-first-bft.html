Моя первая БФТ

Гайд PO: от запроса заказчика — до validated-документа. Без терминов «снаружи»: всё, что нужно, — на этих экранах.

0Перед началом — 2 минуты

Система поднята?

cd harness && ./start.sh --demo --no-open

Если уже поднимали — команда просто проверит и напечатает ссылку. Ваша текущая ссылка:

cat harness/.last-url

Ключ Z.AI стоит?

Настоящий fast-прогон идёт на GLM. Проверить/поставить — одной командой:

./set-key.sh --from-pi --check-only

Если «принял» — всё готово. Нет ключа? Прогон пойдёт на демо-модели: конвейер тот же, тексты фиктивные.

Что вы получите в конце: письмо в чат (пересылается заказчику как есть), два CSV (персоны + требования), документ БФТ и HTML-страница ревью — плюс инициатива, доведённая системой до validated.

1Откройте систему

Перейдите по ссылке из .last-url — это харнесс с разделом «Управление требованиями». Первый раз — покажется онбординг (5 шагов): на последнем вставьте ключ и нажмите «Проверить» → «Готово». Онбординг запомнится в этом браузере и больше не появится. Уже проходили — сразу открывается форма ввода.

Открыть раздел: кнопка ✎ Управление требованиями в подвале левой панели харнесса.

2Введите запрос заказчика

Перед вами строка ввода — сюда идёт всё, что дал заказчик:

КнопкаЧто принимает
текстпереписка, Summary, звонок по памяти — свободной формой
🎤диктовка голосом (браузерная — быстро; локальная whisper — приватно)
📎файлы встречи, фото экранов, PDF, презентации
ссылкипросто вставьте URL в текст — система сама соберёт их в «Источники»

Пример ввода (можете вставить свой по образцу)

Заказчик — сеть аптек «ФармаПлюс», контакт закупок ivanov@pharmaplus.ru. Хотят: выгрузку заказов в CSV для их BI, раз в сутки, все статусы кроме черновика. Техлид с их стороны — Петров (petrov@pharmaplus.ru), я — PO с нашей. Дэдлайн согласования границ — в пятницу. Материалы: https://confluence.corp.ru/x/AbCd и приложенный транскрипт звонка.
Секрет хорошего прогона: назовите электронные адреса (заказчик, PO, техлид) прямо в тексте — система зафиксирует их в контакты верификации. Чего не знаете — не выдумывайте: оно станет открытым вопросом, так и задумано.

3Отправить → минута ожидания

  1. ⏳ «Агент собирает fast-документ…»быстрая модель раскладывает вводные по формам методологии — до минуты
  2. Карточка результатаскоринг: что понято · контакты (Заказчик/PO/Техлид с email) · источники · открытые вопросы
  3. Красные пометки?«Укажите контакт: Техлид (email)» — это не ошибка: допишите прямо в следующий прогон или закроете в верификации

4«Запустить проработку →»

Кнопка на карточке результата. Одно нажатие — и дальше система ведёт инициатива сама:

# что произошло под капотом (вам не нужно):
инициатива зарегистрирована в конвейере   → стадия запрос
модель собирает пакет БФТ по методологии  → стадия сбор
указания людям расставлены по адресатам   → стадия верификация

Дальше начинается ваша главная роль — отвечать, когда система спросит.

5Верификация: кто что делает

КтоГде отвечаетКак система узнаёт
Вы (PO) Сайдбар «Управление требованиями» → секция «Указания» сверху: карточки решений («Волна 1: A или B?») → кнопка «Ответить» прямо в строке мгновенно ответ уходит в конвейер
Сотрудники Трекер http://ваш-хост:3456 — задачи «сборочная/верификационная» с пометкой инициативы; закрыли задачу — ответили вебхук закрытие задачи = исход
Заказчик Element http://ваш-хост:8090 — комната #bft-…: вопрос уже там, ответ пишется в чат слушатель ответ в чате = исход
Молчание — не проблема: у каждого указания срок. Прошёл — система напомнит сама (в трекер/комнату), затянулось — эскалирует карточкой вам. Ничто не теряется и не висит вралом.

6Наблюдать: доска-конвейер

Сайдбар → внизу «Доска запросов» → переключатель Конвейер:

ЗАПРОС  →  СБОР  →  ВЕРИФИКАЦИЯ  →  VALIDATED
                └─ ваша инициатива · «ждём: po, заказчик»

Клик по карточке — панель процесса: светофор качества (сколько зелёных/жёлтых/красных проверок), чьи ответы ждём, ссылки: Temporal-процесс (для разбора сложных случаев), комната заказчика, задачи.

Как читать светофор: в приёмку ведёт только зелёный при утверждённом плане. Жёлтый — «недоказано», красный — чинится указаниями.

7Приёмка → VALIDATED

Все указания закрыты, светофор зелёный — приходит последнее указание «принять пакет». Нажимаете «Ответить» («принимаю») — и:

инициатива → validated ✅   (границы исполнителей прописаны, договорённости зафиксированы,
              открытые вопросы перечислены — контракт для следующего этапа готов)

Если что-то не так

Ссылка не открывается (401)

Токен живёт до рестарта. Новый:

docker compose logs harness-web | grep token

Fast завис на «⏳»

Скорее всего нет ключа: ./set-key.sh --from-pi, затем «Отправить» снова. Без ключа работает только демо-модель.

Указание не двигается

Панель процесса на доске → «Temporal-процесс»: видно, на чьём ожидании стоим. Ждём не вас — пингуйте адресата; вас — отвечайте карточкой.

Хочу прогнать «на сухую»

Демо-модель без ключа — весь конвейер до validated:

python3 harness/smoke-e2e.py
