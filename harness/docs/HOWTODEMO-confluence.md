# HOWTODEMO — «Отправить в Confluence» (ADR-0028)

Шесть шагов владельца: от кнопки на странице БФТ до истории отправки в Temporal UI.
Публиковать — только в тестовое место (своя тестовая страница-родитель), не в рабочие разделы.

## 0. Предусловия

- Портал выложен (`harness/deploy-server.sh`), в контуре есть `temporal`, `bft-flow`,
  `confluence-publisher` (в журнале: «исполняю bft-confluence»).
- В `harness/deploy/server.env` — `CONFLUENCE_PUBLISH_URL` (база Confluence; для Cloud — с `/wiki`,
  тогда же `CONFLUENCE_PUBLISH_USER` — email), выложено.
- Ключ с правом записи введён на сервере (ввод не печатается):

  ```bash
  bash ~/<DEPLOY_DIR>/harness/deploy/set-confluence-publish-key.sh
  ```

- Есть заявка с готовым полным БФТ и тестовая страница-родитель в Confluence, куда ключ может писать.

## 1. Кнопка на странице полного БФТ

Откройте `…/bft/api/customer-form.bftFast?session=<id>`. В рейке слева — вкладка
**«⇪ В Confluence»** (у документа без формы вопросов — кнопка «⇪ Отправить в Confluence» под «Скачать»).

Ожидаем: вкладка видна рядом с «Вопросы» и «Планирование».

## 2. Панель выбора родителя и ТОП-5

Нажмите вкладку. Справа открывается панель «Отправить в Confluence»; пока ищет — «Подбираю,
куда лучше положить БФТ…». Затем блок **«Куда лучше положить — ТОП-5»**: до пяти страниц,
у каждой — пространство и причина («сюда уже публиковали БФТ из портала», «здесь лежит
похожий БФТ «…»», «страница из материалов и разведки заявки», «найдено поиском «…»»).

Ожидаем: подбор занимает секунды; без поиска (шлюз недоступен) — честная строка и поле для ссылки.

## 3. Быстро найти свою страницу

В поле «Название страницы или ссылка на неё»:

- название → список найденных страниц;
- ссылка `…/pages/viewpage.action?pageId=…`, `…/spaces/KEY/pages/ID/…` или `…/display/KEY/Название`
  → одна страница, выбрана сразу;
- номер страницы → то же;
- короткая ссылка `…/x/…` → подсказка скопировать полный адрес.

Выберите тестовую страницу-родитель: внизу «Подстраницей страницы «…»», кнопка «Отправить» активна.

## 4. Отправить и видеть ход по шагам

Нажмите **«Отправить»**. Панель показывает четыре шага: «Преобразование в формат Confluence» →
«Создание или обновление страницы» → «Вложения: схемы, .docx, .pdf» → «Готово», с отметками
◌ / ✓ / ✕ и подробностями («страница создана», «загружено 3»). В конце — «Готово — БФТ
опубликован в Confluence» и ссылка на страницу.

- Перезагрузите страницу посреди отправки — панель откроется сама с тем же ходом.
- Ошибка (нет прав, нет родителя) — красным текстом, кнопки «Повторить» и «Выбрать другую страницу».
- Нет ключа — после «Отправить» текст «Публикация в Confluence не настроена: … CONFLUENCE_PUBLISH_TOKEN».

## 5. Страница по корпоративному стандарту, повторная отправка без дублей

Откройте ссылку. Ожидаем: заголовок `[БФТ] <slug>: <Название>`; сверху панель «опубликовано из
портала» и оглавление; разделы канона по порядку, таблицы с шапкой; сценарий приёмки —
картинкой; Jira — макросом; служебного «Продолжить / уточнить БФТ» нет; метки `bft`,
`bft-<slug>`; во вложениях схемы, `.docx`, `.pdf`.

Отправьте ещё раз (кнопка «Отправить ещё раз или в другое место» → та же страница выбрана →
«Отправить (обновить страницу)»). Ожидаем: шаг 2 — «страница обновлена (версия 2)», шаг 3 —
«без изменений N»; в Confluence одна страница, в истории — новая версия. В задаче трекера —
комментарий «📘 БФТ опубликован в Confluence».

## 6. История в Temporal UI

`…/bft-temporal/` (администраторы) → namespace `bft` → фильтр
`WorkflowType = "ConfluencePublish"` или `BftTaskId = <номер заявки>`.

Ожидаем: на каждую отправку — `bft-<taskId>-confluence-<n>`, статус `Completed` (или `Failed`
с той же причиной, что в панели); в истории — четыре активности по порядку, повторы видны
попытками; query `progress` показывает шаги. В цикле заявки `bft-<taskId>` — записи хроники
«Отправка в Confluence подстраницей «…»» и «БФТ опубликован в Confluence: <ссылка>».
