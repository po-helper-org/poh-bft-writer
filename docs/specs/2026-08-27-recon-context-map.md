# Спецификация: разведка контекста JIRA/Confluence (`/bft-recon`)

**Дата:** 2026-08-27
**Ветка:** `claude/bft-fast-fixes-chjumt`
**Источник требований:** PO после живого прогона `/bft-fast` — «он только на мой текст ориентируется, нигде в явном виде нет оповещения и этапа сбора данных из JIRA»

## Зачем

`/bft-fast` наружу не ходит по построению: принцип 1 SKILL, гейт периметра на этапе 5, машинный гейт 19 (`bft-ground-lint.py`). Это даёт ноль галлюцинаций и работу на Haiku — ломать нельзя.

Но у PO пропадает то, чего периметр не заменяет: **связи с уже накопленным знанием**. На встрече обсуждают фичу, по которой в JIRA уже есть эпик, в Confluence — страница с решением, а в закрытых задачах — отказ делать ровно это. Пока `/bft-deep` дойдёт до стадии 2, письмо уже разослано и вопросы заданы не те.

Разведчик закрывает разрыв между «зафиксировали сказанное» и «поняли, с чем это пересекается». Он **не добавляет знания в документ** — он даёт ссылки, по которым PO решает сам.

## Целевая модель

| | `/bft-fast` | `/bft-recon` | `/bft-deep` |
|---|---|---|---|
| Роль | стенографист | картограф контекста | аудитор |
| Внешние источники | никаких | JIRA + Confluence, только чтение | индекс, JIRA, Confluence, git, артефакты |
| Что на выходе | письмо, 2 csv, `<epic_slug>-fast.md` | `context_map.md` + нотификация | `<epic_slug>.md` (канон MTS) |
| Отношение к фактам | фиксирует сказанное | **указывает на документы, не пересказывает их** | якорит факты по `anchor_rules.md` |
| Пишет в артефакты БФТ | да | **нет, никогда** | да |

Ключевой инвариант: **разведчик — отдельный контур.** Он не может дописать факт в письмо, csv или документ, потому что не пишет в эти файлы вовсе. Периметр `/bft-fast` остаётся нетронутым, гейт 19 продолжает работать как работал.

## Контур запуска

Форк — на **этапе 8** `/bft-fast`, рядом с deep-форком (решение PO), после того как этап 7 дописал frontmatter. Порядок внутри этапа:

1. Нотификация старта в чат — PO видит, что сбор данных идёт.
2. Форк `bft-recon` (Agent tool, `run_in_background`).
3. Форк `bft-deep` по `deep_fork.md` — как раньше. В его промт добавляется путь `context_map.md` с оговоркой «файл появится позже или не появится вовсе — работай в любом случае». Жёсткой зависимости нет: два фоновых прогона не синхронизируются.

Конфликта записи нет: `bft-recon` пишет `context_map.md`, `bft-deep` — `<epic_slug>.md`, `bft-fast` — `<epic_slug>-fast.md`.

## Что ищет разведчик

Запрос строится из сущностей этапа 2 (`extraction_schema.md`): термины, названия систем, ФИО, ключ эпика, если PO его назвал. Пять срезов:

| Срез | Где ищет | Зачем |
|---|---|---|
| Эпики и задачи по теме | JQL по `tracker_projects` | не делается ли это уже |
| Существующие документы | CQL по `wiki_space` | не написан ли БФТ по этой теме |
| Решения и отказы | закрытые задачи с резолюцией, страницы решений/ADR | не отклонили ли это раньше |
| Люди в теме | assignee/reporter/авторы страниц | кого не позвали на встречу |
| Пересечения | задачи в работе, трогающие те же сущности | чья зона ответственности |

## Формат находки

Каждая находка — строка таблицы `context_map.md`:

```
| Тип | Заголовок | Ссылка | Почему релевантно | Статус/дата |
```

Типы: `УЖЕ ОПИСАНО`, `ПЕРЕСЕЧЕНИЕ`, `ЗАВИСИМОСТЬ`, `ПРОТИВОРЕЧИЕ`, `ВЛАДЕЛЕЦ`, `ТЕРМИН`.

Дисциплина формулировок — жёсткая, потому что разведчик работает с внешним текстом, который легко пересказать как факт домена:

- «Почему релевантно» — одна строка про **документ**, не про предметную область: «эпик про тот же виджет», а не «виджет работает так-то».
- Модальность обязательна: «похоже», «относится к», «проверь». Утвердительное «в системе сделано так» запрещено.
- Строка без ключа задачи или URL не выводится вовсе.

## Машинный гейт (гейт 20)

Дисциплину проверяет скрипт, а не самоотчёт модели — как и остальные гейты навыка:

```bash
python3 skills/bft-writer/scripts/bft-recon-lint.py <docs_path>/<epic_slug>/context_map.md
```

| Код | Что ловит |
|---|---|
| `RC001` | нет frontmatter или обязательных ключей (`epic_slug`, `scanned`, `sources`, `findings`) |
| `RC002` | таблица находок не по шаблону колонок |
| `RC003` | строка находки без ключа задачи и без URL |
| `RC004` | недопустимый тип находки |
| `RC005` | нет раздела «Что не найдено» — молчание выдаётся за отсутствие |

## Границы

Разведчик **не** делает: записи в JIRA/Confluence любого вида; правок письма, csv и обоих документов БФТ; выводов о предметной области; оценок «это надо делать так». Он не заменяет `/bft-index` (тот строит индекс воркспейса из локальных файлов) и не заменяет стадию 2 `/bft-deep` (та поднимает источники и якорит факты).
