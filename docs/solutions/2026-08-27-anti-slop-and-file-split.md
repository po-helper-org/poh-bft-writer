# Канон БФТ-документа расплодился по редакторским правкам между запусками генератора

## Ситуация

Владелец вычищал руками одни и те же вещи в каждом сгенерированном документе: хеджи и
сленг-кальки в тексте, прозаическое пояснение цели рядом с таблицей цели, догадки о
департаментах персон, границы прозой, и дублированный в шапке скелет требований, который уже
есть в CSV. Неудачный прогон глубокой стадии затирал выверенную шапку быстрой — обе стадии
писали в один файл.

## Причина

Требования к языку и структуре существовали в стандарте, но проверялись только чтением;
пояснение цели и таблица цели дублировали друг друга; поле «Департамент» приглашало к догадке;
файлы стадий не были разделены.

## Решение

Шесть изменений, каждое с машинной проверкой:

- **Гейт 18 anti-slop**: хеджи, мета-комментарии, избыточные квалификаторы, сленг-кальки —
  категории адаптированы на русский корпоративный регистр; линтер
  `scripts/bft-style-lint.py` (38 паттернов) + фикстура + самотест. Гейт закрывает ту же
  слепую зону самооценки LLM, что гейт 17 для структуры, и применим к любому артефакту.
- **Цель по SMART**: в письме — короткая строка для копипасты; в документе под заголовком
  «Цель» — только таблица `SMART | Значение`; буква без основания — маркер уточнения, не
  заглушка «важно для бизнеса».
- **Персоны: «Департамент» → «Влияние»** — вклад участника именно в этот документ, из
  сказанного на встрече, а не догадка по должности.
- **«Границы» — список, а не абзац**, единый формат с соседними блоками.
- **Разделение файлов стадий**: быстрая стадия пишет `<эпик>-fast.md`, глубокая читает его как
  seed и пишет свой `<эпик>.md`; fast-документ иммутабелен — с него можно перезапуститься.
- Снят дублирующий блок «Критичные требования» из шапки глубокой стадии (в быстрой он позже
  возвращён — PR #15).

## Как проверить

```bash
bash skills/bft-writer/scripts/test-bft-lint.sh
bash skills/bft-writer/scripts/test-bft-style-lint.sh
```

Плюс живой прогон быстрой стадии изолированным субагентом на эталонной выжимке: оба линтера
ноль с первого раза, все шесть изменений в выходе.

## Уроки

- Слепая зона самооценки LLM закрывается не уговорами в промте, а отдельным линтером на каждый
  класс дефектов (структура → гейт 17, лексика → 18, сверка с источником → 19).
- Поле, которое невозможно заполнить из источника, будет заполнено догадкой: убирать поле
  или переименовывать во «влияние/вклад», а не ждать честного «не знаю».
- Иммутабельный артефакт предыдущей стадии — дешёвая страховка от затирания при перезапуске
  следующей.
