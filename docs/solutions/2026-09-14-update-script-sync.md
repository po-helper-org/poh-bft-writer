# Установленный контур обновлялся в двух половинах и они рассинхронились

## Ситуация

Установленный в харнессе контур устаревает в двух местах по отдельности: плагин раздела
харнесс грузит по ссылке из чекаута (нужны git pull, сборка, перезапуск), навыки — копия в
воркспейсе (нужен установщик). В сессии именно рассинхрон половин и был первопричиной бага
«после быстрой стадии ничего не обновилось».

## Причина

Две половины установки обновлялись разными командами в разное время; единой команды и проверки
синхронности не было.

## Решение

- `update.sh` в корне: находит домашний каталог харнесса по живому процессу (у службы запуска
  своё окружение), проверяет, что профиль грузит плагин именно из этого чекаута — иначе
  отказывается и называет путь; обновляет обе половины одной командой; режим `--check` — отчёт
  без изменений (свежесть чекаута, синхронность навыков побайтово, ответ харнесса), код
  возврата 1, если что-то отстало.
- Контрактный тест как шлюз перед перезапуском; опрос до HTTP-ответа; лог на invalid plugin.
- Установщик получил режимы «ставить из заданного чекаута» и «без вопроса в терминале».
- Команда и гайд обновления — инструкция для ИИ-агента: как найти чекаут, что значит каждая
  строка отчёта, когда остановиться и спросить.

## Как проверить

```bash
bash update.sh --check
```

На живой установке отчёт сам находит процесс, ссылку профиля и воркспейс, верно сообщает о
несобранной после мержа библиотеке и отставании навыков.

## Уроки

- Что обновляется двумя путями — рассинхронизируется: держать одну команду и режим проверки
  синхронности побайтово.
- Домашний каталог сервиса ищется по живому процессу, а не по умолчанию — у службы запуска своё
  окружение.
- Инструкция обновления пишется для агента: стоп-условия и способ найти настоящий чекаут, иначе
  агент обновит не ту копию.
