# На старте инициативы не было договорённости, кто что делает на стыках команд

## Ситуация

Глубокий БФТ описывает требования, но на старте инициативы между командами нет единой
договорённости: кто (команда и человек) что и где делает на стыках и по какому проверяемому
критерию принимается работа. Декомпозиция в трекере тяжела и не про стыки.

## Причина

Формы «матрицы стыков между командами» не было ни в навыке, ни в готовых открытых шаблонах.

## Решение

Новый навык и команда собирают матрицу исполнения по deep-БФТ: строка = стык, участник,
проверяющий, требование, критерий приёмки, точки паузы, статус. Форму собрали из нескольких
практик: формат чеклистов готовности (у каждого пункта доказательство, N/A только с причиной),
роли RACI (один подотчётный на строку, отдельный проверяющий), стык по образцу интерфейсных
документов (требования к обеим сторонам), покрытие требований, точки паузы и режимы
чтения-действия, журнал возвратов. Тяжёлые трекеры требований не взяты: результат уходит в
вики, а проверку держит лёгкий линтер по образцу структурного.

Состав: навык с ресурсами и эталоном, гейт 23 (линтер с кодами, тест и фикстура со всеми
нарушениями), режим страницы ревью (комментарий адресуется строке, свой промт и своя команда
отгрузки, сводка по командам с фильтром), отгрузка отдельным флагом отгрузки (тело страницы
собирает скрипт, разбор общий со страницей ревью), защита плагина от подмены страницы
требования страницей матрицы.

Субагент со свежим контекстом выполнил команду только по навык-файлу, без эталона: 9 строк,
покрытие 7 из 7 требований, гейты зелёные; по его замечаниям поправлены код линтера и формат
стоп-точки.

## Как проверить

```bash
bash skills/bft-writer/scripts/test-bft-matrix-lint.sh
pnpm test
```

В браузере: сводка, фильтр по команде, комментарии мышью → промт со ссылкой на строку матрицы.

## Уроки

- Форму документа можно собрать из чужих практик, когда готового шаблона нет: фиксируй
  «откуда что взято» таблицей соответствий.
- Новый артефакт получает свой машинный гейт с первого дня — иначе он деградирует в свободную
  форму.
- Прогон свежим исполнителем без эталона — проверка самодостаточности навыка.
- «Дверь двусторонняя»: новый навык и режим отгрузки не меняют существующий поток.
