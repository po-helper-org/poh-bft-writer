# После быстрой стадии доска задач и страница ревью не обновлялись сами

## Ситуация

Сценарий в харнессе: владелец выбирает задачу в сайдбаре раздела, нажимает «Создать документ»,
отправляет команду быстрой стадии. Ожидалось: страница ревью собрана, задача доски перешла в
стадию быстрой готовности, к ней прикреплена ссылка на страницу. По факту — ничего из трёх.

## Причина

Три независимые дыры: страница не собиралась, потому что харнесс читает только навык-файл, а
шаг экспорта страницы жил в файле команды; статус не обновлялся, потому что никто не пишет в
доску — плагин её только читал, навык про неё не знает, конвенция была «ставит владелец
вручную»; ссылка не прикреплялась, потому что задача доски и каталог эпика связывались только
совпадением идентификатора и слага, которых в общем случае нет.

## Решение

- Чтение доски одним вызовом CLI с фильтром по типу — задачи без типа перестали течь в очередь
  (было 41 строка, стало 22).
- Связка задача ↔ эпик через ссылку задачи внутрь каталога документов → слаг равен
  идентификатору → заголовок; эвристик по времени файлов нет намеренно.
- Писатель доски: стадия только вверх, отменённые не трогаются, повтор без изменений не зовёт
  CLI, провал — видимая строка «доска не обновлена» у задачи, не молчание.
- Сверка по событию простоя агента (с дебаунсом) и при каждом обновлении списка; панель тихо
  обновляется раз в 30 секунд.
- Черновик передачи для задачи без документа отдаёт команду создания с описанием, критериями
  приёмки и заметками задачи дословно.
- Шаг экспорта страницы перенесён из файла команды в навык — его видит и харнесс.

Живой прогон: агент собрал документ, вложения и страницу; через полторы секунды после простоя
плагин записал стадию и ссылку в доску (панель была закрыта). Побочный эффект первой сверки на
рабочей доске: старая задача поднялась в стадию ревью — её deep-документ лежал с начала месяца;
поведение признано корректным.

## Как проверить

```bash
pnpm test
bash plugin/test-contract.sh
```

Контрактный тест с настоящим `backlog init` во временном воркспейсе: сверка, ссылка,
идемпотентность.

## Уроки

- «Кто-то потом поставит статус руками» — не конвенция, а дыра: пишет тот, кто узнаёт факт
  (агент закончил), по событию простоя, а не по таймеру.
- Связь двух сущностей через равенство двух полей ломается на первом же исключении — держать
  явную ссылку.
- Шаги, от которых зависит другая среда исполнения (харнесс), кладут в общий навык, а не в файл
  команды конкретного агента.
- Первая сверка на живой доске вскрывает накопленное расхождение — это норма, а не сбой.
