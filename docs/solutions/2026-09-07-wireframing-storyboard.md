# Раскадровка сценариев демо собиралась прямоугольниками с текстом

## Ситуация

Сценарии «Как продемонстрировать» в шапке документа — текст; показать владельцу и смежникам
будущий экран по ним было нечем: обычные wireframe-инструменты дают прямоугольники с подписями, а
не реальные виджеты, и не соединяют кадры в историю.

## Причина

Отдельного навыка визуализации сценариев не было; ручные инструменты не рассчитаны на автора-LLM.

## Решение

Опциональный навык раскадровки: превращает уже написанные сценарии в пошаговую визуализацию
интерфейса — кадры с реальными виджетами (переключатели, таблицы), в рамке браузера или
телефона, соединённые стрелками с подписями. Не входит в контур по умолчанию — только явная
команда.

- Грамматика ограничена нужным для экрана документа подмножеством; три ловушки зафиксированы в
  ресурсе (футер только прямым потомком окна, многострочный футер эмулируется, ширина панели не
  задаётся явно).
- Композер собирает раскадровку: кадры → рамка → стрелки и подписи. Ни одна рамка не несёт
  текста, похожего на факт (домен в адресной строке, время в статус-баре) — это оформление, не
  источник данных.
- Экспортёр HTML-страницы не несёт встроенной логики раскадровки: нашёл соседний навык —
  прогнал через него; не нашёл — честный маркер «навык не установлен», документ всё равно
  собирается (тот же принцип деградации, что у линтеров и рендерера диаграмм).
- Оба эталонных примера прогнаны через реальный рендер перед тем, как стать эталоном.

## Как проверить

```bash
bash skills/bft-wireframing/scripts/test-wireloom-render.sh
```

Прогон команды на реальном документе: семь сценариев → раскадровка с виджетами и стрелками.

## Уроки

- Опциональные способности подключаются деградацией с честным маркером, а не встраиванием в
  основной поток.
- Эталон примера собирается реальным рендером, иначе он расходится с фактическим выходом.
- Кадры не должны содержать правдоподобных данных (домены, время) — читатель принимает
  оформление за факты.
