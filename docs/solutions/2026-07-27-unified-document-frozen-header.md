# Глубокая проработка переписывала документ с нуля и затирала проверенную шапку

## Ситуация

Быстрый и глубокий проходы выдавали два раздельных артефакта: детальный документ читался тяжело,
а глубокая проработка генерировала канон заново, не расширяя шапку быстрого. Брошенный на
быстрой стадии документ продолжить было неоткуда — сессия закрыта, задача забыта.

## Причина

Стадии не имели общего артефакта и границы ответственности за его части; связи «быстрая шапка →
дописать канон» в пайплайне не было.

## Решение

Один растущий документ: frontmatter + заголовок + шапка (собирает быстрый проход) + строка-граница
`BFT-HEAD-END` + область канона (дописывает глубокий, сохраняя шапку байт-в-байт). Отгрузка
обновляет существующую страницу по `pageId` вместо создания дубля.

Восстановление: под областью канона лежит «открытое поле» — самодостаточный промт. Любой
владелец открывает свёрнутый блок, копирует промт в свою сессию и доводит документ до финала,
даже если исходная сессия давно закрыта.

Гонка записи закрыта правилом приоритета: пока идёт автоответвление глубокой проработки, документ
«занят» и ручной путь через открытое поле не запускается — иначе два прогона пишут канон под одну
шапку и обновляют одну страницу, второй молча затрёт первого. Правило внесено в сам промт шагом
«перед стартом».

Поиск границы — четыре якоря по порядку, включая Setext-форму заголовка: канон использует
подчёркивание, поиск только по решёткам давал ложное «не обогащён».

## Как проверить

`diff` замороженной шапки между эталонами быстрого и глубокого документа — пуст; строка-граница
уникальна в репозитории; ссылки на примеры разрешаются; открытое поле присутствует до
обогащения.

## Уроки

- Два писателя в один документ — это гонка: закрывать явным приоритетом, а не надеяться на
  порядок запуска.
- Промежуточный артефакт без точки восстановления теряется: самодостаточный промт внутри
  документа дешевле пере-сбора контекста.
- Структурную границу искать по нескольким формам якоря — единая форма даёт ложные отрицания.
