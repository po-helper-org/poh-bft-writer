# Правила отгрузки в вики жили прозой и молча терялись под давлением времени

## Ситуация

Реальная отгрузка под давлением времени пропустила оба правила конвертации (markdown-ссылки на
трекер и вики → макросы, диаграммы → картинки): команда отгрузки описывала шаги прозой в
markdown-инструкции, ничего не исполняло и не проверяло их — на скорости правила молча
отбрасывались.

## Причина

Правило, живущее только в прозе инструкции, не исполняется; у исполнителя нет ни скрипта,
который надо запустить, ни отчёта, который покажет, что именно пропущено.

## Решение

Три скрипта, на которые инструкция теперь указывает в первую очередь (ручные шаги остаются
fallback на случай отсутствия скрипта):

- предполётный отчёт: считает несконвертированные ссылки на трекер/вики и сырые блоки PlantUML
  в документе — для сухого прогона отгрузки;
- конвертер markdown-ссылок в макросы вики (storage или wiki-формат; для ссылок трекера ключ
  уже в URL, для страниц вики вызывающий передаёт карту идентификаторов);
- рендер диаграмм: каждый блок → PNG (CLI, docker как fallback), замена на плейсхолдеры для
  подстановки после загрузки вложений; если рендерера нет — честный маркер «нет рендерера» на
  каждую диаграмму, а не молчаливый код в теле страницы.

## Как проверить

```bash
python3 skills/bft-writer/scripts/bft-deliver-check.py <документ>
python3 skills/bft-writer/scripts/bft-confluence-macros.py <документ>
python3 skills/bft-writer/scripts/bft-render-plantuml.py <документ>
```

На живом документе отчёт корректно находит все несконвертированные ссылки и блоки; конвертер
даёт валидные макросы; рендерер — PNG и корректные плейсхолдеры.

## Уроки

- Правило отгрузки, не подкреплённое исполняемым скриптом и отчётом, будет молча пропускаться
  именно тогда, когда время поджимает.
- Сухой прогон с подсчётом «что осталось несконвертированным» превращает прозу в чек-лист.
- Отсутствие инструмента — честный маркер в тексте, не тихий пропуск.
