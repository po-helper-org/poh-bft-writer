# Письмо генератора не было похоже на то, что владелец реально отправляет

## Ситуация

Быстрый проход (`/bft-fast`) собирал письмо-итог по формату, придуманному изнутри: цель без
обоснования впереди, обязательный формат открытых вопросов «ФИО — вопрос», без блока ссылок на
документацию, с идентификаторами историй в теле. Владелец каждый раз правил отправленные письма
руками — расхождение накопилось в целый список правок по живому кейсу.

## Причина

Формат письма не сверялся с фактической практикой владельца: реальные правки к письмам не
возвращались в генератор и golden-эталоны.

## Решение

Правки владельца заложены в формат fast-письма:

- «Цель» ведёт обоснование (why) вперёд, с якорем на родительский эпик.
- Открытые вопросы — гибрид-формат: строка = вопрос / блокер / решение / зависимость, владелец
  опционально в скобках; обязательный префикс «ФИО —» снят.
- Новый блок «Документация» — указатели на вики, трекер и смежные страницы.
- Таблица требований уходит вложением (два CSV: персон и требований, UTF-8 BOM, запятая,
  RFC 4180), по флагу `--table` может остаться в теле; письмо самодостаточно для пересылки.
- Идентификаторы историй вынесены из тела; хвост ответвления глубокой проработки — одна строка.

Golden-письма переписаны в гибрид-форму, в ресурс формата добавлен накапливаемый блок «Уроки
правок PO» — точка, куда следующая порция правок ложится сразу.

## Как проверить

Прогнать быстрый проход по транскрипту и сравнить письмо с golden-эталоном: пять блоков,
гибрид-вопросы, вложения-CSV на месте, старой формы «ФИО — вопрос» в репозитории нет (проверка
греп-развёрткой по всем файлам формата).

## Уроки

- Формат генератора живёт по фактическим правкам владельца, а не по внутреннему идеалу;
  завести место, куда правки складываются (durable-блок в ресурсе формата).
- Письмо для пересылки и машиночитаемые данные — разные артефакты: CSV-вложение вместо
  таблицы в теле.
