**Goal:** Превратить два раздельных артефакта (письмо bft-fast и канон bft-deep) в один растущий документ: fast собирает читаемую шапку + Confluence-черновик + открытое поле с портативным промтом, deep сохраняет шапку и дописывает полный канон MTS ниже.

**Architecture:** Стек-модель. Документ = `frontmatter` + `H1` + строка-статус + **шапка** (формат bft-fast) + **строка-граница** + **область канона** (до deep — плейсхолдер с открытым полем; после deep — полный канон MTS). Граница — ASCII-якорь в HTML-комментарии с видимыми fallback-якорями для Confluence-roundtrip. Contract-файлы (`document_assembly.md`, `open_field.md`) пишутся первыми: от них зависят и fast, и deep.

**Tech Stack:** Markdown-навыки Claude Code (`skills/*/SKILL.md` + `resources/*.md` + `examples/*.md`), слэш-команды (`commands/*.md`), Confluence/JIRA через MCP (`confluence_create_page`, `confluence_update_page`, `confluence_get_page`, `jira_create_issue`). Автотест-раннера в репо нет — верификация через golden-фикстуры + runnable grep/diff-проверки.

## Global Constraints

Копируются из спеки `docs/superpowers/specs/2026-07-22-bft-unified-document-design.md`. Действуют на каждую задачу.

- **Строка-граница — байт-точная константа**, одинаковая в fast (пишет) и deep (ищет):
  `<!-- BFT-HEAD-END · ГРАНИЦА ШАПКИ · выше bft-fast, ниже bft-deep · шапку не затирать -->`
- **Порядок якорей при поиске границы** (deep): 1) `BFT-HEAD-END`; 2) заголовок `## ⏳ Полный БФТ — в проработке`; 3) заголовок `Бизнес описание` в обеих формах разметки — ATX (`## Бизнес описание`) и Setext (текст + линия `===`, как в `skills/bft-writer/examples/ideal_bft.md`) — значит уже обогащено; 4) якорь не найден → канон дописать в конец + предупреждение, ничего не удалять.
- **Замороженная область** (deep не меняет ни байта): от строки `## Шапка (сутевое описание запроса)` до строки-границы включительно. `frontmatter` и верхняя строка-статус — обновляемые (это не часть замороженной области).
- **Внешняя запись только после явного «ок» PO** по сухому прогону (`confluence_create_page` / `confluence_update_page`). MCP недоступен → честный `[УТОЧНИТЬ: MCP недоступен]`, локальный `.md` пишется всё равно, успех не эмулируется.
- **Zero-hallucination:** факт без источника → `[УТОЧНИТЬ у {кого}]`. Контекст внутри открытого поля — тоже только грундированные значения.
- **Высота БФТ:** без API-контрактов, схем БД, кода — только результат и приёмка.
- **ID-консистентность:** ID критичной таблицы шапки (`БТ-1`, `ПТ-1`, …) присутствуют в каноне с тем же типом. Новые ID deep добавляет только в канон, шапку не перенумеровывает.
- **Голос:** `skills/bft-writer/resources/writing_style.md` — деловой русский, без эмодзи в теле, без стоп-слов. Исключение: строка-статус и заголовок плейсхолдера (`⚡`, `⏳`, `▶`) — служебные маркеры прогресса, разрешены.
- **Конфиг:** используются существующие ключи `wiki_space`, `bft_parent_page_id`, `docs_path`, `tracker_projects`. Новых ключей не вводить.

## Шапка (сутевое описание запроса)

Цель: хотим редактируемый блок «Вопрос-ответ» на карточках событий, площадок и персон в Direct, чтобы опубликованные вопросы показывались покупателю на сайте и попадали в поисковую выдачу.

### How to demo

1. Открываю в Direct карточку события (потом площадки, потом персоны) → есть раздел «Вопрос-ответ».
2. Добавляю вопрос, правлю, меняю порядок, один скрываю.
3. Захожу на страницу на сайте → вижу опубликованные вопросы; скрытый не показан.
4. На странице без вопросов блока нет, страница работает как обычно.
5. Проверяю в Google Search Console / Яндекс.Вебмастер, что вопросы попали в поиск (в течение суток обновится).
