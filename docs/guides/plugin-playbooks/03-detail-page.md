# 3. Детальная страница

Прочитать документ требования, посмотреть ключевые поля и поработать с агентом над
документом, не уходя со страницы: правки, уточняющие вопросы, отгрузка в JIRA и Confluence.

## Шаги

### 1. Открой страницу

Из превью нажми **«Детальная страница»** (или нажми карточку на доске — сценарий 4).
Страница занимает весь экран: слева документ требования, справа колонка — стадия,
последняя сессия, ссылки на Confluence и эпик и **чат с Claude Code** (транскрипт, поле
«Что сделать по этому БФТ», кнопка «В чат»).

![Детальная страница: документ слева, чат справа](screenshots/03-detail-page/01-detail.png)

Документ на снимках — демонстрационный: настоящие документы требований внутренние и в
публичные картинки не попадают.

Документ ищется в каталоге документов по связке с задачей доски: по ссылке задачи, по
каталогу с именем идентификатора или по H1 документа. Документа нет — слева будет
«Документа нет» и кнопка **«Создать документ»**: она запускает в чате справа ход
`/bft-fast` с источником прямо в тексте — описание, критерии приёмки и заметки задачи, —
названием для H1 и слагом эпика, равным идентификатору задачи строчными (`po-140`).
Нажимать больше ничего не нужно.

Что происходит дальше — без твоего участия:

1. агент собирает `<slug>-fast.md`, csv-вложения и страницу ревью `<slug>-fast.html`
   в каталоге `<docs_path>/<slug>/`; ход виден в чате справа, документ слева накрыт
   анимацией проработки;
2. как только агент закончил ход, раздел сверяет доску с файлами: задача переходит в
   `FAST-DONE`, к ней добавляется ссылка на страницу ревью;
3. страница перечитывает задачу и документ сама, в чате остаётся короткий итог; панель
   обновляется сама (раз в полминуты, пока открыта); задача и документ теперь — одна
   строка, а детальная страница показывает собранную страницу ревью.

Стадию раздел двигает только вверх и никогда не трогает `BFT-CANCELED`: то, что PO поставил
рукой, файлы не перебивают.

### 2. Посмотри поля

В правой колонке над чатом — стадия, последняя сессия (состояние и давность), ссылки на
Confluence и эпик, когда они уже есть. У документа с собранным скриптом интервью над
рамкой — переключатель **«Документ БФТ» / «Скрипт интервью»**.

### 3. Отправь правку

Поле **«Что сделать по этому БФТ»** → **«В чат»** (или Cmd/Ctrl+Enter). Отправляется
сразу и прямо здесь: ход идёт через Claude Code CLI, транскрипт — в чате справа (своё
сообщение, ответ по мере набора, строки инструментов), документ на время работы накрыт
анимацией проработки. Когда агент закончит, документ и стадия перечитаются сами; в чате
останется короткий итог — «Внесены правки:» списком, ссылки на JIRA и Confluence, если
публиковал или менял, открытые вопросы, если есть, — и кнопка **«Открыть детальную
страницу»** (перечитать страницу заново). Идущий ход можно **«Остановить»**; страница,
открытая заново, подхватывает идущий ход.

Что уходит агенту, зависит от того, первое ли это сообщение в сессии требования:

- **первое** — черновик навыка, который раздел собирает по составу файлов эпика; твой
  текст в нём — правка PO к документу. Для deep-документа черновик начинается с
  `/bft-deep <slug>` (режим доработки), для fast-документа — без команды навыка, с
  указанием внести правку в `{slug}-fast.md` и прогнать линтер и пересборку страницы
  ревью, для задачи без документа — дополнением к диктовке в `/bft-fast`;
- **дальше** — текст как есть, в тот же диалог: ответ на уточняющий вопрос, «ок» на сухой
  прогон, следующая правка;
- **пустое поле** — следующий шаг навыка по артефактам (после deep с недостающими
  ссылками — `/bft-deliver <slug>`);
- **`/bft-… ` в начале** — команда навыка, которую назвал ты.

Подсказка об этом — под полем ввода.

![Быстрые правки: текст набран, готов к отправке](screenshots/03-detail-page/03-quick-edit.png)

### 4. Отгрузи в JIRA и Confluence

Документ deep собран, ссылок на эпик и страницу ещё нет — отправь пустое поле: уйдёт
`/bft-deliver <slug>`. Агент делает сухой прогон и задаёт вопросы в чат: пространство
Confluence, родительская страница, проект JIRA, если их нет в корневом `bft-config.md`.
Ответь в поле ввода (значения он запишет в корневой `bft-config.md`, чтобы не спрашивать
снова), затем **«ок»** — публикация. Под итогом появятся ссылки **JIRA** и **Confluence**,
они же — в колонке над чатом и в задаче Backlog.md, стадия — `DEEP-DONE`.

Чат Claude Code выключен в профиле (`claudeBin: off`) — «В чат» и «Создать документ»
кладут черновик в композер харнесса, Enter жмёшь сам.

### 5. Вернись

**«Назад»** возвращает туда, откуда пришёл: в превью или на доску.

## Что стоит знать

- Сессия Claude Code по требованию заводится один раз и переиспользуется (`--resume`):
  повторные правки и ответы уходят в тот же диалог, а не плодят новые чаты. В блоке
  «Последняя сессия» она подписана «Чат Claude Code — на детальной странице»; кнопки
  «Открыть чат» у неё нет — чат и есть эта страница.
- Ход идёт из рабочего пространства `bft` внутри воркспейса (там `bft-config.md` —
  копия корневого с путями от `bft/`, перечитывается на каждый ход: править корневой).
- Пока ход идёт, второй по тому же требованию не запустится; по другому — можно.
- Перезапуск харнесса обрывает идущий ход и очищает транскрипт на странице; сессия
  Claude Code при этом сохраняется — следующее сообщение продолжит её.
