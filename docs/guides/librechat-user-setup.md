# bft-writer в LibreChat: установка без прав администратора

Для сотрудника, у которого есть **только рабочий LibreChat**: подключены MCP JIRA и
Confluence, выдан доступ к модели, больше ничего. Никаких `librechat.yaml`, `.env` и
перезапусков сервера — всё делается мышкой в интерфейсе за 10–15 минут.

Что получится: в чате появляется `bft-fast` — он превращает Summary встречи или
диктовку в письмо, две таблицы и документ-шапку БФТ по методологии po-helper. Дальше
подключаются разведка по JIRA и Confluence и глубокая проработка.

Чего **не** получится без администратора: автосохранения документов на диск, запуска
линтеров, сборки HTML-страниц ревью и распознавания записи встречи. Документы будут
приходить текстом в чат — их вы копируете к себе или просите опубликовать в
Confluence. Подробности — в разделе «Что работает, а что нет».

## Шаг 1. Понять, что у вас включено — 2 минуты

Три проверки прямо в интерфейсе:

| Проверка | Как посмотреть | Что значит |
|---|---|---|
| **Навыки (Skills)** | в поле ввода сообщения набрать `$` | выпал список — навыки включены |
| **Агенты (Agents)** | в списке моделей/эндпоинтов есть «Agents», рядом — кнопка создать | можно собрать своего агента |
| **Code Interpreter** | в настройках агента, среди возможностей | почти наверняка выключен — это нормально |

Дальше — ровно один путь из трёх:

| Что есть | Путь | Времени |
|---|---|---|
| Навыки **и** агенты | **А** — загрузить навыки файлами | 10 минут |
| Только агенты | **Б** — агент с инструкцией | 10 минут |
| Ни того, ни другого | **В** — вставить инструкцию в чат | 2 минуты |

## Шаг 2. Получить файлы

Нужны заготовки: архивы навыков (`.zip`) и готовые инструкции (`.md`). Собираются
одной командой из клона репозитория — на любой машине, где есть терминал:

```sh
git clone https://github.com/po-helper-org/poh-bft-writer.git
cd poh-bft-writer
bash librechat-pack.sh
```

В `dist/librechat/` появятся:

- `bft-fast.zip`, `bft-writer.zip`, `bft-recon.zip`, `bft-deep-swarm.zip` и остальные —
  для **пути А**;
- `instructions-bft-fast.md` и такие же по каждому навыку — для **путей Б и В**.

Терминала нет — попросите файлы у того, кто уже ставил bft-writer: это обычные файлы,
их можно переслать в мессенджере.

## Путь А — навыки файлами

1. Боковая панель → **Skills** → **+** → **Upload a skill**.
2. Загрузить `bft-fast.zip`. Повторить для `bft-writer.zip` — в нём канон разделов,
   стиль и правила привязки к источникам, на которые ссылаются остальные навыки.
3. Позже, когда освоитесь, — `bft-recon.zip` (разведка по JIRA и Confluence) и
   `bft-deep-swarm.zip` (глубокая проработка и аудит).
4. Создать агента: **Agents** → создать → имя «БФТ», модель — любая доступная.
5. В настройках агента: **Enable skills** → добавить загруженные; в инструментах
   отметить MCP **JIRA** и **Confluence**.
6. В поле **Instructions** вставить текст из
   [`librechat/agent-profile.md`](librechat/agent-profile.md) — это поправка на то, что
   в LibreChat нет диска и скриптов. Без неё навык будет писать «сохранил файл
   `.bft/documentation/…`», хотя ничего не сохранил.
7. Сохранить агента. Готово — переходите к шагу 3.

> **Грабля.** Повторно загрузить навык с тем же именем нельзя — сначала удалить
> старый. Так же и обновление: удалить, загрузить свежий `.zip`.

## Путь Б — агент с инструкцией

Навыков в инстансе нет, но агента собрать можно.

1. **Agents** → создать → имя «БФТ · Fast», модель — любая доступная.
2. Открыть `dist/librechat/instructions-bft-fast.md`, скопировать **весь** текст и
   вставить в поле **Instructions**. Файл уже содержит и поправку на LibreChat, и тело
   навыка — это 15,5 тысяч знаков (24 КБ), так и должно быть: **ограничения на длину у
   поля нет**, оно влезает целиком (см. «Влезет ли инструкция» ниже).
3. Если ваш инстанс всё же обрежет вставку (дописанная кем-то валидация, прокси): оставить
   в поле первую часть — до заголовка `# bft-fast`, — а сам файл приложить к агенту как
   **File Context**: его текст тоже дополняет инструкции.
4. В инструментах отметить MCP **JIRA** и **Confluence**.
5. Приложить к агенту файлы `skills/bft-writer/resources/*.md` (**File Search** или
   **File Context**) — `bft_standards.md`, `writing_style.md`, `hard_gates.md`,
   `anchor_rules.md`. Это база канона: разделы, лексика, правила «факт только с
   источником».
6. Сохранить. Второй агент — «БФТ · Deep» с `instructions-bft-deep-swarm.md` — заводится
   так же, когда дойдёте до глубокой проработки.

## Путь В — без агентов вообще

Работает всегда, даже если в LibreChat доступен только чат с моделью.

1. Открыть новую беседу.
2. Первым сообщением вставить весь текст `instructions-bft-fast.md`, а следом —
   «Дальше работаем по этой инструкции. Источник пришлю следующим сообщением».
3. Вторым сообщением — Summary встречи или диктовку.

Минус один: инструкцию придётся вставлять в каждую новую беседу. Если в LibreChat есть
**библиотека промтов** — сохраните её туда как промт с командой (например `bft-fast`),
и дальше он вызывается из поля ввода по `/`.

## Шаг 3. Первый прогон

Одинаково для всех трёх путей. Выберите агента «БФТ» (путь А или Б) и напишите:

```
$bft-fast
```

и следом — текст встречи. В путях Б и В `$`-вызов не нужен: агент уже и есть навык,
просто пришлите источник:

```
Зафиксируй по методологии БФТ. Эпик: lk-b2b-docs.

Встречались с бухгалтерией: в личном кабинете юрлица нет раздела закрывающих
документов, акты ищут письмами. Хотят видеть список за период и выгрузку.
Иван Петров — владелец кабинета, Мария Сидорова — бухгалтерия…
```

Что должно прийти в ответ:

1. **Письмо** — Цель, How to demo, Открытые вопросы, Границы (и «Документация», если вы
   называли ссылки).
2. **Две таблицы** блоками csv: `personas.csv` (ФИО / Роль / Влияние) и
   `requirements.csv` (ASIS / TOBE).
3. **Документ-шапка** одним блоком markdown — его копируете к себе или отдаёте дальше.
4. **Строка самопроверки** — что навык проверил сам вместо линтера.

Признак, что всё работает правильно: в тексте нет ничего, чего вы не говорили, а
пробелы стоят вопросами в «Открытых вопросах», а не догадками. Это не осторожность
модели, а гейт методологии: факт без источника в ваших словах не проходит.

**Дальше:**

- «Опубликуй документ в Confluence, пространство BFT» — уйдёт через MCP от вашего имени;
- `$bft-recon` (или «пройди разведку по JIRA и Confluence») — карта того, что по теме
  уже описано и с чем пересекается;
- `$bft-deep-swarm` — аудит и полный документ из 11 разделов;
- `$bft-custdev` — скрипт проблемного интервью, когда пробел закрывается только
  разговором с заказчиком.

## Влезет ли инструкция в поле Instructions

Да. Проверено по исходникам LibreChat, а не по документации:

| Где мог быть лимит | Что в коде |
|---|---|
| форма агента (`Instructions.tsx`) | поле `required`, `maxLength` не задан |
| валидация запроса (`schemas.ts`) | `instructions: z.string().optional()` — без `.max()` |
| база (`schema/agent.ts`) | `instructions: { type: String }` — без `maxlength` |
| размер запроса (`api/server/index.js`) | `express.json({ limit: '3mb' })` — у нас 24 КБ |

Сами файлы: самый большой — `instructions-bft-writer.md`, 20,6 тыс. знаков (31 КБ);
`instructions-bft-fast.md` — 15,6 тыс. знаков (24 КБ). До 3 МБ далеко.

Ограничение другое, и оно не про «влезет»: инструкция уходит в модель **на каждом
сообщении**. 15,6 тыс. знаков русского текста — это примерно 7 тысяч токенов на запрос.
Для контекста в 128–200 тысяч это немного, но если беседа длинная и дорогая, держите
одного агента на одну стадию, а не одного «на всё» со всеми навыками сразу.

Для **пути А** это не важно вовсе: там в поле идут только первые ~2 тысячи знаков
(поправка на LibreChat), а тело навыка LibreChat подаёт сам — и проверяет по своим
лимитам: имя ≤64 знака, `description` ≤1024, тело SKILL.md ≤100 000, архив ≤50 МБ,
≤500 файлов, ≤10 МБ на файл. Все семь бандлов проходят с запасом — самый длинный
`description` 601 знак, самое длинное тело 17 986 знаков.

## Что работает, а что нет

| Возможность | Без прав админа |
|---|---|
| Письмо, таблицы, документ-шапка `bft-fast` | ✅ полностью |
| Канон 11 разделов, гейты, стиль (`bft-deep-swarm`, `bft-writer`) | ✅ полностью |
| Разведка и чтение JIRA / Confluence (`bft-recon`) | ✅ через ваши MCP |
| Публикация страницы и комментарий в задаче (`bft-deliver`) | ✅ через ваши MCP, от вашего имени |
| Скрипт интервью `bft-custdev` | ✅ текстом, без HTML-страницы встречи |
| Сохранение документов на диск, `.bft/`, `/bft-index` | ❌ документы приходят текстом в чат |
| Линтеры (`bft-lint` и др.) | ❌ заменены самопроверкой навыка |
| Страницы ревью `.html` | ❌ |
| Распознавание записи встречи | ❌ приносите текстовый транскрипт |
| Фоновые форки разведки и глубины | ❌ запускаются вами по очереди |
| Раздел «Управление требованиями», доска стадий | ❌ это плагин для другого харнесса |

Ничего из красного не ломает методологию: гейты и формы живут в тексте навыка, а не в
скриптах. Скрипты закрывали механическую проверку — без них её проходит сам навык и
отчитывается строкой самопроверки.

## Если нужен полный контур — что попросить у администратора

Готовый текст, который можно переслать в поддержку LibreChat как есть:

> Прошу включить для нашего инстанса LibreChat:
> 1. Возможности агентов (`endpoints.agents.capabilities`): `skills`, `execute_code`,
>    `stateful_code_sessions`, `subagents`, `run_in_background`; `recursionLimit: 50`.
> 2. Code Interpreter (`LIBRECHAT_CODE_BASEURL_STATEFUL`) — навыки запускают
>    python-скрипты проверки документов на стандартной библиотеке, без сети.
> 3. По возможности — MCP-сервер файловой системы для общего каталога отдела, чтобы
>    документы требований не терялись между беседами.
>
> Зачем: методология подготовки БФТ (репозиторий poh-bft-writer) поставляется как
> Agent Skills; без этих пунктов работает только текстовая часть, без автопроверок и
> хранения.

Что именно администратор будет делать — по шагам с примерами конфигов расписано в
[`librechat-setup.md`](librechat-setup.md).
