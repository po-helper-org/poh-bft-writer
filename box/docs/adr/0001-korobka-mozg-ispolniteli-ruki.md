# Коробка думает сама, внешние агенты только исполняют

Коробка БФТ ставится отдельно (`docker-compose`) и должна сама не выпускать непроработанные требования, кто бы её ни вызвал. Поэтому у неё своя модель (провайдер настраивается: сейчас GLM, в корпоративном контуре — корпоративная), она сама пишет пакет, ведёт стратегию и судит о качестве. Проверки, которые проверяются кодом (идентификаторы, ссылки, приоритеты), идут кодом поверх модели. Своих каналов у коробки нет: людей, Jira и Confluence трогают только исполнители по её указаниям; коробка хранит состояние инициативы и версии пакета.

Решение владельца 2026-10-16, тикет «Жизненный цикл инициативы БФТ v1» (#345). Заменяет решение 2026-10-15 «коробка сама LLM не зовёт, сессии исполняет подключённый Hermes».

## Considered Options

- Без своей модели — тексты пишут исполнители, коробка проверяет только детерминированно: качество зависело бы от того, кто вызвал коробку.
- Коробка сама читает или пишет Jira и Confluence: каждой установке нужны корпоративные доступы; отложено — чтение для проверки ссылок можно добавить, если присланного контекста не хватит.

## Consequences

- Правила общения с людьми (каналы, уровни доверия, лимиты, ✅ на сообщение) живут у исполнителя; коробка лишь не выдаёт указаний адресатам вне утверждённого плана.
- Решения PO приходят исходами указаний через исполнителя; в v1 коробка им доверяет.
