# Коробка — отдельный публичный репозиторий на Temporal в docker-compose

Коробка живёт в своём репозитории `po-helper-org/poh-bft-box`: README, `docker-compose`, MCP-сервер, обезличенный канон БФТ и навык исполнителя. Всё корпоративное — шаблоны пространств, замечания ревью, примеры — хранится в настройках вне репо. Процесс инициативы ведёт Temporal: таймеры сроков указаний, повторы вызовов модели, итерации переживают рестарт. Compose: `box-mcp`, `box-worker`, `temporal`, `postgres` (общий для Temporal и данных коробки) и `temporal-ui` в профиле `debug`. Стек — Python 3.12, FastMCP, Temporal SDK. Модель — любой OpenAI-совместимый API из `.env`. Из `poh-issue-agents` переносится только знание (канон, эталоны, подсказки стадий), без кода воркера.

Решение владельца 2026-10-19, тикет «Репозиторий коробки, состав docker-compose и судьба стенда T1» (#358).

## Considered Options

- Пакет внутри `poh-issue-agents`: продукт с собственным README и compose утонул бы в контуре GitHub-задач.
- DBOS на одном Postgres вместо Temporal: легче по памяти, но опыта с ним нет. Это запасной вариант, если compose окажется тяжёлым.
- Свой конечный автомат на Postgres: пришлось бы заново писать таймеры и повторы.

## Consequences

- Стенд T1 (Gitea, webhook, worker, Temporal под systemd) коробке не нужен: юниты остановлены и выключены 2026-10-19, данные хранятся месяц.
- На сервере владельца свободной памяти мало, поэтому лимиты памяти в compose обязательны, а перед запуском снимается замер.
