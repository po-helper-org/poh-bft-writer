# Контракт протокола коробки БФТ 1.0.0

Договор между коробкой и любым её исполнителем — внешним ИИ-агентом, который по указаниям коробки работает с людьми и корпоративными системами. Коробка пока не собрана. Контракт уже нужен тестовому двойнику на стороне исполнителя (po-helper-org/poh-widget-harness#43): обе стороны гоняют контрактные тесты по одним и тем же эталонам и поэтому не разъезжаются. Когда появится репозиторий коробки, контракт переедет туда целиком.

Термины — в [словаре](../GLOSSARY.md). Откуда решения:
- «Жизненный цикл инициативы БФТ v1» (#345) — состояния, итерация, указание, исход;
- «Протокол коробки» (#352) — вызовы, идемпотентность, версии;
- этот контракт (#363).

## Состав

| Файл | Что |
|---|---|

| [`rendered/`](rendered/) | markdown-вид итераций 3 (проработка) и 8 (приёмка) |
| `tests/test_bft_box_contract.py` | эталоны проходят схему, а нарушения договорённостей схема ловит |

## Вызовы и сообщения

| Вызов | Запрос | Ответ |
|---|---|---|
| `start` | `StartRequest` — обязательна только `goal` | `Ack` (итерация 1 `preparing`) |
| `submit` | `SubmitRequest` — исходы по `directive_id` | `Ack`: новая итерация или «исходы копятся» |
| `get` | `iteration_id`, `format=json\|md` | `Iteration` |
| `status` | `initiative_id` | `Status` — дёшево, без модели |
| `control` | `ControlRequest` — `pause`, `resume`, `cancel`, `reopen` | `Ack` |
| `list` | — | `InitiativeList` |
| любой отказ | — | `Error` (`schema_version` есть и в ошибке) |

## Правила, которые держит схема или эталоны

- Новая итерация начинается в одном из трёх случаев: по всем указаниям текущей итерации есть исходы, исполнитель передал `iterate: true` или истёк срок указания (`trigger: deadline`). Иначе `submit` отвечает `new_iteration: false` и `pending_outcomes`.
- `submit`, пока последняя итерация в статусе `preparing`, возвращает `not_ready` (решение #363). Повторить после `retry_after_seconds`.
- `submit` с устаревшей `base_iteration` — `conflict` и `latest_iteration_id`.
- Тот же `idempotency_key` с тем же телом — тот же ответ. С другим телом — `idempotency_mismatch`.
- Другая мажорная `schema_version` — `bad_schema_version`. Старшая минорная — совместимый ответ.
- Итерация `preparing` — только шапка. `ready` — пакет, светофор и указания. `error` — только `error` (сбой модели — это итерация N+1 со статусом `error`, указания прошлой итерации остаются в силе).
- В состоянии `acceptance` все проверки зелёные, и у каждой есть доказательство.
- `external_refs` из `start` возвращаются в каждой итерации без изменений.
- `id` указания постоянен между итерациями. Повтор по тому же пробелу — тот же `id` с `attempt` на единицу больше.
- Если в `start` нет команды, первое указание — `clarify_team`.
- Человеку вне утверждённого плана указание не выдаётся. Вместо этого PO получает `approve_plan_change`.
- `reopen` работает и для `cancelled`, и для `accepted`. Во втором случае это «Доработка»: тот же `initiative_id`, версия пакета +1.
- На паузе новых указаний нет, выданные получают `suspended`, истёкший срок не запускает новую итерацию.
