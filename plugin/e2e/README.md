# E2E-прогоны раздела

Playwright против **живого** харнесса с установленным `poh-bft-plugin` (см.
`docs/guides/dsh-plugin-setup.md`) в системном Chrome. Каждый файл — один сценарий из
`docs/guides/plugin-playbooks/` (корень репозитория), шаги идут в том же порядке, что в тексте плейбука.

```sh
pnpm test:e2e          # проверки поведения
pnpm playbook:shots    # то же + скриншоты в docs/guides/plugin-playbooks/screenshots/
```

Адрес харнесса берётся из `DSH_E2E_URL` (с токеном: `dsh web` печатает его при старте), а
без неё — из последней строки `dsh web:` в `/tmp/dsh-harness-ui.log`, если харнесс пишет лог
туда. Нет ни того, ни другого — прогоны пропускаются.

## Что прогоны трогают у живого харнесса

- **Документ настроек** (`$DSH_HOME/settings.yaml`, секция `bft`) — сценарии 5 и 6 пишут
  туда демонстрационные значения. Перед этим текущие значения снимаются и в конце
  возвращаются дословно; копия лежит в `e2e/.artifacts/<сценарий>.settings-backup.json`.
  Прогон упал до восстановления — открой Настройки → Плагины → «Требования» и верни
  значения из этого файла руками.
- **Композер чата** — кнопки раздела кладут туда черновик; прогон читает его и стирает.
  Enter не нажимается никогда: агенту ничего не уходит.
- **Ничего в Backlog.md** — раздел только читает.

Форма для сценария 6 — локальный HTTP-сервер (`support/form-server.ts`), а не настоящая
Google Forms: без сети, с проверяемой отправкой.

## Скриншоты публичные — страница обезличивается

Перед каждым снимком `support/redact.ts` подменяет текст в DOM, прячет фотографию
пользователя, а живые значения настроек PO — что бы в них ни было — регистрирует секретами
прогона (`readCard` → `registerSecrets`). Документ требования на детальной странице
подменяется демонстрационным (`support/demo-document.ts`). После снимка всё откатывается.

В коде только общие правила: почта → `example.com`, «Фамилия Имя» → «Сотрудник». **Словарь
установки** — названия продуктов, партнёров, домены трекера и вики, фамилии без имени —
живёт в `e2e/.redact.local.json` (в .gitignore): список «что скрывать» в публичном
репозитории раскрыл бы ровно то, что скрывает. Формат и пример —
`e2e/redact.local.example.json`; `samples` в нём — строки с живой страницы, на которых
`00-redaction-rules.e2e.ts` проверяет, что словарь вычищает всё из `forbidden`.

Гейт `assertClean` падает, если на кадре остался фрагмент из `forbidden`. Поймал новое слово —
допиши правило и образец в словарь. Гейт видит только текст: логотипы-картинки перед
публикацией смотрят глазами.

## Почему не поднимаем харнесс внутри теста

Харнесс — композиция профиля, плагинов и воркспейса с Backlog.md; собрать её в тесте —
отдельный проект, а живой уже стоит и ровно его видит PO. Плата за это — один воркер без
параллельности (`playwright.config.ts`): два прогона одновременно затёрли бы друг другу
настройки и композер.
