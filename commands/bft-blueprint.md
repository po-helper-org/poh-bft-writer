## Использование

```
/bft-blueprint <epic_slug|путь> [вводная] [--story | --map | --layers]
```

**Параметры:**
- `<epic_slug|путь>` — слаг эпика (БФТ ищется по пути `<docs_path>/<epic_slug>/<epic_slug>.md`, если его нет — `<epic_slug>-fast.md` с предупреждением) либо прямой путь к документу.
- `--story` — опц., только первый этап: собрать или пересобрать историю и остановиться.
- `--map` — опц., только второй этап по уже согласованной истории.
- `--layers` — опц., прежняя слоевая схема `<epic_slug>-blueprint.md` для документов, собранных раньше.
- `[вводная]` — опц., текст или путь к файлу: какие команды участвуют и кто что делает. Без неё команды берутся из «Зависимостей» БФТ, остальное — `[УТОЧНИТЬ]`.

## Примеры

```
/bft-blueprint bartello-restart
/bft-blueprint bartello-restart --story
/bft-blueprint bartello-restart --map "сканер делает Bartello, проверку билета — GDS"
```

## Что делает

**Этап 1 — история через экраны**, со своей паузой:

1. `<epic_slug>-story.md` — персонажи, этапы, шаги, экраны, вопросы.
2. `<epic_slug>-story.html` — каждый персонаж — ряд, который читается слева направо через экраны; карточка шага — картинка, контур, заголовок, пояснение; «Рассказать историю по шагам» — слайды; красная точка — открытый вопрос.

Пробелы истории агент закрывает сам: один раунд до четырёх вопросов PO с вариантами из БФТ.

**Этап 2 — карта инициативы**, когда PO согласовал историю:

1. `<epic_slug>-map.md` — команды, задачи, IDEF0, процессы, участники и схемы, критерии, цепочка, вопросы.
2. `<epic_slug>-map.html` — первый экран на всю высоту — «Что видят» раскадровкой: экран картинкой и подпись на каждый шаг, несколько экранов листаются в кадре, путь уходит вправо; ниже колонки — шаги пути, ряды «Что делаем» (задачи с цветом команды и фильтром по команде), «Как это работает» (Frontstage, Backstage, Support). Клик по процессу — карточка для техлида: «← до · этот процесс · после →», было → станет, чек-лист «что требуется», описание и sequence-схема с линией видимости и списком скрытых шагов, IDEF0 с декомпозицией, заметка и промпт для системной аналитики с ИИ. «Схема как код» — редактор блоков `seq` и `idef0`: проверка на лету, предпросмотр, «применить к карточке» и промпт «собрать схему с ИИ». Шапки нет: «Рассказать историю», «Блокеры», «Инструкции», «Легенда» и фильтр по команде — в меню-бургере поверх карты. Один файл, без CDN; на телефоне — лента по шагам.

## Важно

**Не источник требований.** Только то, что есть в БФТ или в ответах PO. Нет — `[УТОЧНИТЬ у {кого}]` и строка в «Вопросах».

**Лёгкая карта, детали по клику.** Задача — одна строка до 80 знаков, ряды — слои Service Blueprint, а не системы. Эндпоинты, протоколы, таблицы и поля — вне высоты БФТ, линтер их отклоняет.

**Каждое ФТ, ИТ и НФТ на карте** — в задаче или в критерии процесса.

**Схемы — код, а не рисунок.** Sequence и IDEF0 — короткие блоки ```` ```seq П3 ```` и ```` ```idef0 1.2 ```` (`resources/diagram_dsl.md`). LLM пишет только текст; проверка (коды `DG`) и рисунок детерминированы. Одну схему правят блоком через `bft-diagram-apply.py`, карту целиком не переписывают.

**Не входит в контур по умолчанию.** `/bft-fast` и `/bft-deep` команду не вызывают — только явный запуск.

**Не трогает БФТ.** Единственные записи — `<epic_slug>-story.*` и `<epic_slug>-map.*` (в режиме `--layers` — `<epic_slug>-blueprint.*`).

## Инструкция для LLM

Навык — `../skills/bft-blueprint/SKILL.md`. Порядок — этапы оттуда: resolve → **story** со своим STOP → **map** → STOP. Стандарты — `resources/story_line.md`, `resources/story_interview.md`, `resources/map_rules.md`; эталоны — `examples/golden_story.md`, `examples/golden_map.md`.

### Гейт перед показом PO (обязателен)

История:

```bash
python3 <skills_path>/bft-blueprint/scripts/bft-story-lint.py <docs_path>/<epic_slug>/<epic_slug>-story.md
python3 <skills_path>/bft-writer/scripts/bft-style-lint.py <docs_path>/<epic_slug>/<epic_slug>-story.md
python3 <skills_path>/bft-blueprint/scripts/bft-story-render.py <docs_path>/<epic_slug>/<epic_slug>-story.md
```

Карта:

```bash
python3 <skills_path>/bft-blueprint/scripts/bft-map-lint.py <docs_path>/<epic_slug>/<epic_slug>-map.md
python3 <skills_path>/bft-writer/scripts/bft-style-lint.py <docs_path>/<epic_slug>/<epic_slug>-map.md
python3 <skills_path>/bft-blueprint/scripts/bft-map-render.py <docs_path>/<epic_slug>/<epic_slug>-map.md
```

Ненулевой код — причина в выводе, исправить и прогнать снова. Рендеры по сломанному документу файлов не пишут.

Одна схема (правка PO, блок из карточки, ответ ИИ):

```bash
python3 <skills_path>/bft-blueprint/scripts/bft-diagram-apply.py <docs_path>/<epic_slug>/<epic_slug>-map.md блок.txt
python3 <skills_path>/bft-blueprint/scripts/bft-map-render.py <docs_path>/<epic_slug>/<epic_slug>-map.md
```

### САМОПРОВЕРКА ИСТОРИИ

1. Каждый персонаж — ряд «Знакомьтесь» → шаги → «И с тех пор», слева направо?
2. Карточка шага — только картинка, контур, заголовок, пояснение?
3. Ни ID требований, ни команд, ни слов разработки в истории (нет `ST012`)?
4. У каждого шага и экрана есть источник (нет `ST016`)?
5. Вопросы PO заданы одним раундом, с вариантами из БФТ; без ответа — красная точка?
6. На STOP показаны путь к `-story.html`, «было → стало» и вопросы «кому — что»; карта не начата, пока PO не согласовал историю?

### САМОПРОВЕРКА КАРТЫ

1. Колонки и «Что видят» совпадают с согласованной историей?
2. Задача — один результат одной команды до 80 знаков, без API и БД (нет `MP014`, `MP018`)?
3. Каждое ФТ, ИТ, НФТ есть в задаче или критерии (нет `MP017`)?
4. У каждой задачи есть процесс и блок IDEF0, у каждого процесса — блок схемы с описанием, критерии и связь в цепочке (нет `MP021`–`MP023`, `MP028`, `DG025`)?
5. Схемы и IDEF0 — блоки без ошибок `DG`; развилки — из БФТ, стрелки декомпозиции сходятся по подписям?
6. Неизвестная команда — `? (кандидаты)`, неизвестное — в «Вопросах» с «Кому»; блокеры отмечены типом `блокер`?
7. На STOP показаны путь к `-map.html`, задачи по командам, блокеры и вопросы «кому — что»?
