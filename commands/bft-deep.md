## Использование
```
/bft-deep <документ|epic_slug|seed> [epic_slug]
```
- `<документ|epic_slug|seed>` — приоритет источника (`orchestration.md` §Стадии, стадия 1): путь к существующему документу БФТ; либо `epic_slug`, если документ стадии fast лежит по стандартному пути `<docs_path>/<epic_slug>/<epic_slug>-fast.md` (читается только на чтение — deep пишет свой `<epic_slug>.md`, `../skills/bft-fast/resources/document_assembly.md` §«Путь файла») или опубликован (тогда читается `confluence_get_page` по `pageId`); документа нет нигде → деградация на seed (Fast-черновик/Summary), сначала собрать шапку по `document_assembly.md`.
- `[epic_slug]` — опц.; нужен в основном при seed-деградации (без него — date-slug из темы); при чтении существующего документа epic_slug берётся из его frontmatter/пути.

## Важно
Роль — Аудитор (V2). Берёт fast-документ как основу, **сначала аудирует его и задаёт вопросы**, затем наращивает глубину и укладывает в канон-структуру MTS. Стоп на валидированном черновике; `/bft-deliver` — отдельный ручной шаг PO. Факт без источника → `[УТОЧНИТЬ]`. Шапка `bft-fast` сохраняется дословно, канон дописывается ниже строки-границы.

- **Вопросы раньше документа.** `/bft-fast` наружу не ходит и фиксирует только слова PO, поэтому его документ неполон по построению. Deep — первый, кто поднимает индекс `.bft/index/`, Confluence, JIRA, git и прошлые артефакты эпика, и первым делом сверяет с ними seed по шести срезам (пробел / противоречие / edge-кейс / граница / термин / риск) — `../skills/bft-deep-swarm/resources/audit.md`. Интерактивный прогон выводит вопросы и **останавливается** до ответов PO; фоновый — помечает блокируемые ячейки `[УТОЧНИТЬ]`, продолжает и выносит список в нотификацию. В документ вопросы не пишутся ни в одной ветке (ЗМ-020).

- `/bft-draft` вызывается **как генератор текста канона** и сам документ не сохраняет; единственная запись файла — эмит (стадия 11). `/bft-validate` и ревью работают по области ниже строки-границы; шапка и строка-статус — read-only контекст, 🔴 на них — ложное срабатывание.
- Документ уже обогащён (`stage: deep` во frontmatter или «Проблема которую решаем» ниже границы) → прогон **доработка**: закрыть `[УТОЧНИТЬ]`, уточнить разделы; канон не пересобирается, ID не перенумеровываются.
- Confluence: обновляется та же страница по `pageId`, дубль не создаётся. `pageId: pending` → публикации нет, дальше `/bft-deliver <epic_slug>`.
- Запуск — вручную либо фоновым авто-форком `bft-fast`; параллельно с идущим форком прогон не запускать (`../skills/bft-fast/resources/open_field.md` §«Приоритет путей»).

## Инструкция для LLM
1. Загрузить `../skills/bft-deep-swarm/SKILL.md` + resources (orchestration/audit/enrichment/grounding_verifier/eval_rubric).
2. Резолв конфига (SKILL.md §Резолв).
3. Прочитать документ БФТ, зафиксировать границу шапки и определить режим прогона — первичная сборка или доработка (`orchestration.md` стадия 1: приоритет источника, поиск границы по порядку якорей `document_assembly.md`, проверка `stage: deep` / «Проблема которую решаем» отдельным шагом). Затем прогнать оркестрацию `../skills/bft-deep-swarm/resources/orchestration.md` стадии 0-11 (стадия context — `/bft-index` + Confluence/JIRA/git/прошлые артефакты; если индекс `.bft/index/` устарел или неполон по теме, перезапустить `/bft-index` перед этой стадией; стадия 2а audit — вопросы к PO по `../skills/bft-deep-swarm/resources/audit.md`, интерактивно со STOP, в фоне через `[УТОЧНИТЬ]` + нотификацию).
4. Emit (`orchestration.md` стадия 11): собрать документ = замороженная шапка (байт-в-байт, минус строка-граница и блок «Критичные требования» — ЗМ-022, ЗМ-027) + канон MTS. Первичная сборка → канон встаёт вместо плейсхолдера `## ⏳ Полный БФТ — в проработке`. Доработка → существующий канон сохраняется, правятся только ячейки с `[УТОЧНИТЬ]` и строки с новым ответом, новые ID — в конец типизированной таблицы, старые не перенумеровываются. В конце документа обязателен блок «Продолжить / уточнить БФТ» со слим-промтом (`../skills/bft-fast/resources/open_field.md` §«Судьба после deep»). Перед записью — гейт шаблона: `python3 <skills_path>/bft-writer/scripts/bft-lint.py <файл>`, ненулевой код = не сохранять и не публиковать (ЗМ-017, гейт 17). Обновить frontmatter (`stage: deep`, `version`+1, `synced`, `status`) и строку-статус; сохранить `<docs_path>/<epic_slug>/<epic_slug>.md` + artefacts/ — единственная запись документа за прогон; `<epic_slug>-fast.md` не перезаписывается. Опубликовать: реальный `pageId` во frontmatter → сухой прогон превью → STOP → «ок» PO → `confluence_update_page` по этому `pageId`; новую страницу не создавать. `pageId: pending` → в Confluence не писать вовсе: сохранить локально и вывести подсказку `/bft-deliver <epic_slug>` (создание страницы и запись `pageId`/`source` — его зона, `commands/bft-deliver.md` Шаг 3). MCP недоступен → `[УТОЧНИТЬ: MCP недоступен]`, локальный файл сохранён. Нотификация — успех/провал, никогда молча.
