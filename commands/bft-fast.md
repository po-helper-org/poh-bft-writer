## Использование

```
/bft-fast <источник> [epic_slug] [--table] [--no-deep]
```

**Параметры:**
- `<источник>` — путь к `#summary`-заметке, путь к файлу транскрипта или инлайн-текст. Пусто → команда просит указать.
- `[epic_slug]` — опц., имя для файла-копии; не задан → slug из главной темы Summary (`{ГГГГ-ММ-ДД}-{slug}`).
- `--table` — приложить вложение-таблицу требований (персоны + БТ/ПТ/ИТ/ФТ/НФТ) отдельным блоком после письма. По умолчанию выкл — `/bft-fast` выдаёт только письмо (самодостаточно для пересылки).
- `--no-deep` — не форкать фоновую deep-проработку (по умолчанию форкается: RICH-контекст → параллельно письму, THIN → следом, seed=письмо).

## Примеры

```
/bft-fast summaries/2026-07-03-direct-faq.md
/bft-fast summaries/2026-07-03-direct-faq.md --table
/bft-fast skills/bft-fast/examples/golden_summary.md
/bft-fast "сырой транскрипт встречи ..." direct-faq
```

## Важно

**Роль: PO-аналитик быстрого прохода.** Результат — **одно письмо в чат**, пересылаемое коллегам как есть. Не полный БФТ-документ. Глубина (полный сбор контекста, deep-проработка) по умолчанию форкается автоматически в фоне (этап 7, `bft-deep-swarm`) сразу после письма; `--no-deep` отключает форк — тогда это отдельный ручной шаг PO после ответов на вопросы письма, вне этой команды.

**Анти-правило:** ничего не выдумывать. Факт без источника в Summary → «Открытый вопрос», не утверждение.

## Инструкция для LLM

### ФОРМАТ ВЫВОДА — копируй структуру точно

Письмо — ровно 5 блоков, строго в порядке. Вложение-таблица — только при флаге `--table`.

```
Цель: <драйвер/контекст: для эпика X, почему — закон/бизнес/требование>. <что делаем, одно предложение>. (WHY вперёд)

How to demo:
1. <шаг от лица роли-приёмщика; дизамбигуация «X, не Y» в скобках, если сказана; без внутренних US#N/story-ид>
2. …

Открытые вопросы:
* <вопрос / блокер / решение — одна развилка на строку> (<владелец или «кто уточнит, срок» — если есть>)
* …
(плоский список; строка = вопрос/блокер/решение/зависимость; владелец опционален, в скобках; БЕЗ обязательного префикса `ФИО —`, БЕЗ заголовков-групп `ФИО:`, БЕЗ чекбоксов `- [ ]`)

Границы: <in-scope> (<out-of-scope> — не входят в зону БФТ).
Дополнительно, если возможно: <nice-to-have, если было>.
<операционные заметки: сроки/эффекты>

Документация:
* <указатель одной строкой, или [подпись](URL) где URL известен>
* …

────────────────────────────────────────
Вложение — ТОЛЬКО при флаге `--table` (иначе не выводить). Отдельным блоком после письма:

Персоны (домен знаний):

| ФИО | Роль | Департамент |
|---|---|---|
| … | … | … |

Требования:

| ID | ASIS (сейчас) | TOBE (после) | Связанные | Источник (цитата) |
|---|---|---|---|---|
| БТ-1 | … | … | … | ФИО: «…» |
(порядок строк: БТ → ПТ → ИТ → ФТ → НФТ)
```

### СТОП-ГАЛЛЮЦИНАЦИИ — на брифинге критично, не додумывать

- **Департамент/роль не сказаны на встрече → `[не указано]` / `[роль не подтверждена]`.** НЕ писать «Product», «Engineering», «QA» из головы.
- **Технологии/алгоритмы (BM25, TF-IDF, типы кухни, фильтры), которых НЕ было в репликах → НЕ добавлять.** Вопрос заводится, только если сам участник его поднял.
- **Таймстемпы НЕ цитировать.** Колонка «Источник» = текст реплики: `ФИО: «дословно»`.
- **ASIS не проговорён → `[ASIS не озвучен]`.** НЕ реконструировать «как оно наверное сейчас».
- **out-of-scope (следующий квартал / «не делаем») → только в «Границы».** НЕ в How to demo, НЕ в таблицу требований.
- **Блок «Цель» обязателен, WHY вперёд** (драйвер/эпик впереди механизма). Вопросы — строка = вопрос/блокер/решение; владелец опционален в скобках (не обязательный префикс `ФИО —`, не группировать, не чекбоксить).

### САМОПРОВЕРКА ПЕРЕД ВЫВОДОМ (пройди каждый пункт, иначе переделай)

1. Первая строка письма — `Цель: …`, WHY/драйвер вперёд? Если нет — добавь Цель, не начинай с «How to demo».
2. Блок «Открытые вопросы» — строка = вопрос/блокер/решение/зависимость, владелец опционален в скобках? Нет обязательного префикса `ФИО —`, нет заголовков-групп `ФИО:`, нет `- [ ]`? Если есть — переписать в плоский гибрид-список.
3. В теле письма нет внутренних `US#N`/story-ид? (Ссылка на родительский эпик `GDSLV-1374` как якорь — можно.)
4. Блок «Документация» — только реальные указатели/URL (нет URL → подпись без ссылки, не выдумывать)? Нет источников → блока нет.
5. Вложение-таблица выводится ТОЛЬКО если задан `--table`? Без флага — только письмо (5 блоков), таблицы нет.
6. Если задан `--table`: в «Персоны» департамент = `[не указано]` там, где не звучал? Роль не в индексе стейкхолдеров и не названа → `[роль не подтверждена]`? Нет выдуманных «Product/Engineering»?
7. Если задан `--table`: каждая строка таблицы требований имеет **реальную цитату** в «Источник» (строка с пустым источником — удалить)? «Связанные» — только ID (`БТ-1`, без нулей `БТ-001`), нет связи → пустая ячейка? ASIS без реплики = `[ASIS не озвучен]`?
8. В «How to demo» нет шагов про следующий квартал/будущие итерации («в Q4 будет…») и нет out-of-scope? Всё это — только в «Границы», не в демо и не в таблице?
9. В вопросах нет выдуманных технологий (BM25, кухни, фильтры), которых не поднимали участники?

### Этап 1: Загрузка
1. `skills/bft-fast/SKILL.md` (роль, принципы, этапы, резолв конфига).
2. `skills/bft-fast/resources/`: `extraction_schema.md`, `demo_synthesis.md`, `letter_format.md`, `requirements_table.md`.
3. Голос: `skills/bft-writer/resources/writing_style.md`.
4. Резолв конфига из `bft-config.md` (опц.; нет файла → дефолты ниже, без остановки).

### Этап 2: resolve-source
Определить форму `<источник>` (СТ-2). Транскрипт → внутренняя выжимка до `#summary`. Пусто → спросить путь/текст, не выдумывать. Путь указан, но файл не читается/не найден → сообщить ошибку пути и попросить корректный источник; не эмулировать содержимое.

### Этап 3: extract
Извлечь сущности по `extraction_schema.md`; каждая с source; участники сверить с индексом стейкхолдеров.

### Этап 4: synth
Построить `Цель` (WHY вперёд: драйвер/эпик, затем что делаем, 1-2 строки), `How to demo` (demo_synthesis.md; дизамбигуации «X, не Y» в скобках у шагов; без US#N/story-ид), `Открытые вопросы` (гибрид: вопрос/блокер/решение/зависимость, владелец опционально в скобках; No Silent Skip), `Границы` (in/out + тир «Дополнительно, если возможно» + заметки), `Документация` (указатели на источники — Confluence/JIRA/смежные истории; живая ссылка где есть URL, иначе подпись; нет источников → блока нет).

### Этап 5: assemble + gate
Собрать письмо по `letter_format.md` (5 блоков, без обвязки). **Вложение — только если задан `--table`:** по `requirements_table.md` блок персон (ФИО/Роль/Департамент) + таблица требований ASIS/TOBE (порядок БТ→ПТ→ИТ→ФТ→НФТ, каждая строка ← цитата, без обогащения). Гейт: утверждение письма ← source или вопрос; URL «Документации» — только реальные; строка таблицы ← непустая цитата; роль/департамент ← индекс стейкхолдеров/сказанное или `[не указано]`.

### Этап 6: emit
Вывести письмо в чат (готовое к пересылке). **Вложение-таблицу — только если задан `--table`**, отдельным блоком после письма. Опц. копия в `.bft/documentation/{epic_slug}/letter.md` (письмо) и — при `--table` — `.bft/documentation/{epic_slug}/requirements.md` (таблица); `docs_path` из `bft-config.md`, дефолт `.bft/documentation`. Финал: одна простая строка вне тела письма — по умолчанию (без `--no-deep`) «Глубокая проработка запущена в фоне, уведомление придёт по завершении»; при `--no-deep` — «Ответы получены — запусти глубину отдельно». Без внутренностей пайплайна (swarm/оси/тяжесть).
