## Использование

```
/bft-fast <источник> [epic_slug]
```

**Параметры:**
- `<источник>` — путь к `#summary`-заметке, путь к файлу транскрипта или инлайн-текст. Пусто → команда просит указать.
- `[epic_slug]` — опц., имя эпика: определяет путь документа (`<docs_path>/<epic_slug>/<epic_slug>.md`) и файла-копии письма; не задан → slug из главной темы Summary (`{ГГГГ-ММ-ДД}-{slug}`).

## Примеры

```
/bft-fast summaries/2026-07-03-direct-faq.md
/bft-fast skills/bft-fast/examples/golden_summary.md
/bft-fast "сырой транскрипт встречи ..." direct-faq
```

## Важно

**Роль: PO-аналитик быстрого прохода.** Результат — **одно письмо в чат**, пересылаемое коллегам как есть, плюс документ БФТ (шапка + открытое поле) и Confluence-черновик после «ок» PO. Не полный БФТ канон-структуры MTS. Глубина (полный сбор контекста, deep-проработка) — не автоматика: PO отвечает на вопросы шапки и сам осознанно запускает `/bft-deep <epic_slug>`, либо копирует промт из открытого поля документа (`resources/open_field.md`) в любую сессию Claude Code — отдельный шаг, вне этой команды.

**Анти-правило:** ничего не выдумывать. Факт без источника в Summary → «Открытый вопрос», не утверждение.

## Инструкция для LLM

### ФОРМАТ ВЫВОДА — копируй структуру точно

Письмо — ровно 4 блока, строго в порядке. Затем вложение.

```
Цель: <1-2 строки: кто хочет что, зачем, ключевой enabler>

How to demo:
1. <шаг от лица роли-приёмщика; дизамбигуация «X, не Y» в скобках, если сказана>
2. …

Открытые вопросы:
* <ФИО> — <вопрос кратко>
* <ФИО> — <вопрос кратко>
(плоский список; БЕЗ заголовков-групп `ФИО:`, БЕЗ чекбоксов `- [ ]`; владелец неясен → `* [кому?] — вопрос`)

Границы: <in-scope> (<out-of-scope> — не входят в зону БФТ).
Дополнительно, если возможно: <nice-to-have, если было>.
<операционные заметки: сроки/эффекты>

Вложение — таблица требований на согласование границ:

Персоны (домен знаний):

| ФИО | Роль | Департамент |
|---|---|---|
| … | … | … |

Требования:

| ID | ASIS (сейчас) | TOBE (после) | Связанные | Источник (цитата) |
|---|---|---|---|---|
| БТ-1 | … | … | … | ФИО: «…» |
(порядок строк: БТ → ПТ → ИТ → ФТ → НФТ)
```

После вложения — документ БФТ: скелет (frontmatter, H1, строка-статус, шапка, строка-граница, открытое поле) собирается точно по `resources/document_assembly.md` и `resources/open_field.md`, шаблон здесь не дублируется — эталон целиком в `examples/golden_document.md`. Сохраняется в `<docs_path>/<epic_slug>/<epic_slug>.md`.

### СТОП-ГАЛЛЮЦИНАЦИИ — на брифинге критично, не додумывать

- **Департамент/роль не сказаны на встрече → `[не указано]` / `[роль не подтверждена]`.** НЕ писать «Product», «Engineering», «QA» из головы.
- **Технологии/алгоритмы (BM25, TF-IDF, типы кухни, фильтры), которых НЕ было в репликах → НЕ добавлять.** Вопрос заводится, только если сам участник его поднял.
- **Таймстемпы НЕ цитировать.** Колонка «Источник» = текст реплики: `ФИО: «дословно»`.
- **ASIS не проговорён → `[ASIS не озвучен]`.** НЕ реконструировать «как оно наверное сейчас».
- **out-of-scope (следующий квартал / «не делаем») → только в «Границы».** НЕ в How to demo, НЕ в таблицу требований.
- **Блок «Цель» обязателен.** Вопросы — только `* ФИО — вопрос` (не группировать, не чекбоксить).

### САМОПРОВЕРКА ПЕРЕД ВЫВОДОМ (пройди каждый пункт, иначе переделай)

1. Первая строка письма — `Цель: …`? Если нет — добавь Цель, не начинай с «How to demo».
2. Блок «Открытые вопросы» — каждая строка вида `* ФИО — вопрос`? Нет заголовков-групп `ФИО:` и нет `- [ ]`? Если есть — переписать в плоский список.
3. В «Персоны» департамент = `[не указано]` там, где не звучал? Роль не в индексе стейкхолдеров и не названа → `[роль не подтверждена]`? Нет выдуманных «Product/Engineering»?
4. Каждая строка таблицы требований имеет **реальную цитату** в «Источник»? Строка с `[не указано]`/пустым источником — **удалить** (нет цитаты — нет требования).
5. «Связанные» — только ID (`БТ-1`, `ПТ-1`), не свободный текст, не `[не указано]` (нет связи → пустая ячейка)? ID вида `БТ-1` (без нулей `БТ-001`)?
6. ASIS без реплики = `[ASIS не озвучен]`? Нет реконструкции «как наверное сейчас»?
7. В «How to demo» нет шагов про следующий квартал/будущие итерации («в Q4 будет…») и нет out-of-scope? Всё это — только в «Границы», не в демо и не в таблице?
8. В вопросах нет выдуманных технологий (BM25, кухни, фильтры), которых не поднимали участники?
9. Документ собран по `document_assembly.md`: frontmatter (10 ключей), H1, строка-статус, шапка, ровно одна строка-граница `BFT-HEAD-END`?
10. Открытое поле присутствует, промт заполнен реальными значениями (epic_slug, источник, Confluence или «не опубликовано», pin_commit)? Ни одной незаполненной `<…>`-подстановки?
11. Публикация в Confluence — только после сухого прогона и явного «ок» PO? При недоступном MCP — `pageId: pending` и честная пометка, без эмуляции успеха?

### Этап 1: Загрузка
1. `skills/bft-fast/SKILL.md` (роль, принципы, этапы, резолв конфига).
2. `skills/bft-fast/resources/`: `extraction_schema.md`, `demo_synthesis.md`, `letter_format.md`, `requirements_table.md`, `document_assembly.md`, `open_field.md`.
3. Голос: `skills/bft-writer/resources/writing_style.md`.
4. Резолв конфига из `bft-config.md` (опц.; нет файла → дефолты ниже, без остановки).

### Этап 2: resolve-source
Определить форму `<источник>` (СТ-2). Транскрипт → внутренняя выжимка до `#summary`. Пусто → спросить путь/текст, не выдумывать. Путь указан, но файл не читается/не найден → сообщить ошибку пути и попросить корректный источник; не эмулировать содержимое.

### Этап 3: extract
Извлечь сущности по `extraction_schema.md`; каждая с source; участники сверить с индексом стейкхолдеров.

### Этап 4: synth
Построить `Цель` (кто/что/зачем + enabler, 1-2 строки), `How to demo` (demo_synthesis.md; дизамбигуации «X, не Y» в скобках у шагов), `Открытые вопросы` (атрибуция по стейкхолдерам; неясно → `[кому?]`; No Silent Skip), `Границы` (in/out + тир «Дополнительно, если возможно» + заметки).

### Этап 5: assemble + gate
Собрать письмо по `letter_format.md` (порядок блоков, без обвязки) + вложение по `requirements_table.md`: блок персон (ФИО/Роль/Департамент) + таблица требований ASIS/TOBE (порядок БТ→ПТ→ИТ→ФТ→НФТ, каждая строка ← цитата, без обогащения). Гейт: утверждение письма ← source или вопрос; строка таблицы ← непустая цитата; роль/департамент ← индекс стейкхолдеров/сказанное или `[не указано]`.

### Этап 6: emit
Вывести письмо в чат (готовое к пересылке), затем вложение — таблицу требований отдельным блоком. Опц. копия письма — `.bft/documentation/{epic_slug}/letter.md` (`docs_path` из `bft-config.md`, дефолт `.bft/documentation`).

Собрать документ БФТ по `document_assembly.md`: frontmatter (10 ключей — состав и порядок см. `document_assembly.md` §Frontmatter, на fast `stage: fast`) + H1 + строка-статус + шапка (`Цель`/`How to demo`/`Открытые вопросы`/`Границы` — из письма; «Критичные требования (скелет на цитатах)» — из вложения) + строка-граница `BFT-HEAD-END` + открытое поле по `open_field.md` (плейсхолдер-заголовок, `<details>`, промт заполнен реальными значениями этого прогона — ни одной пустой `<…>`-подстановки). Сохранить в `<docs_path>/<epic_slug>/<epic_slug>.md`.

### Этап 7: publish
Сухой прогон: собрать превью Confluence-страницы (title = H1 документа; body = содержимое документа, frontmatter не публикуется; space = `wiki_space`, parent = `bft_parent_page_id` из `bft-config.md`; status «Черновик») → вывести превью → СТОП, дождаться явного «ок» PO. Без «ок» — не публиковать.

После «ок»: `confluence_create_page`. Успех → захватить `pageId`, записать `source` (URL страницы), `pageId`, `space` во frontmatter документа, пересохранить файл. MCP/VPN недоступен или запись не прошла → `pageId: pending`, `source: [УТОЧНИТЬ — не опубликовано]`; локальный `.md` уже сохранён на Этапе 6 независимо от исхода публикации; успех не эмулировать.

Финал — хендофф: строка с предложением ответить на «Открытые вопросы» шапки и запустить `/bft-deep <epic_slug>`, либо скопировать промт из открытого поля документа в любую сессию Claude Code.
