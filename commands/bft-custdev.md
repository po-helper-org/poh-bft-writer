## Использование

```
/bft-custdev <epic_slug> [--no-html]
```

**Параметры:**
- `<epic_slug>` — имя эпика. Скрипт собирается по **собранному БФТ**: берётся `<epic_slug>.md` со `stage: deep`, если он есть, иначе `<epic_slug>-fast.md`. Рядом читаются `personas.csv`, `requirements.csv` и `context_map.md` (опц.). Пусто → команда просит указать эпик.
- `--no-html` — не собирать страницу встречи `<epic_slug>-custdev.html` (по умолчанию собирается). Сам `.md` пишется в любом случае.

## Примеры

```
/bft-custdev direct-faq
/bft-custdev 2026-09-07-zayavki-operatora --no-html
```

## Что делает

Собирает **скрипт проблемного интервью**. Результат встречи — шесть блоков:

1. для кого;
2. какую проблему решаем;
3. как принимается работа;
4. как поймём, что решает;
5. кто вовлечён;
6. какое решение видит запрашивающий.

Блоки 3 и 4 главные: без приёмки и метрики БФТ писать не из чего.

**Решение запрашивающего — гипотеза, а не требование.** Запросы приходят решением
(«расширить кафка-топики»), а не проблемой («вывести КИНО на VibeApp, чтобы заработать»).
Скрипт не принимает такой запрос требованием: он ведёт по лестнице вверх — что произойдёт,
если не сделать → кто заметит первым → что делает вместо этого → по чему поймём, что
помогло. Исходная формулировка уезжает в блок 6 с критерием успеха и проверяется.

Вопрос заводится **только на пробел**: блок, уже понятный из fast-документа, вопроса не
получает. Обычно выходит 6–9 вопросов на разговор в 5–10 минут.

Канон методички «Awesome Problem Interview Script» (Сергей Тихомиров) — источник форм
вопроса, а не сценарий обхода: его 14 этапов рассчитаны на 45–60 минут исследования
незнакомой персоны.

## Артефакты

```
<docs_path>/<epic_slug>/<epic_slug>-custdev.md     скрипт интервью
<docs_path>/<epic_slug>/<epic_slug>-custdev.html   страница встречи
```

Документы БФТ, csv и карта контекста не трогаются: у прогона свой файл.

**Страница встречи** — рабочая поверхность разговора. Один вопрос на экран: текст, что
хотим узнать, кому, поле ответа, «Назад / Пропустить / Далее» и полоса прогресса.
Ctrl+Enter ведёт дальше.

| Где | Что |
|---|---|
| Левая рейка → Материалы | гипотеза, «что унести» с отметкой пробелов, участники |
| Левая рейка → Email Agenda | письмо участникам: зачем зовём и что спросим. Правится на месте, копируется или уходит в почту |
| Правая панель «Вопросы» | список всех вопросов с отметками; прыжок к любому |
| Экран итога | промт для чата и выгрузка ответов файлом |

К каждому вопросу прикладываются файлы: кнопкой, перетаскиванием или Ctrl+V со скриншотом
из буфера. На доске и на экране информации часто больше, чем участник успевает
проговорить. Файлы живут в памяти страницы и уходят на диск вместе с ответами; в промте
перечислены по вопросам, чтобы приложить их к тому же сообщению в чат.

Ответы живут в браузере; ключ ответа — хэш текста вопроса, поэтому пересборка скрипта не
сдвигает их на соседний вопрос.

## Когда запускать

**Обычно запускать не нужно: скрипт собирается сам.** `/bft-fast` форкает подготовку в фоне
после разведки (`--no-custdev` отключает). Эта команда — ручной путь: пересобрать скрипт
после правки документа, собрать его при `--no-custdev` или после падения фона, либо
подготовить второе интервью по оставшимся гипотезам.

Скрипт не собирается вовсе, если пробелов в документе нет: интервью тогда не требуется.

## После встречи

Ответы возвращаются в БФТ промтом с экрана итога плюс
транскрибация. Принимает повторный `/bft-fast`, а если канон уже собран — `/bft-deep`.
Новой команды для этого нет. Ответ участника становится цитатой-источником требования, и
закрытый им `[УТОЧНИТЬ]` получает нормальный якорь.

## Инструкция для LLM

1. Выбрать исходный документ: `<docs_path>/<epic_slug>/<epic_slug>.md` со `stage: deep`, иначе `<epic_slug>-fast.md`. Нет ни одного — сообщить путь и остановиться, содержимое не эмулировать.
2. Отработать этапы навыка `bft-custdev` (`<skills_path>/bft-custdev/SKILL.md`), пробелы брать по `../skills/bft-custdev/resources/gap_sourcing.md`.
3. Прогнать гейт 22: `python3 <skills_path>/bft-writer/scripts/bft-custdev-lint.py <путь к -custdev.md>`. Ненулевой код — исправить, файл не сохранять.
4. Собрать страницу, если нет `--no-html`: `python3 <skills_path>/bft-writer/scripts/bft-custdev-export.py <путь к -custdev.md>`.
5. Вывести нотификацию по `../skills/bft-fast/resources/custdev_fork.md` §Нотификация и предложить открыть страницу локально (`open <путь>`), не публиковать как Artifact.
