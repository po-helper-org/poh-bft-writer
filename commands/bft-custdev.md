## Использование

```
/bft-custdev <epic_slug> [--no-html]
```

**Параметры:**
- `<epic_slug>` — имя эпика. Скрипт собирается по артефактам `<docs_path>/<epic_slug>/`: `<epic_slug>-fast.md` (обязателен), `personas.csv`, `requirements.csv`, `context_map.md` (опц.). Пусто → команда просит указать эпик.
- `--no-html` — не собирать страницу встречи `<epic_slug>-custdev.html` (по умолчанию собирается). Сам `.md` пишется в любом случае.

## Примеры

```
/bft-custdev direct-faq
/bft-custdev 2026-09-07-zayavki-operatora --no-html
```

## Что делает

Собирает **скрипт проблемного интервью** по методологии «Awesome Problem Interview Script»
(Сергей Тихомиров, productframework.ru): гипотеза проблемы `Person + Problem + Cause +
Motivation` с общей метрикой, 14 этапов канона в двух потоках, дополнительные гипотезы по
пяти формулам, профиль персоны для заполнения после встречи.

Вопросы **выводятся из пробелов** документа fast: `[УТОЧНИТЬ]`, `[ASIS не озвучен]`,
открытые вопросы письма, `[роль не подтверждена]`, противоречия цитат. Вопрос без
пробела-источника не выводится: он тратит время встречи и создаёт видимость работы.

Пробел, закрытый находкой карты контекста `/bft-recon`, снимается — со ссылкой на источник
ответа, в разделе «Чего не спрашиваем». Ради этого фильтра команда и ждёт разведку.

## Артефакты

```
<docs_path>/<epic_slug>/<epic_slug>-custdev.md     скрипт интервью
<docs_path>/<epic_slug>/<epic_slug>-custdev.html   страница встречи
```

Документы БФТ, csv и карта контекста не трогаются: у прогона свой файл.

**Страница встречи** — рабочая поверхность разговора, а не второй рендер документа. Один
вопрос на экран: текст, поле ответа, поле «кто ответил», кнопки «Назад», «Не относится»,
«Далее» и полоса прогресса. Всё остальное убрано в левую рейку и открывается панелью:

| Вкладка рейки | Что внутри |
|---|---|
| Материалы | гипотеза проблемы, план и цели, участники, «Чего не спрашиваем» — переключаются вкладками внутри панели |
| Email Agenda | готовое письмо участникам: цель встречи, вопросы к обсуждению по адресатам, тайминг. Правится на месте, копируется или уходит в почтовый клиент |
| Подсказки | уточняющие контекстные вопросы методички — их держат открытыми на разговоре |
| Результат | промт для чата и выгрузка ответов файлом |

Вести можно не весь скрипт сразу: в «Участниках» у каждого кнопка «Вести только его
вопросы» — опросник сужается до его блока, чтобы отпустить человека со звонка раньше.

Ответы живут в браузере; ключ ответа — хэш текста вопроса, поэтому пересборка скрипта не
сдвигает их на соседний вопрос.

## Когда запускать

**Обычно запускать не нужно: скрипт собирается сам.** `/bft-fast` форкает подготовку в фоне
после разведки (`--no-custdev` отключает). Эта команда — ручной путь: пересобрать скрипт
после правки документа, собрать его при `--no-custdev` или после падения фона, либо
подготовить второе интервью по оставшимся гипотезам.

Скрипт не собирается вовсе, если пробелов в документе нет: интервью тогда не требуется.

## После встречи

Ответы возвращаются в БФТ промтом со страницы (рейка → «Результат») плюс
транскрибация. Принимает повторный `/bft-fast`, а если канон уже собран — `/bft-deep`.
Новой команды для этого нет. Ответ участника становится цитатой-источником требования, и
закрытый им `[УТОЧНИТЬ]` получает нормальный якорь.

## Инструкция для LLM

1. Убедиться, что `<docs_path>/<epic_slug>/<epic_slug>-fast.md` существует; нет — сообщить путь и остановиться, содержимое не эмулировать.
2. Отработать этапы навыка `bft-custdev` (`<skills_path>/bft-custdev/SKILL.md`), пробелы брать по `../skills/bft-custdev/resources/gap_sourcing.md`.
3. Прогнать гейт 22: `python3 <skills_path>/bft-writer/scripts/bft-custdev-lint.py <путь к -custdev.md>`. Ненулевой код — исправить, файл не сохранять.
4. Собрать страницу, если нет `--no-html`: `python3 <skills_path>/bft-writer/scripts/bft-custdev-export.py <путь к -custdev.md>`.
5. Вывести нотификацию по `../skills/bft-fast/resources/custdev_fork.md` §Нотификация и предложить открыть страницу локально (`open <путь>`), не публиковать как Artifact.
