## Использование

```
/bft-recon <epic_slug|тема> [источник]
```

**Параметры:**
- `<epic_slug|тема>` — слаг эпика (карта ляжет в `<docs_path>/<epic_slug>/context_map.md`) или тема встречи словами.
- `[источник]` — опц., путь к Summary или к fast-документу: из него берутся термины поиска. Не задан → термины из темы и из `<epic_slug>-fast.md`, если он есть рядом.

## Примеры

```
/bft-recon direct-faq
/bft-recon direct-faq summaries/2026-07-03-direct-faq.md
/bft-recon "блок вопрос-ответ на карточках"
```

## Важно

**Роль: картограф контекста.** Выход — карта находок со ссылками, а не знание о предметной области. На вопрос «как это работает» карта не отвечает: она отвечает «вот документ про это, посмотри».

**Периметр: только чтение.** JIRA и Confluence открываются на чтение. Никаких записей — ни комментария к задаче, ни создания задачи, ни правки страницы.

**В артефакты БФТ не пишет.** Письмо, `personas.csv`, `requirements.csv`, `<epic_slug>-fast.md`, `<epic_slug>.md` не трогаются. Единственная запись — `context_map.md`.

**Ссылка или молчание.** Находка без ключа задачи или URL не выводится. «Где-то это точно обсуждали» — не находка.

**Запускается сам.** По умолчанию `/bft-fast` форкает разведку в фоне на этапе 8 (`skills/bft-fast/resources/recon_fork.md`, `--no-recon` отключает). Эта команда — ручной путь: повторить обход, обойти другую тему, дособрать контекст перед встречей.

## Инструкция для LLM

Навык — `skills/bft-recon/SKILL.md`. Порядок работы:

### Этап 1: resolve
`bft-config.md`: `tracker_projects`, `wiki_space`, `docs_path` (дефолт `.bft/documentation`). Ни один из двух источников не задан → остановиться: вывести причину, файл не создавать.

### Этап 2: probe
Одним лёгким запросом проверить Atlassian MCP. Недоступен → остановиться с причиной (`MCP недоступен (VPN?)`). Поиск не эмулировать: пустая карта честнее выдуманной.

### Этап 3: terms
Собрать термины: сущности и термины источника (`skills/bft-fast/resources/extraction_schema.md`), ФИО участников, ключ эпика, если назван. Ключ эпика не выдумывать.

### Этап 4: scan
Пять срезов по `skills/bft-recon/resources/search_plan.md`: эпики и задачи по теме, существующие документы, решения и отказы, люди в теме, пересечения. Глубина обхода — 1: найденное по его же ссылкам дальше не разворачивается.

### Этап 5: classify
Разложить по типам (`findings_format.md`): `УЖЕ ОПИСАНО`, `ПЕРЕСЕЧЕНИЕ`, `ЗАВИСИМОСТЬ`, `ПРОТИВОРЕЧИЕ`, `ВЛАДЕЛЕЦ`, `ТЕРМИН`. Не подошло ни под один тип → связь с темой неочевидна, отбросить. Порог 5–15 находок.

### Этап 6: emit + гейт
Записать `<docs_path>/<epic_slug>/context_map.md` по `findings_format.md`, прогнать гейт 20:

```bash
python3 skills/bft-writer/scripts/bft-recon-lint.py <docs_path>/<epic_slug>/context_map.md
```

Ненулевой код — исправить и прогнать снова; карта с ошибками не сохраняется и в чат не выводится. Затем нотификация: топ-5 находок, вопросы с возможным ответом, предлагаемый блок «Документация» (предложение, не правка письма).

### САМОПРОВЕРКА ПЕРЕД ВЫВОДОМ

1. У каждой строки карты есть ключ задачи или URL из ответа MCP? Нет — строку убрать.
2. Колонка «Почему релевантно» говорит про документ, не про предметную область? («эпик про тот же виджет», не «виджет работает так-то»).
3. Есть раздел «Что не найдено», включая пропущенные срезы с причиной?
4. Ни один инструмент записи не вызывался: ни `jira_create_*`, ни `jira_add_comment`, ни `confluence_create_page`, ни `confluence_update_page`?
5. Файлы БФТ не открывались на запись?
6. Гейт 20 вернул 0?
