## Использование
```
/bft-html <путь к <epic_slug>.md>
```

## Что делает

Генерирует read-only HTML-версию БФТ-документа рядом с исходным `.md` (`<epic_slug>.html`, тот же каталог `.bft/documentation/<epic_slug>/`). Не публикуется никуда — локальный файл для ревью PO/стейкхолдерами до `/bft-deliver`.

Страница — документ, не промо-лендинг: чёрно-белая, без декоративной палитры.

- **План демонстрации** — PlantUML-блок раздела конвертируется в реальную Mermaid `sequenceDiagram` (ограниченный actor-level диалект PlantUML, который и так предписан `hard_gates.md` — без message-схем, обязательные `alt`-ветки) и рендерится в браузере через mermaid.js (CDN).
- **Якоря на ID.** Каждый `БТ-N`/`ПТ-N`/`ИТ-N`/`ФТ-N`/`НФТ-N` получает `id` на первом определении (в требований-таблице); все остальные упоминания этого ID в документе (Связанные требования, текст других требований) становятся ссылками на первое определение — быстрая навигация без прокрутки.
- **TOC справа** — строится в браузере из фактических `<h2>` документа, не хардкодится.
- **Обход `[УТОЧНИТЬ]` слева.** Кнопка слева раскрывает панель со списком всех `[УТОЧНИТЬ]`-точек документа (раздел + фрагмент контекста); клик — скролл к месту, подсветка и сразу форма для ответа/комментария. Так PO быстро проходит документ и оставляет только то, что реально требует решения.
- **Комментарии → промт.** Клик по красной точке рядом с `[УТОЧНИТЬ]`, либо выделение любого фрагмента текста — открывает форму комментария на месте. Все комментарии складываются в `localStorage` браузера и в правом верхнем углу собираются в готовый промт («Доработай БФТ-документ `<epic_slug>.md` с учётом следующей обратной связи: 1. [Раздел] (по фрагменту: «…») текст…») с кнопкой «Скопировать промт» — вставить в чат с ИИ для следующего прогона `/bft-fast`/`/bft-deep`. Ctrl/Cmd+Enter в поле комментария сохраняет запись без клика по кнопке.
- **Отметка «отвечено».** Комментарий к конкретной `[УТОЧНИТЬ]`-точке (по точке или из левой панели) помечает её отвеченной — в панели она уходит под разделитель, счётчик слева переключается с «N» на «неотвечено/отвечено». ID точки — хэш от раздела и окружающего текста, не порядковый номер: при перегенерации после правок документа статус «отвечено» остаётся привязан к тому же содержательному пункту, а не съезжает на соседний из-за сдвига нумерации. Комментарии по произвольному выделению текста статус не трогают — они не привязаны к конкретной `[УТОЧНИТЬ]`.
- **Гейты в подвале.** Если рядом со скриптом (или рядом с самим документом — приоритет у копии в проекте-потребителе) лежат `bft-lint.py`/`bft-style-lint.py`, страница прогоняет их на исходнике и показывает реальный результат (не хардкод) — так расхождение версий шаблона видно сразу, а не только при ручном запуске линтера.

## Когда запускать

**Обычно запускать не нужно: страница собирается сама.** `/bft-fast` и `/bft-deep` по умолчанию генерируют её сразу после записи своего документа (`<epic_slug>-fast.html` и `<epic_slug>.html` соответственно, ЗМ-033); отключается флагом `--no-html` у той команды. Эта команда — ручной путь: пересобрать страницу после правки `.md` руками, собрать её при `--no-html` или после падения авто-шага. Точки потока — см. `../skills/bft-writer/SKILL.md` §«Рекомендуемый интерактивный поток». Можно и в любой другой момент доработки — сгенерировать заново с тем же именем, файл перезаписывается. Комментарии PO живут в браузере (per-документ ключ localStorage на основе `epic_slug`), не в файле — синхронизации между перегенерациями нет, это ожидаемо (комментарии превращаются в промт и уходят в чат, а не остаются частью артефакта); статус «отвечено» — исключение, он переживает перегенерацию (см. выше).

## Инструкция для LLM

1. Убедиться, что документ существует и (желательно) прошёл `/bft-validate`.
2. Выполнить: `python3 <skills_path>/bft-writer/scripts/bft-html-export.py <путь к epic.md>`.
3. Сообщить PO путь к сгенерированному `.html` и предложить открыть локально (`open <путь>`), не публиковать как Claude Artifact — документ остаётся файлом рядом с `.md`.
