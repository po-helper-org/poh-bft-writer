# Golden-пример: сценарий How to demo → блок раскадровки

Реальный кусок из БФТ (эпик мониторинга MEV в TON, browser-кейс) плюс
отдельный мобильный кейс — оба прогнаны через
`scripts/wireloom-render.py` и отрендерены без ошибок.

## До (только текст сценария, как его оставил bft-deep)

```markdown
**Сценарий 1 — расчёт без реальных сделок**

Образ результата: по каждой найденной возможности видно расчёт комиссий и чистой прибыли, решение «допустить» или «отказаться» и расхождение с тем, что случилось на рынке по факту.

HowToDemo:
- Запускаю систему в режиме без отправки операций на реальных данных TON.
- Система сама находит токены и торговые пулы.
- По каждой возможности вижу расчёт комиссий, проскальзывания и чистой прибыли.
- Вижу виртуальное решение «допустить» или «отказаться».
- После завершения события на рынке вижу расхождение расчёта с фактом.
```

## После (тот же текст + вставленный блок раскадровки)

Блок встаёт сразу после последнего буллета `HowToDemo:`, перед следующим
`**Сценарий 2 — …**`. Четыре кадра — по одному на первые четыре буллета;
пятый буллет («вижу расхождение...») — это уже сам четвёртый кадр (журнал),
а не отдельный пятый: результат, не новое действие.

Заметки к примеру:

* **Один shell на все четыре кадра** (принцип 3 `SKILL.md`): `navbar` и список
  разделов слева не меняются, различается только `active`-пункт и содержимое
  `col:` справа. Так раскадровка читается как один продукт, а не четыре
  разных экрана.
* **Значения в кадре 3** (25 GRAM, 25.45 GRAM, 0.12 GRAM, 0.33 GRAM, 1.32%) —
  цитата уже одобренного примера из ТЗ этого же документа (раздел «Эталонный
  пример»), не новое число.
* **Решение в футере, не в панели** — `footer` внутри `col`/`panel` даёт
  ошибку разбора (`resources/wireloom_grammar.md` §Ловушки, пункт 1);
  строка решения поднята на уровень `window`.
* **Факт «—» в журнале** — там, где сам ТЗ не даёт числа для сравнения
  расчёта с фактом (система ещё не запускалась), стоит прочерк, а не
  придуманное значение.

## Мобильный кейс (для сравнения, суффикс `:mobile`)

```markdown
**Сценарий N — получаю уведомление о превышении убытка**

Образ результата: вижу push с причиной остановки, открываю карточку и вижу,
какой бот и кошелёк затронуты.

HowToDemo:
- На телефоне приходит уведомление о превышении дневного убытка.
- Открываю уведомление — вижу причину и затронутый кошелёк.
```

````markdown
```wireloom-storyboard:mobile
Приходит уведомление о превышении убытка
---
window:
  header large:
    text "Уведомления"
  list:
    slot "Дневной убыток превышен" chevron:
      text "5 минут назад" muted
  tabbar:
    tabitem "Уведомления" selected
    tabitem "Боты"
    tabitem "Отчёты"
===
Открываю уведомление
---
window:
  navbar:
    leading:
      backbutton "Уведомления"
  panel:
    text "Дневной убыток превышен" bold
    divider
    kv "Бот" "bot-3"
    kv "Кошелёк" "0x...перечислен в документе"
    kv "Действие" "новые сделки остановлены"
```
````
