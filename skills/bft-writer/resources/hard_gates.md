# Hard Gates БФТ + чек-лист самовалидации

## Hard Gates — бинарные 🔴 (автоматический отказ)

Любой сработавший гейт = документ не готов. Исправить до сборки.

**Область применения.** В файле есть строка с токеном `BFT-HEAD-END` (HTML-комментарий-граница; искать по токену, не по полному тексту) — это единый растущий документ (`bft-fast/resources/document_assembly.md`), и гейты прогоняются **только по канону ниже границы**. Шапка (от `## Шапка (сутевое описание запроса)` до границы включительно), строка-статус под H1 и открытое поле / блок «Продолжить / уточнить БФТ» — read-only контекст для гейтов 1–16: их сверяют, не правят и в нарушения не записывают. Строки-границы нет → гейты 1–16 по всему документу, как раньше.

**Исключение — гейт 17.** Структурный линтер проверяет документ целиком, включая шапку: там живут граница, SMART-таблица и карточка проекта, и именно они теряются молча. Read-only означает «ревью и деп не переписывают формулировки», а не «структуру никто не проверяет».

|---|------|-----------|

## Гейт 17 — Template-Conformance (машинная проверка)

Гейты 1–16 читает LLM, и она же их «почти соблюдает»: раздел пропущен, граница потеряна, колонка «Источник» пуста — а отчёт зелёный. Гейт 17 снимает это: структуру проверяет скрипт, вердикт бинарный.

```bash
python3 skills/bft-writer/scripts/bft-lint.py .bft/documentation/<epic_slug>/<epic_slug>.md
```

Код выхода `0` — документ следует шаблону. Ненулевой — 🔴, документ не сохраняется и не публикуется до исправления.

| Префикс | Что проверяет |
|---|---|
| `FM*` | десять ключей frontmatter, их порядок, допустимый `stage` |
| `H1*` | H1 по шаблону, совпадение `epic_slug` с frontmatter, строка-статус под H1 |
| `BD*` | строка-граница `BFT-HEAD-END`: ровно одна на `stage: fast`, отсутствует на `stage: deep` (`BD003`) |
| `HD*` | заголовок шапки, абзац `Цель`, SMART-таблица под ним (S/M/A/R/T, гейт `HD007`), состав и порядок блоков, снятые блоки (вкл. «Критичные требования», ЗМ-018), битые заголовки |
| `CN*` | канон: полнота 11 разделов, порядок, снятые разделы, обязательные подразделы, плейсхолдер и блок продолжения по стадии |
| `DP*` | «План демонстрации»: непустой блок `plantuml` с веткой `alt`, таблица акторов |
| `FT*` | приоритет у каждого ФТ |
| `TB*` | пустые строки-заглушки, HTML-сущности, HTML-разметка списков в ячейках (`TB003`) |
| `ST*` | эмодзи в каноне вне санкционированных зон |

Линтер отвечает за структуру. Смысл — грундинг, высота, различение типов, стиль — остаётся за гейтами 1–16: скрипт не знает, выдумано требование или нет.

## Гейт 18 — Anti-Slop, лексика (машинная проверка)

Гейт 13 (Стиль/Голос) тоже читает LLM — та же слепая зона, что у гейта 17 до его появления: слово-паразит легко пропустить при самоперечитывании. Гейт 18 закрывает лексическую часть гейта 13 скриптом.

```bash
python3 skills/bft-writer/scripts/bft-style-lint.py .bft/documentation/<epic_slug>/<epic_slug>.md
# и так же — по промежуточным артефактам:
python3 skills/bft-writer/scripts/bft-style-lint.py .bft/documentation/<epic_slug>/artefacts/*.md
```

Код выхода `0` — стоп-слов/хеджей/интенсификаторов/мета-комментариев/buzzwords нет. Ненулевой — 🔴, документ правится до исправления.

| Префикс | Что проверяет |
|---|---|
| `SW*` | стоп-слова AI-словаря (`writing_style.md` §1): позволяет/обеспечивает/осуществляет/производит/способствует/представляет собой и т.д. |
| `HG*` | хедж-конструкции (§1a): может потенциально/как правило/в некоторых случаях и т.д. |
| `MC*` | мета-комментарии и signposting (§1a): «в данном разделе рассматривается», «ниже описаны», «начнём с рассмотрения» |
| `QF*` | избыточные квалификаторы и пустые интенсификаторы (§1a): крайне важно/абсолютно необходимо/совершенно уникальный |
| `BZ*` | corporate buzzword англ. кальки (§1a): leverage/utilize/holistic/synergy/game-changer/next-generation/empower |

Линтер отвечает за лексику. Тире-дисциплину (§2), bold-в-ячейках (§4), callout-блоки (§5) и `[УТОЧНИТЬ Ox]`-кросс-рефы (§6) читает LLM — регексом это либо не детектируется однозначно, либо уже ловит гейт 17 (`ST*`).

## Чек-лист самовалидации

### 1. Структура и идентификаторы
- [ ] Frontmatter заполнен — все десять ключей (гейт 17, `FM*`)
- [ ] H1 содержит EPIC-код и название
- [ ] Все обязательные разделы присутствуют (гейт 17, `CN002`)
- [ ] Разделы канона в фиксированном порядке (ЗМ-005/ЗМ-016): Проблема которую решаем → Изменение в UJM → План демонстрации → Бизнес-Требования (Вводные\* + Ценность\*) → Пользовательские\* → Интерфейсы\* → Функциональные\* → Нефункциональные\* → Зависимости → Риски → Якоря (см. `bft_standards.md`). Имена разделов/колонок дословно (ЗМ-006); в каноне нет «Бизнес описание», «Общая информация», «Заинтересованные стороны», «История изменений», «Доп. материалов», «Ревью требований», «Границы», «Критерии успеха», «Ключевые решения»
- [ ] Идентификаторы локальные и единообразны `{TYPE}-{N}` (без EPIC; один шаблон в «Идентификатор» и «Связанные требования») — ЗМ-003
- [ ] Объём задан блоком `Цель` шапки + ДЛЯ КОГО/ЧТО ДЕЛАЕМ в «Проблеме»; высота БФТ соблюдена (приёмка, не системный/API/код). Строки «Скоуп документа —» нет (ЗМ-014); блок `### Ограничения и договоренности` в шапке остаётся на месте — гейт 4
- [ ] Блок `Цель` шапки даёт образ результата конкретно и операционно, не абстрактное «документ описывает…» (ЗМ-013)
- [ ] Под `Цель` — SMART-таблица (S/M/A/R/T, гейт 17 `HD007`); буква без основания в Summary → `[УТОЧНИТЬ]`, не общая заглушка («достижимо силами команды») — `document_assembly.md` §SMART-таблица
- [ ] Документ не противоречит сам себе: `Цель` / «Проблема» / БТ / ФТ / скоуп согласованы (ЗМ-014)

### 2. Трассировка
- [ ] Нет пустых «Связанные требования»
- [ ] Каждая строка ссылается вверх (к БТ) + на эпик в трекере
- [ ] Каскад `БТ ← ПТ ← ИТ` и `БТ ← ФТ ← НФТ` соблюдён

### 3. Качество требований
- [ ] БТ и каждый ФТ имеют приоритет
- [ ] НФТ только измеримые (число / % / RPS / срок)
- [ ] ПТ в формате Когда / Я хочу / Чтобы
- [ ] Каждый ФТ ≈ атомарная задача (1–2 дня), со ссылкой на трекер
- [ ] Типы не смешены (ПТ≠ФТ≠НФТ) — гейт 11

### 4. Якорение (Truth Anchors — `anchor_rules.md`)
- [ ] Каждое ключевое утверждение имеет якорь R1 (код, As-Is) / R2 (трекер/wiki/BR/ADR) / R3 (PO-решение)
- [ ] To-Be не заякорен на код (R1) — гейт 12
- [ ] Решения PO — с «кто + когда + источник»
- [ ] Раздел «Якоря истины» заполнен (Факт | Якорь | Ранг | Тип)
- [ ] Все ссылки Jira/Confluence — markdown-ссылкой, не голым ключом (ЗМ-004, гейт 10)
- [ ] Каждая ссылка Jira/Confluence ведёт на **существующую** страницу; нет битых/выдуманных ссылок и плейсхолдер-URL (несуществующее → `[УТОЧНИТЬ]` без URL) — ЗМ-009

### 5. План демонстрации (акторы + сценарий) и визуализация
- [ ] Раздел «План демонстрации» есть; сценарии на уровне актор → действие → результат, с `alt`-ветками (ошибка / недоступно / отмена)
- [ ] Есть раздел «Изменение в UJM» (таблица Было/Стало)
- [ ] PlantUML — actor-level / black-box, без вызовов между внутренними сервисами и без имён сообщений
- [ ] Есть таблица акторов
- [ ] Нет атрибутивного состава сообщений (это зона СА) — гейт 14
- [ ] Mermaid не используется
- [ ] Надписи на языке документа, технические имена в скобках

### 6. Полнота и неизвестное
- [ ] Подраздел «Вводные для разрабатываемого функционала\*» присутствует (единая таблица открытых вопросов; нет отдельного «Ключевые решения»)
- [ ] Раздела «Ревью требований» в документе НЕТ (снят ЗМ-016)
- [ ] Все пробелы знаний помечены `[УТОЧНИТЬ]` и продублированы строкой в «Вводных»
- [ ] Ни одного выдуманного ключа эпика / статуса / оценки / стейкхолдера / метрики — только из трекера / PO (ЗМ-008)
- [ ] Нет утечки служебных лесов инструмента (внутренние пути пайплайна `artefacts/`/`.bft/index/`, сноски resources, автор «Claude») — ЗМ-007

### 7. Контекст и риски
- [ ] Зависимости между командами вашего проекта со статусом согласования
- [ ] Риски имеют митигацию
- [ ] Персоны шапки заполнены (роль/департамент — из индекса или сказанного, иначе помечены)

### 8. Стиль и голос (`writing_style.md`)
- [ ] В теле документа нет эмодзи (статусные значки только в `validation.md`; маркеры прогресса `⚡ ⏳ ▶ ✅` в строке-статусе, плейсхолдер-заголовке и `<summary>` единого документа — норма, гейт 13)
- [ ] В ячейках таблиц БТ/ИТ/ФТ/НФТ нет `**bold**` (кроме story-ключей в ПТ)
- [ ] Нет callout-блоков `> **⚠️ …`
- [ ] Em-dash — для определений и перечислений, не как связка; не больше одного на предложение
- [ ] Нет стоп-слов («позволяет», «обеспечивает», «осуществляет», «представляет собой», «важно отметить»)
- [ ] Нет хеджей/интенсификаторов/мета-комментариев (`writing_style.md` §1a)
- [ ] Нет HTML-разметки в ячейках таблиц (`<ul>`, `<li>`, `<br>`) — ячейка одна короткая формулировка (ЗМ-021, гейт 17 `TB003`)
- [ ] Открытые вопросы не записаны в документ: нет разделов-накопителей, вопросы ушли в диалог (ЗМ-020, гейт 7)
- [ ] `bft-style-lint.py` вернул 0 (гейт 18) — лексика проверена машинно, не глазами
- [ ] `[УТОЧНИТЬ]` без кросс-рефов `[УТОЧНИТЬ Ox]`; каждый вопрос один раз в «Открытые вопросы»; нет дубля таблиц
- [ ] Frontmatter без diff-narrative; версия правки — ключи `version`/`synced` (раздела истории нет, ЗМ-016)

### 9. Замечания ревью (Known-Mistake — `review_feedback.md`)

- [ ] Ни одно ранее зафиксированное замечание PO не повторено
