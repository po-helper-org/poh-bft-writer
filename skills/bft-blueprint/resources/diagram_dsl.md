# Схемы как код — грамматика блоков `seq` и `idef0` (diagram_dsl.md)

Sequence-схема процесса и IDEF0 задачи пишутся коротким текстом, а не таблицей и не рисунком. LLM пишет только текст. Проверку и рисунок делают статичные функции:

1. **Пишет LLM** — агент на этапе карты или ИИ по промпту из карточки процесса. Результат — блок ```` ```seq П8 ```` или ```` ```idef0 6.3 ````.
2. **Проверяет код** — `scripts/diagram_dsl.py` (линтер карты и `bft-diagram-apply.py`) и его близнец `scripts/diagram_kit.js` (редактор на странице). Правила, коды и сообщения у них одни; совпадение держит самотест.
3. **Рисует код** — `diagram_kit.js`: sequence с линией видимости, IDEF0 A0 и декомпозиция лесенкой. Ошибка в блоке — рисунка нет, есть список «строка · код · что не так».

Так ИИ не тратит токены на разметку и не перерисовывает карту целиком: правка одной схемы — один блок.

## Блок `seq` — как устроен процесс

````
```seq П8
описание: Гость показывает билет, официант сканирует штрихкод. GDS проверяет билет: валиден — скидка, иначе — отказ с причиной.
G -> W: показывает билет
W -> App: сканирует штрихкод
App -> Gd: проверка билета
если билет валиден
  Gd --> App: валиден · билет «использован»
  App -> W: скидка 10%
иначе отменён, возвращён, использован или вне окна
  Gd --> App: отказ с причиной
  App -> W: причина и инструкция
конец
```
````

| Строка | Смысл |
|---|---|
| `описание: …` | суть процесса одной-двумя фразами, до 240 знаков; одна на блок; на странице стоит над схемой |
| `A -> B: что передаётся` | вызов — сплошная стрелка |
| `B --> A: что вернулось` | ответ на вызов `A -> B` — пунктир |
| `A -> A: проверка` | шаг внутри участника |
| `если <условие>` … `иначе <условие>` … `конец` | развилка прямо из БФТ (валиден / отказ); `иначе` без условия — «в остальных случаях»; вложенных веток нет — делите процесс |
| `система Pay: Платёжный шлюз` | участник, которого нет в «Участниках» карты; вид — `человек`, `интерфейс`, `система`, `внешний` |
| `// …` | комментарий |

Участник — ID из раздела «Участники» (латиница до 8 знаков) или объявленный в блоке. Люди и интерфейсы встают слева, системы и внешние — справа от линии видимости; шаг с системой — синий, «скрыт от гостя». До 12 шагов и 6 участников, сообщение до 70 знаков. Неизвестное — `[УТОЧНИТЬ у {кого}]`, на схеме красным.

## Блок `idef0` — задача целиком

````
```idef0 6.3
вход: Штрихкод билета (6.2); Статус билета и дата мероприятия
управление: Активен, не использован, ≤7 дней (ФТ-1); Трёхсторонний контракт Bartello, GDS, Ticketland
выход: «Валиден» и флаг «использован»; Отказ с понятной причиной
механизм: GDS; Сервис валидации билетов

A1 Проверить условия акции
  вход: Штрихкод билета (6.2); Статус билета и дата мероприятия
  управление: Активен, не использован, ≤7 дней (ФТ-1)
  выход: Билет прошёл проверку; Отказ с понятной причиной
  механизм: Сервис валидации билетов
A2 Пометить билет «использован»
  вход: Билет прошёл проверку
  управление: Трёхсторонний контракт Bartello, GDS, Ticketland
  выход: «Валиден» и флаг «использован»
  механизм: GDS
```
````

| Строка | Смысл |
|---|---|
| `функция: …` | название A0; без него — текст задачи |
| `вход:` (`входы:`) | что преобразуется |
| `управление:` (`регуляторы:`) | правила и ограничения — с ID требований |
| `выход:` (`выходы:`) | результат |
| `механизм:` (`механизмы:`) | кто и чем исполняет |
| `A1 Название` | функция декомпозиции; ключи под ней — её стрелки |

Значения — через `;` (внутри `[…]` точка с запятой не делит). Все четыре поля блока обязательны. Декомпозиция — по желанию, от 2 до 6 функций, номера по порядку. Правила стрелок IDEF0 проверяются по подписям, дословно (регистр, «ё» и знаки в конце не важны):

- у каждой функции есть `управление` и `выход`;
- вход и управление функции приходят с границы блока (его вход или управление) или с выхода другой функции;
- каждый выход блока выдаёт какая-то функция;
- выход функции, который никуда не идёт, — предупреждение;
- механизм функции — из механизмов блока, иначе предупреждение.

Стрелку от выхода одной функции ко входу другой страница рисует сама: подпись на обоих концах одна и та же. Обратная связь (выход поздней функции на вход ранней) — пунктир поверх лесенки.

## Коды

| Код | Уровень | Что не так |
|---|---|---|
| DG000 | ошибка | нет блока, блок не закрыт, в заголовке не ID процесса или задачи |
| DG001 | ошибка | seq: строка не разобрана |
| DG002 | ошибка | seq: описание пустое или второе |
| DG003 | ошибка | seq: `иначе` или `конец` без `если`, ветка в ветке, ветка не закрыта, `если` без условия |
| DG004 | ошибка | seq: участник объявлен дважды, без имени или с другим видом, чем в карте |
| DG005 | ошибка | seq: нет сообщения после участников |
| DG006 | ошибка | seq: ветка без шагов |
| DG007 | ошибка | seq: участника нет ни в карте, ни в блоке |
| DG008 | ошибка | seq: ни одного шага |
| DG020–DG026 | предупреждение | больше 12 шагов или 6 участников, длинное сообщение, участник не участвует, ответ без вызова, нет описания, длинное описание |
| DG030 | ошибка | idef0: строка не разобрана |
| DG031 | ошибка | idef0: ключ повторён на одном уровне |
| DG032 | ошибка | idef0: пустое поле блока |
| DG033 | ошибка | idef0: номера функций не по порядку, функций не 2–6, функция без названия |
| DG034 | ошибка | idef0: у функции нет управления или выхода |
| DG035 | ошибка | idef0: вход или управление функции ниоткуда не приходит |
| DG036 | ошибка | idef0: выход блока не выдаёт ни одна функция |
| DG040–DG042 | предупреждение | выход функции никуда не идёт, механизм не из блока, подпись длиннее 60 знаков |

В карте строка кода — строка файла; в редакторе и в `bft-diagram-apply.py` — строка блока.

## Как схема попадает в карту

- **Агент собирает карту** — пишет блоки прямо в разделы «Схемы» и «IDEF0» `-map.md`. Ошибки ловит `bft-map-lint.py`.
- **Поправить одну схему** — агент пишет только блок и вставляет его детерминированно; карту целиком не переписывает:
  ```bash
  python3 <skills_path>/bft-blueprint/scripts/bft-diagram-apply.py <docs_path>/<epic>/<epic>-map.md блок.txt
  python3 <skills_path>/bft-blueprint/scripts/bft-map-render.py <docs_path>/<epic>/<epic>-map.md
  ```
  Скрипт берёт первый блок из текста, так что подходит и ответ ИИ с пояснениями. Он проверяет блок и заменяет блок с тем же ID, а если такого нет — добавляет в конец раздела. Карту пишет, только если в ней не появилось ошибок. С `--check` — только проверка.
- **Техлид на странице** — в карточке процесса «Схема как код». Там текст блока, вкладки Sequence и IDEF0, проверка на лету и предпросмотр. «Применить к карточке» перерисовывает схему: правка хранится в браузере, отметка «правка в браузере». «Собрать схему с ИИ» отдаёт промпт с грамматикой, участниками и контекстом карточки. Ответ ИИ вставляется в поле целиком. «Скопировать блок» — текст для `bft-diagram-apply.py`.
