# Требования к экранам — заметки для дизайнера (screen_notes.md)

Требования к экрану — это файл `screens/<ID>.md` рядом с картой, по одному на экран истории. На странице карты клик по кадру раскадровки открывает панель:
- вверху — название экрана;
- под ним — картинки экрана;
- дальше — вкладки Product, Design, Functions со стеком заметок.

Клик по заметке открывает её целиком, клик по картинке — картинку крупно. Одна заметка — одно требование. Как рисовать, заметка не говорит: только что нужно и зачем.

## Файл

````md
# Сканер — результат проверки

![Скидка 10%](screen:F3)
![Отказ](screen:F4)

## Product

### Понять, давать ли скидку
Когда я отсканировал билет, хочу **сразу понять, давать ли скидку**, чтобы не спорить с гостем.

Источник: ФТ-1, ФТ-8

## Design

### Главное на экране
Скидка 10% или отказ — без двусмысленности.

Источник: ИТ-8

## Functions

### Повторное сканирование
**Дано** билет уже использован
**Когда** официант сканирует штрихкод
**Тогда** отказ с причиной «использован»

Источник: ФТ-1
````

| Строка | Что это |
|---|---|
| `# …` | название экрана — шапка панели |
| `![подпись](screen:F3)` до первой вкладки | картинки экрана: ни одной, одна или несколько. `screen:ID` — экран истории; путь к файлу — настоящий макет, страница встроит его в себя |
| `## Product`, `## Design`, `## Functions` | вкладки, все три, по порядку |
| `### …` | заметка: короткий заголовок, ниже — текст |
| текст заметки | абзацы, списки `- `, `**жирный**`, картинки `![…](…)` |
| `Источник: ФТ-1, ИТ-8` | ID требований БФТ; линтер сверяет их с БФТ |
| `[УТОЧНИТЬ у {кого}]` | неизвестное; в стеке у такой заметки красная точка |

Экраны, показанные картинкой в шапке чужого файла, покрыты им: отказ F4 описан в файле F3.

## Вкладки

- **Product** — зачем экран в истории. Job stories: «Когда …, хочу **…**, чтобы …». Одна история — одна заметка. Источник — ПТ, БТ, ФТ.
- **Design** — что нужно дизайнеру:
  - где экран и в каком моменте пользователь;
  - что главное;
  - куда дальше;
  - ограничения из НФТ: тексты, айдентика, размеры.
  
  Каждый пункт — отдельная заметка.
- **Functions** — сценарии Gherkin: `**Дано**`, `**Когда**`, `**Тогда**`, `**И**`, одна заметка — один сценарий. В них входят и отказы, и «что если» из БФТ. Если поведения нет в БФТ, в `**Тогда**` пишется `[УТОЧНИТЬ у {кого}]`.

Заметка короткая. Заголовок — два–пять слов, текст — одна-две строки. Длинное делится на две заметки.

## Проверка

`bft-map-lint.py` разбирает папку `screens/` рядом с картой (`bft_screens.py`).

| Код | Уровень | Что не так |
|---|---|---|
| SN001 | ошибка | имя файла — не ID экрана истории |
| SN002 | ошибка | нет `# названия` или их два |
| SN003 | ошибка | вкладка не из трёх, не по порядку, нет вкладки, текст вне заметки |
| SN004 | ошибка | заметка без заголовка или текста, повтор заголовка во вкладке |
| SN005 | ошибка | в Functions нет шага `**Тогда**` |
| SN006 | ошибка | картинка: экрана нет в истории или файла нет рядом |
| SN020 | предупреждение | вкладка без заметок |
| SN021 | предупреждение | в Product или Functions нет «Источник:» и нет `[УТОЧНИТЬ]` |
| SN022 | предупреждение | в Product не job story «Когда …, хочу …» |
| SN023 | предупреждение | экран истории без требований |

ID из «Источник:» сверяются с БФТ (`MP016`). Документ с ошибками не рисуется.
