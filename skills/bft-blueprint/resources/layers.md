# Слои blueprint (layers.md)

Один вопрос на слой и один источник в БФТ. Слой выбирается по тому, **кто это видит и кто это делает**, а не по тому, как команда называет систему.

## Слои и источники

| Слой | Вопрос слоя | Источник в БФТ | Статус работы |
|---|---|---|---|
| `выгода` | какой результат клиент получает на этой стадии | БТ; «Чтобы» из ПТ; `TOBE` из «Проблемы» | `—` |
| `действия` | что клиент делает | How to demo, «Что хочу» из ПТ, сценарий «Плана демонстрации» | `—` |
| `контакт` | где это происходит: экран, канал, страница | ИТ (платформа, экран, канал) | `—` или `используем` |
| `витрина` | что клиент видит и может сделать на экране | ИТ, видимая часть ФТ | обязателен |
| `сервис` | что должна делать система или команда | ФТ, «Зависимости», ограничения «Цели» | обязателен |
| `основа` | внешние системы, данные, мониторинг, процессы вокруг | НФТ общего характера, «Зависимости», ограничения | обязателен |

## Правила «в какой слой кладу»

| Признак | Слой |
|---|---|
| клиент это делает руками | `действия` |
| это место или канал, где клиент действует | `контакт` |
| клиент видит это на экране, нажимает, читает | `витрина` |
| система делает это без участия клиента, внутри нашей инициативы | `сервис` |
| это делает чужая система, процесс или команда вне инициативы, либо оно общее для всех сервисов | `основа` |
| выгода сформулирована как результат для клиента, а не как действие | `выгода` |

Спорные случаи:

- **ИТ** даёт две карточки: «где» на слое `контакт` и «что показываем» на слое `витрина`. Если БФТ называет только экран без деталей — достаточно `витрина`.
- **ФТ** без видимого результата — `сервис`. ФТ про видимое поведение — карточка `витрина` и вторая `сервис` с тем, что система для этого делает.
- **НФТ про конкретную операцию** (например, задержка публикации) — на карточке `сервис`, которая её обеспечивает. **НФТ общесистемное** (логирование, доступ, мониторинг) — `основа`.
- **Поисковик, платёжный шлюз, чужая команда** — дорожка `основа`, статус `используем`, если БФТ не просит их менять.
- Не понял, где живёт требование, — карточка в `сервис` со статусом `уточнить` и `[УТОЧНИТЬ у {кого}]` в тексте. Пропуск требования — ошибка `BP012`.

## Дорожки

Слои `сервис` и `основа` режутся на дорожки; остальные слои — одна дорожка на слой.

- Дорожка — **одна система или одна команда**. Берутся из «Зависимостей» БФТ и ФТ. В «Зависимостях» названа команда без системы — дорожка по команде.
- ID дорожки — латиница в нижнем регистре: `direct`, `site`, `search`. Название — по-русски, как в БФТ.
- Колонка «Команда / система» — владелец, как назван в БФТ. Не назван — `[УТОЧНИТЬ у {кого}]`.
- Порядок дорожек в таблице — порядок на диаграмме сверху вниз. Ставь выше те, что ближе к витрине.
- Больше четырёх дорожек слоя — инициатива слишком велика для одного blueprint или дорожки слишком мелкие: объедини по команде.

## Статус работы

Только на слоях `витрина`, `сервис`, `основа`. Опора — ASIS и TOBE БФТ.

| Статус | Когда |
|---|---|
| `создать` | БФТ говорит о новом: «добавляем», «новый раздел», ASIS пуст по существу |
| `доработать` | ASIS существует, БФТ его меняет |
| `используем` | БФТ опирается на уже работающее и не просит менять |
| `уточнить` | из БФТ не ясно; в тексте карточки обязателен `[УТОЧНИТЬ у {кого}]` |

`[ASIS не озвучен]` само по себе статус `создать` не даёт: если БФТ не называет это новым, ставь `уточнить`.
