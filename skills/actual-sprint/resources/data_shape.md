# Форма данных для шаблона

`resources/report_template.html` рендерит таблицу из одного JS-массива `EPICS`. Единица отчёта — **эпик**, не история (PO трекает прогресс на уровне эпика). Заполняй массив целиком (не трогай остальной JS/CSS шаблона):

```js
{
  rowId: "GDSLV-1737",              // уникален на СТРОКУ — обычно = epicKey; "no-epic" для псевдо-эпика
  epicKey: "GDSLV-1737",             // null → строка рендерится как псевдо-эпик "Без эпика"
  epicTitle: "AI Harness (Bartello)",
  stories: [
    {
      key: "GDSLV-1919",
      title: "Harness DevAgent",     // summary истории
      status: "Бэклог",              // status.name истории — текст на бейдже
      category: "К выполнению",      // statusCategory.name истории — для цвета бейджа
      statusChanged: "2026-09-07T10:48:42.000+0300",  // ISO-дата последней смены статуса (из changelog)
      assignee: "Ишманов Алексей Юрьевич",            // displayName исполнителя; null если не назначен
      subtasks: [
        { key: "GDSLV-1881", summary: "[FAQ] Direct: новый таб FAQ на страницах",
          status: "Ревью", category: "В работе", statusChanged: "2026-09-14T16:41:58.368+0300",
          assignee: "Сморкалов Алексей Владимирович" }
      ]
    }
  ]
}
```

## Псевдо-эпик «Без эпика»
Истории без эпик-линка не выбрасывай — собери их в один элемент массива с `epicKey: null`, `epicTitle: "Без эпика"` (или без `epicTitle` — шаблон сам подставит), `rowId: "no-epic"`.

## Группировка — только визуальная
Никакой агрегированной метрики (% выполнено, счётчик "3 из 5") в строке эпика не считать и не выводить — PO попросил именно визуальную группировку, не сводный статус. Агрегация — не задача этого навыка.

## Кнопка «Статус» (одна на эпик) → единая панель из двух колонок
Клик выезжает одна панель с общей шапкой и одной кнопкой закрытия; внутри — две колонки:
1. **«Прогресс»** — заметка привязана к эпику (`rowId` эпика). `localStorage`-ключ: `actual-sprint:{REPORT_ID}:note:{rowId}`.
2. **«Истории»** — список историй эпика: `key — title` + статус-бейдж истории. Если у истории есть подзадачи — стрелка-тоггл разворачивает их список под историей (тот же принцип статус-бейджа, но для `subtasks`). Нет подзадач у истории → стрелка скрыта (`disabled`), просто нет разворота.

Закрытие — крестик в шапке, клик по оверлею или Esc.

## Ловушка вёрстки (не повторять)
Класс ячейки-счётчика (`td.tally`) и класс внутреннего бокса (`.tally-box`) должны отличаться. Одинаковое имя приводило к тому, что правило `display: inline-block` применялось и к `<td>` — ячейка выпадала из табличной раскладки, схлопывалась по ширине и рисовала свою нижнюю границу выше строки (обрывки линий под счётчиками).

## Возраст статуса
`statusChanged` — ISO-строка из changelog (см. `data_collection.md`, шаг 3b). Дни НЕ считать заранее: `statusAge`/`ageHtml` в шаблоне вычисляют их от текущей даты в браузере, поэтому открытый через неделю отчёт покажет актуальные цифры, а не замороженные на момент генерации. Порог «просрочки» — константа `STALE_DAYS` в шаблоне (сейчас 3 дня), всё что дольше красится красным.

## Исполнитель
`assignee` — полное ФИО из `fields.assignee.displayName`, как вернул JIRA. Инициалы («ИА») считает шаблон функцией `whoHtml`, в данных их дублировать не нужно. Задача без исполнителя → `null`, рендерится как «—».

## Статусы и бакеты
В данных храни ТОЛЬКО сырые `status` (status.name) и `category` (statusCategory.name) как их вернул JIRA. Классификацию в 6 бакетов (`Открыто / Заблокировано / В работе / Тестирование / Ревью / Готово`) делает сам шаблон функцией `classifyBucket` при рендере — и для бейджей, и для счётчиков в строке эпика. Правила — `status_mapping.md`. Не считай бакеты заранее и не добавляй их полем в данные: логика должна жить в одном месте.
