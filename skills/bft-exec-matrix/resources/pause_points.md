# Чеклисты точек паузы (pause_points.md)

Чеклист применяется не всё время, а в точках паузы — как хирургический чеклист ВОЗ: перед
разрезом, перед закрытием, перед уходом пациента. Здесь пять пауз.

| Пауза | Когда | Вопрос паузы |
|---|---|---|
| `Старт` | встреча-старт, до работы | все согласились с одной и той же матрицей? |
| `Стыковка` | поставщик отдаёт результат потребителю | потребитель может начать свою часть? |
| `Приёмка` | демо заказчику | всё, что увидит заказчик, принято проверяющими? |
| `Запуск` | решение «выкатываем» | нет открытых возвратов и неснятых рисков? |
| `После запуска` | 1–2 недели после | эффект виден, поддержка приняла? |

## Правила (`MX015`)

- Раздел `### Старт` есть всегда; остальные — для каждой паузы, которая встречается в колонке
  «Пауза» строк.
- В разделе **1–9 пунктов** формата `- [ ] текст` или `- [x] текст`. Больше девяти — внимание
  рассыпается, проверяющие начинают отмечать не читая (killer items, Boorman). Дробится не
  чеклист, а пауза.
- Пункт — то, что можно подтвердить вслух за секунды: «EX-01 и EX-02 в статусе Сдано, доказательства
  приложены», а не «стыковка прошла хорошо».

## Режим команды в чеклисте

Для команд с `READ-DO` пункты по их строкам пишутся шагами, по порядку:

```markdown
- [ ] EX-07 (SEO и аналитика): 1) открыть отчёт индексации в обеих системах 2) найти тестовые
      вопросы пилотной карточки 3) приложить скриншоты к строке
```

Для `DO-CONFIRM` — один пункт-сверка: «EX-02 сдано, Витрина подтвердила на test».

## Стартовый набор `### Старт`

- [ ] У каждой строки один поставщик с именем и проверяющий из другой команды
- [ ] Каждое ФТ, ИТ, НФТ БФТ покрыто строкой
- [ ] Критерии отвечают «да/нет», у каждого есть вид доказательства
- [ ] Каждая команда отметила «Согласовано» на текущей версии
- [ ] Владелец матрицы и дата следующей ревизии названы

Пункт берётся в чеклист, если за ним стоит реальная ошибка. Новые пункты приходят из колонки
«Урок» журнала возвратов (`returns_journal.md`), а не из воображения автора.
