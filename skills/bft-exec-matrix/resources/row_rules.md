# Строка матрицы (row_rules.md)

Одна строка = один проверяемый результат одной команды на стыке с другой. Не задача, не
подзадача: работа внутри команды живёт в её Jira, в матрице — то, что одна команда отдаёт
другой и как вторая убеждается, что получила нужное.

Тест строки: **можно ли через неделю ответить «да» или «нет» на вопрос «сдано ли EX-NN», не
спрашивая автора?** Нельзя — строка не готова.

## Колонки

| Колонка | Правило | Пример | Код |
|---|---|---|---|
| ID | `EX-NN`, сквозной, не переиспользуется после удаления строки | `EX-03` | `MX008` |
| Требование | ID из БФТ (`ФТ-N`, `ИТ-N`, `НФТ-N`), есть в «Покрытии» | `ИТ-1` | `MX008` |
| Поставщик | **одна** команда из «Участников» и **один** человек: `Команда — Имя Фамилия` | `Витрина сайта — Ольга Миронова` | `MX003` |
| Потребитель | команда из «Участников», не равна поставщику | `Продукт` | `MX004` |
| Что | результат, который увидит потребитель, а не работа поставщика | «Блок на страницах события, площадки, персоны» | — |
| Где | `Система · среда`; среда `—`, если её нет (документ, обучение) | `Direct · test` | `MX006` |
| Критерий приёмки | утверждение, на которое ответ «да/нет»; с порогом, где он есть | «на трёх тестовых страницах виден…» | `MX005` |
| Доказательство | что приложит поставщик при сдаче | «Демо на test, запись экрана» | `MX005` |
| Проверяет | `Команда — Имя Фамилия`; команда ≠ команде поставщика | `Продукт — Анна Ковалёва` | `MX004` |
| Пауза | `Старт` · `Стыковка` · `Приёмка` · `Запуск` · `После запуска` | `Стыковка` | `MX009` |
| Срок | `ДД.ММ.ГГГГ` или `спринт N` поставщика | `24.10.2026` | — |
| Статус | см. ниже | `Принято 23.10.2026` | `MX009` |
| Jira | ссылка на задачу поставщика или `—` | `—` | гейт 10 |

## Статусы строки

```
Не начато → В работе → Сдано ДД.ММ.ГГГГ → Принято ДД.ММ.ГГГГ
                              ↘ Возврат  (запись в журнале обязательна, MX010)
Заблокировано: EX-NN | причина
N/A: причина
```

- **Сдано** ставит поставщик, приложив доказательство. **Принято** ставит проверяющий. Пока
  проверяющий не подтвердил — строка не закрыта, сколько бы раз её ни сдавали.
- **Возврат** без записи в «Журнале возвратов» — `MX010`. Возврат и есть «где ошиблись»: ради него
  документ и ведётся.
- **Заблокировано** называет, чем: строкой (`EX-02`) или причиной словами.
- **N/A** только с причиной (`MX009`). Ячейки «Где», «Критерий», «Доказательство» у такой строки
  могут быть `—`.

## Чего в строке быть не может

- **Двух поставщиков** (`MX003`): «Direct, Витрина», «все команды», «совместно», «Direct / Витрина».
  Совместная работа делится на две строки со стыком между ними.
- **Проверяющего из своей команды** (`MX004`): поставщик не принимает сам у себя.
- **Размытого критерия** (`MX005`): «корректно», «правильно», «в полном объёме», «удобно»,
  «качественно», «своевременно», «быстро», «надёжно», «как договорились». Такой критерий каждая
  сторона прочитает по-своему — это и есть причина возвратов.
- **Системного уровня** (`MX011`): эндпоинты, методы HTTP, JSON, поля и таблицы БД, имена топиков.
  Матрица на высоте БФТ (гейт 14): что видит потребитель. Технический контракт живёт у СА, в
  матрицу попадает ссылкой в «Доказательстве» («зелёная проверка контракта на test»).
- **Работы вместо результата**: «написать миграцию», «сделать ревью», «завести задачи». Это строки
  Jira команды. Признак — больше 9 строк одного поставщика на одной паузе (`MX022`, WARN).

## Откуда брать содержимое

| Колонка | Источник |
|---|---|
| Требование, Что, Критерий | ФТ/ИТ/НФТ и «План демонстрации» БФТ — формулировки приёмки уже там |
| Поставщик, Потребитель, Где | «Зависимости» БФТ + вводная PO (итоги встречи-старта, список команд) |
| Проверяет, Срок | вводная PO; нет — `[УТОЧНИТЬ у {кого}]` (только в черновике) |
| Доказательство | вид проверки из критерия: демо, скриншот, выгрузка, отчёт, прогон теста |

Факта нет ни в БФТ, ни во вводной — `[УТОЧНИТЬ у {кого}]`, вопрос — в чат. Выдуманный срок или
выдуманный проверяющий опаснее пустой ячейки: команда начнёт под них планировать.
