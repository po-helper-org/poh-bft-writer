# Участники и зрелость (participants.md)

Раздел — карточка каждой команды инициативы по мотивам Team API (Team Topologies): кто говорит от
команды на стыках, кто ею руководит, в каком ритме она живёт. У команд разные планы и
руководители — без этой карточки непонятно, к кому идти, когда строка застряла.

| Колонка | Правило |
|---|---|
| Команда | имя, которым команда называется в строках матрицы; одно и то же везде |
| Представитель | человек на стыках: сдаёт, принимает, отвечает на вопросы. Один |
| Руководитель | к кому эскалировать, когда представитель не может решить |
| Зрелость | `A`, `B` или `C` |
| Режим | `DO-CONFIRM` или `READ-DO` — следует из зрелости (`MX012`) |
| Ритм | спринт N недель, канбан, по запросу — когда команда может взять строку |
| Согласовано | `—` или `версия N, ДД.ММ.ГГГГ` — какую версию матрицы команда приняла |

## Зрелость → режим чеклиста

| Зрелость | Признак | Режим | Как команда работает с чеклистом |
|---|---|---|---|
| A | сдаёт стыки без возвратов, своя DoD описана | `DO-CONFIRM` | делает по памяти, на паузе сверяется со списком |
| B | возвраты бывают, процесс есть | `DO-CONFIRM` или `READ-DO` | по решению PO |
| C | новая команда, нет своей DoD, частые возвраты | `READ-DO` | идёт по пунктам по порядку, каждый отмечает |

`C` с `DO-CONFIRM` или `A` с `READ-DO` — `MX012`. Одинаковый режим для всех — частая ошибка:
зрелая команда перестаёт читать длинный список, незрелая пропускает шаги короткого.

Зрелость команды PO определяет сам; в источнике её нет — `[УТОЧНИТЬ у PO]` и `B` по умолчанию
не ставится.

## Согласие на старте (`MX013`)

Матрица становится договорённостью, когда **каждая** команда приняла её текущую версию.
Изменили строку стыка после согласования — растёт `version`, и обе стороны стыка согласуют заново.
Колонка «Согласовано» с прошлой версией у команды, чьих строк коснулось изменение, при статусе
`согласована` или `в исполнении` — ошибка.
