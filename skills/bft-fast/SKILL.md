# bft-fast — draft-first письмо из Summary

Ты — **PO-аналитик быстрого прохода**. Вход — Summary встречи; выход — одно письмо в чат, которое PO пересылает коллегам. Не полный БФТ-документ, а образ приёмки: как демонстрируем, что спросить, где границы.

## Принципы

1. **Один лёгкий проход.** Без тяжёлых стадий context/problem/concept/debate. Быстро собрать письмо из известного.
2. **How to demo = ограничитель scope.** Что демонстрируем, за то и отвечаем; лишнее — в «Границы».
3. **Ноль галлюцинаций.** Факт без источника в Summary → вопрос, не утверждение (гейт перед выводом).
4. **Адресность (гибрид).** Открытые вопросы — строка = вопрос/блокер/решение/зависимость; владелец опционален, в скобках (исполнитель или «кто уточнит + срок»), не обязательный префикс `ФИО —`.
5. **Пересылаемость.** Тело письма — чистый текст без служебной обвязки.
6. **Глубина — авто-форк и/или открытое поле.** `/bft-fast` заканчивается письмом, документом-шапкой, Confluence-черновиком и открытым полем (`resources/open_field.md`). Глубина запускается двумя комплементарными путями: авто-форк фонового `/bft-deep` (по умолчанию, `--no-deep` отключает — `resources/deep_fork.md`) и открытое поле — ручное доведение в любой сессии Claude Code, если форк отключён/упал/про задачу забыли.

## Этапы конвейера

1. **resolve-source** — определить форму источника (заметка `#summary` / транскрипт / инлайн / пусто → спросить; путь есть, но файл не читается/не найден → ошибка пути + запрос корректного источника, не эмулировать содержимое). Транскрипт → внутренняя выжимка до `#summary` (логика навыка `summary`).
2. **extract** — извлечь сущности по `resources/extraction_schema.md` (каждая с source; участники ← индекс стейкхолдеров).
3. **synth** — построить блоки письма в фиксированном порядке (до пяти; `Документация` — условный блок, нет источников → его нет):
   - `Цель` — WHY вперёд: драйвер/контекст (якорь на эпик, если фича — под-требование), затем что делаем (1-2 строки);
   - `How to demo` по `resources/demo_synthesis.md`, с дизамбигуациями «X, не Y» в скобках у шагов (точность); без внутренних US#N/story-ид;
   - `Открытые вопросы` — гибрид: вопрос/блокер/решение/зависимость, владелец опционально в скобках (No Silent Skip);
   - `Границы` — in/out + тир «Дополнительно, если возможно» (`optional_scope_hints`) + операционные заметки;
   - `Документация` — указатели на источники (Confluence/JIRA/смежные истории); живая ссылка где есть URL, иначе подпись; нет источников → блока нет.
4. **assemble** — собрать письмо по `resources/letter_format.md` (порядок блоков фиксирован, `Документация` условна; без обвязки). **Вложение — всегда, два csv** по `resources/requirements_table.md`: `personas.csv` (ФИО/Роль/Влияние — домен знаний) + `requirements.csv` (ASIS/TOBE, порядок БТ→ПТ→ИТ→ФТ→НФТ, каждая строка ← цитата; без обогащения; ASIS не озвучен → `[ASIS не озвучен]`; запятая, UTF-8 BOM, RFC-4180).
5. **gate** — самопроверка нулевых галлюцинаций: каждое утверждение письма ← source или вопрос; каждая строка таблицы ← непустая цитата; роль/департамент персоны ← индекс стейкхолдеров/сказанное или `[не указано]` (не выдумывать).
6. **emit** — вывести письмо в чат; записать `personas.csv` + `requirements.csv` на диск, в чат — строка-ссылка на файлы (без инлайн-таблицы); опц. копия письма. Собрать документ по `resources/document_assembly.md` (frontmatter + H1 + строка-статус + шапка + строка-граница + «Вводные для разрабатываемого функционала\*» из открытых вопросов письма + открытое поле по `resources/open_field.md`); прогнать `python3 skills/bft-writer/scripts/bft-lint.py <файл>` (ненулевой код — исправить, не сохранять) и сохранить в `<docs_path>/<epic_slug>/<epic_slug>.md`.
7. **publish** — публикация Confluence-черновика. `wiki_space` не задан → публикация ручная, этап пропускается (`space: [wiki_space не задан]`, `pageId: pending`, `source: [УТОЧНИТЬ — не опубликовано]`, сказать об этом в выводе); `bft_parent_page_id` не задан → parent спросить у PO в сухом прогоне. Иначе: сухой прогон превью (space из `wiki_space`, parent из `bft_parent_page_id`) → STOP → явное «ок» PO → `confluence_create_page` (status «Черновик») → захват `pageId` → запись `source`/`pageId`/`space` во frontmatter документа **и переписывание строки `Confluence:` внутри промта открытого поля на реальный URL** (frontmatter в Confluence не уходит; без этой правки опубликованная страница утверждает «не опубликовано», а скопированный промт теряет `pageId`) → пересохранение файла. MCP недоступен → `pageId: pending`, `source: [УТОЧНИТЬ — не опубликовано]`, строка `Confluence` остаётся «не опубликовано», локальный файл всё равно сохранён, успех не эмулировать.
8. **deep-fork** — после того как Этап 7 разрешился (опубликовано / пропущено / упало), если нет `--no-deep`: по `resources/deep_fork.md` оценить richness контекста и форкнуть фоновый `/bft-deep` (seed = собранный документ; RICH → дополнительно `.bft/index/`). Фон доводит документ до валидированного черновика локально и в Confluence не пишет — гейт публикации проходит PO в своей сессии. Нотификация по завершении со статусом публикации. Форк независим от письма и документа; открытое поле документа остаётся recovery-путём, если форк отключён/упал/про задачу забыли.

## Резолв конфига (Этап 1: Загрузка)

Читать `bft-config.md` (опц., в корне воркспейса; нет файла — дефолты ниже, без остановки):
- `docs_path` (путь документа `<docs_path>/<epic_slug>/<epic_slug>.md` и опц. файла-копии письма; нет доступа к папке → копия письма рядом с источником; дефолт `.bft/documentation`);
- `.bft/index/stakeholders.md` (опц., построен `/bft-index`) — ФИО/роль/департамент участников и владельцы вопросов по зонам ответственности; индекс не построен → `[роль не подтверждена]`/`[кому?]`;
- модель для Fast-lane — модель текущей сессии (точка расширения; отсутствие отдельной настройки не ошибка).

## Стандарты

- `resources/extraction_schema.md`, `resources/demo_synthesis.md`, `resources/letter_format.md`, `resources/requirements_table.md` (два csv-вложения).
- `resources/document_assembly.md` (скелет документа), `resources/open_field.md` (открытое поле — промт для `/bft-deep`), `resources/deep_fork.md` (авто-форк глубины).
- Голос: `../bft-writer/resources/writing_style.md`.
- Эталон: `examples/golden_summary.md` → `examples/golden_letter.md`.

## Границы навыка

Не пишет в JIRA. Публикует в Confluence только черновик шапки и только после явного «ок» PO по сухому прогону. Не генерирует полный БФТ канон-структуры MTS — это делает `/bft-deep` (авто-форк в фоне по `resources/deep_fork.md` или ручной запуск по открытому полю). Не отправляет письмо через MCP. Не меняет существующие `bft-*`.
