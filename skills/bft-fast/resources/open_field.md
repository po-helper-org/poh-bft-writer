# Открытое поле — портативный промт (open_field.md)

## Назначение

Confluence застревает на fast-стадии, и про задачу забывают. Любой PO открывает блок, копирует промт, вставляет в свой Claude Code и доводит БФТ до финала. Промт работает из чистой сессии, без исходного контекста: всё нужное для запуска обогащения несёт сам.

## Приоритет путей (форк или поле, не оба сразу)

Обогащение запускается двумя путями — фоновым авто-форком (`deep_fork.md`) и этим промтом. **Одновременно их запускать нельзя:** оба пишут один и тот же файл `<epic_slug>.md` и оба обновляют одну Confluence-страницу по `pageId` — второй прогон затрёт результат первого, молча. Документ стадии fast (`<epic_slug>-fast.md`) при этом не страдает ни в одном из сценариев: он read-only для deep (`document_assembly.md` §«Путь файла»), и повторный прогон всегда можно начать с него.

Владелец по умолчанию — форк. Ручной путь берётся, когда форк не отработал:

| Ситуация | Признак | Действие |
|---|---|---|
| Форк идёт | В чате строка «Глубокая проработка запущена в фоне», нотификации ещё нет | Дождаться нотификации, промт не запускать |
| Форк отключён | Запуск был с `--no-deep` | Ручной путь — штатный |
| Форк упал | Нотификация о провале | Ручной путь — штатный |
| Про задачу забыли | Сессия закрыта, нотификации не видел никто | Ручной путь — штатный (основной кейс поля) |

Состояние документа — источник правды: `stage: deep` во frontmatter или раздел «Проблема которую решаем» ниже строки-границы означает, что канон уже собран. Тогда прогон — доработка (закрыть `[УТОЧНИТЬ]`, уточнить разделы), а не пересборка с нуля.

## Форма

Блок — единственный элемент документа ниже строки-границы `BFT-HEAD-END` на стадии fast (место в документе: `document_assembly.md` §«Область канона»). Состоит из четырёх частей по порядку: заголовок, строка-пояснение, сворачиваемый `<details>` и внутри него fenced-блок с промтом.

Скелет:

````markdown
## ⏳ Полный БФТ — в проработке

Собрана только шапка (bft-fast). Полный БФТ по корпоративному шаблону MTS ещё не построен.

<details>
<summary>▶ Довести до полного БФТ — промт для Claude Code (скопируй в свою сессию)</summary>

```text
<промт — см. «Шаблон промта»>
```

</details>
````

Заголовок и текст `<summary>` — точная строка поиска для `bft-deep-swarm` при обогащении: полный текст обоих есть в скелете выше. Переформулировать нельзя: документ обогащения не найдёт точку вставки канона.

## Шаблон промта

Промт — дословно тело фикстуры `../examples/golden_document.md` (эталон `epic_slug: direct-faq`). Параметризованы две части: четыре строки блока «КОНТЕКСТ ЭТОГО БФТ» (`epic_slug`, «Источник Summary», «Confluence», `pin_commit`) и путь линтера в шаге «ПЕРЕД СОХРАНЕНИЕМ» (`<skills_path>`) — заменены на `<…>`-подстановки. Остальной текст промта неизменен.

```text
Ты — обогатитель БФТ (роль bft-deep-swarm, «Обогатитель»). Перед тобой документ БФТ,
у которого собрана только ШАПКА (Цель + SMART-таблица, How to demo, Ограничения и
договоренности, Критичные требования на цитатах, Общая информация); те же строки
скелета лежат рядом в `personas.csv`/`requirements.csv`. Доведи документ до ПОЛНОГО
БФТ, НЕ ПЕРЕПИСЫВАЯ и НЕ ЗАТИРАЯ шапку.

ПЕРЕД СТАРТОМ — проверь состояние документа:
- Ниже строки-границы уже есть раздел «Проблема которую решаем» (или во frontmatter
  `stage: deep`)? Значит канон собран: это доработка (закрыть [УТОЧНИТЬ], уточнить
  разделы), а не пересборка.
- Обогащение мог запустить фоновый форк `/bft-fast`. Два прогона затирают друг друга —
  оба пишут один файл <epic_slug>.md и обновляют одну Confluence-страницу. Если форк ещё
  идёт (нотификации о завершении не было) — дождись её, не запускай параллельно.
- Рядом может лежать context_map.md — карта находок JIRA/Confluence от /bft-recon. Это
  УКАЗАТЕЛЬ, куда смотреть, а не фактбаза: каждый пункт открывай по ссылке и якори сам.
  Факт в каноне со ссылкой только на карту и без своего якоря — дефект. Карты нет — работай
  как обычно, это не блокер.
- Результат пиши в ОТДЕЛЬНЫЙ файл <epic_slug>.md рядом. Файл <epic_slug>-fast.md, который
  ты читаешь как исходник, НЕ перезаписывай ни при каких условиях — это выверенная работа
  стадии fast, с которой прогон можно повторить.

ЧТО СДЕЛАТЬ:
1. Шапку выше сохрани дословно. Вместо блока «⏳ Полный БФТ — в проработке» построй ниже
   канон из 11 разделов, ровно в этом порядке и без лишних:
   Проблема которую решаем → Изменение в UJM → План демонстрации (акторы + PlantUML) →
   Бизнес-Требования (Ценность/БТ) → Пользовательские (ПТ) →
   Интерфейсы (ИТ) + Макеты → Функциональные (ФТ) → Нефункциональные (НФТ) →
   Зависимости → Риски → Якоря истины.
   НЕ создавай разделы «Бизнес описание», «Общая информация», «Заинтересованные стороны»,
   «История изменений», «Дополнительные материалы», «Ревью требований», «Границы»,
   «Критерии успеха», «Ключевые решения», «Вводные для разрабатываемого функционала» —
   их в документе нет по решению PO. Открытые вопросы в документ не пишутся: они идут
   ответом в чат, а в ячейке требования остаётся [УТОЧНИТЬ].
   Строку-границу BFT-HEAD-END в финальном документе сними — она нужна была только
   стадии fast как якорь. Блок шапки «Критичные требования (скелет на цитатах)» тоже
   сними: он держал границы документа, пока канона не было, а теперь те же ID живут
   в типизированных разделах. Остальную шапку не трогай.
2. Обогати по 3 осям: ценность (зачем инвестировать), «что если» (стресс How-to-demo),
   явные границы (что не входит).
3. Скелет — «Критичные требования» шапки и те же строки в `requirements.csv`/`personas.csv`
   рядом с документом: ID оттуда сохраняй (БТ-1 в скелете = БТ-1 в каноне), строки разверни
   в типизированные таблицы канона. Новые ID добавляй только в канон, скелет не
   перенумеровывай.
4. Zero-hallucination: факт без источника → [УТОЧНИТЬ у {кого}], не выдумывай. Высота БФТ:
   без API-контрактов, схем БД, кода — только результат и приёмка.
5. Сценарий приёмки — непустой блок ```plantuml с веткой alt. Пустой блок или ```plaintext
   недопустимы. HTML-разметку в ячейках таблиц не использовать вовсе (<ul>, <li>, <br>):
   ячейка — одна короткая формулировка, не вёрстка. Строк-заглушек с пустыми ячейками
   в таблицах не оставляй.
6. Открытые вопросы в документ не переноси — их место в ответе в чат. В документе
   неизвестное остаётся как [УТОЧНИТЬ] в ячейке требования.

ПЕРЕД СОХРАНЕНИЕМ — проверь структуру машинно:
    python3 <skills_path>/bft-writer/scripts/bft-lint.py <путь-к-этому-документу>
Ненулевой код выхода = документ не по шаблону. Исправь и прогони снова; с ошибками
линтера файл не сохраняется и не публикуется. Нет poh-bft-writer под рукой — сверь
вручную: строки BFT-HEAD-END в финальном документе нет, все 11 разделов канона в
порядке выше, у каждой строки requirements.csv непустой «Источник (цитата)».


КОНТЕКСТ ЭТОГО БФТ:
- epic_slug: <epic_slug>
- Источник Summary: <путь или URL источника>
- Confluence: <URL страницы | не опубликовано>
- pin_commit (репо poh-bft-writer): <hash | [УТОЧНИТЬ]>
- Индекс воркспейса: .bft/index/ (если пуст или устарел — сначала /bft-index)
- Открытые вопросы: выводи списком в чат, в документ не переноси.

КАК ЗАПУСТИТЬ:
- Если установлен poh-bft-writer: /bft-deep <путь-к-этому-документу>
- Иначе: скопируй ВЕСЬ этот документ в Claude Code и выполни инструкцию выше.
```

## Поля контекста

Подстановки блока «КОНТЕКСТ ЭТОГО БФТ»:

| Поле | Источник | Фолбэк |
|---|---|---|
| `epic_slug` | аргумент запуска `/bft-fast` или slug темы | обязательный параметр пайплайна, пустым не бывает |
| `Источник Summary` | путь или URL входа этого прогона | источник не сохранён / инлайн-вставка → `[УТОЧНИТЬ]` |
| `Confluence` | URL опубликованной страницы | на стадии fast — всегда `не опубликовано`: fast в Confluence не пишет. Страницу создаёт `/bft-deliver` после глубокой проработки — **он и переписывает эту строку внутри промта реальным URL, пересохраняя файл.** Frontmatter в Confluence не публикуется, так что без перезаписи опубликованная страница несёт промт, утверждающий, что документ не опубликован, а скопировавший его PO теряет `pageId` |
| `pin_commit` | hash репозитория `poh-bft-writer` на прогоне | недоступен → `[УТОЧНИТЬ]` |
| `Индекс воркспейса` | фиксированный путь `.bft/index/` | константа, не значение прогона |
| `Открытые вопросы` | напоминание выводить вопросы в чат, а не в документ (ЗМ-020) | константа, не значение прогона |

Отдельно — путь линтера в шаге «ПЕРЕД СОХРАНЕНИЕМ»: `<skills_path>` заменяется **реальной папкой установки** этого прогона (`.claude/skills`, `.agents/skills`, `.clinerules/skills` или `skills` при запуске из клона). Промт копируют в чистую сессию и выполняют оттуда — неразрешённый токен в нём означает, что PO получит команду, которая не запустится. Раскладку не определить → оставить `<skills_path>` и добавить строку «путь установки не определён» рядом: честный пробел лучше выдуманного пути. Литерал `<путь-к-этому-документу>` в той же строке, наоборот, остаётся как есть — его подставляет уже читатель промта.

## Правило грундинга

В промт попадают только реальные значения текущего прогона. Несуществующий путь, URL или hash не выдумывается — вместо него честный фолбэк из таблицы выше (`[УТОЧНИТЬ]`, «не опубликовано» и т.д.). Правило то же, что и во всём документе (zero-hallucination, Global Constraints), применённое к контексту промта.

## Обёртки Confluence

При публикации (`/bft-deliver` §«Конвертация ссылок в макросы») `<details>` оборачивается макросом **Expand** (storage: `<ac:structured-macro ac:name="expand">`), fenced-блок с промтом — макросом **Code** (`<ac:structured-macro ac:name="code">`). Так промт копируется как есть, без потери переносов строк.

## Судьба после deep

После `/bft-deep` заголовок `## ⏳ Полный БФТ — в проработке` снимается: на его месте встаёт канон MTS. Открытое поле не исчезает целиком: в конце документа остаётся компактный блок «продолжить/уточнить» — тот же промт (см. «Шаблон промта»), с пометкой, что канон уже собран, и заголовком без снятого `⏳`-плейсхолдера.

Дефолт — снять плейсхолдер, оставить слим-промт. Дословный текст слим-промта — фикстура `../../bft-deep-swarm/examples/golden_deep_document.md` §«Продолжить / уточнить БФТ»; она же эталон целого обогащённого документа. Слим-промт обязан нести перечень одиннадцати разделов канона и шаг `python3 <skills_path>/bft-writer/scripts/bft-lint.py` перед сохранением: PO копирует его в чистую сессию, где никаких других инструкций нет.
