# Открытое поле — портативный промт (open_field.md)

## Назначение

Confluence застревает на fast-стадии, и про задачу забывают. Любой PO открывает блок, копирует промт, вставляет в свой Claude Code и доводит БФТ до финала. Промт работает из чистой сессии, без исходного контекста: всё нужное для запуска обогащения несёт сам.

## Приоритет путей (форк или поле, не оба сразу)

Обогащение запускается двумя путями — фоновым авто-форком (`deep_fork.md`) и этим промтом. **Одновременно их запускать нельзя:** оба пишут канон под одну и ту же шапку и оба обновляют одну Confluence-страницу по `pageId` — второй прогон затрёт результат первого, молча.

Владелец по умолчанию — форк. Ручной путь берётся, когда форк не отработал:

| Ситуация | Признак | Действие |
|---|---|---|
| Форк идёт | В чате строка «Глубокая проработка запущена в фоне», нотификации ещё нет | Дождаться нотификации, промт не запускать |
| Форк отключён | Запуск был с `--no-deep` | Ручной путь — штатный |
| Форк упал | Нотификация о провале | Ручной путь — штатный |
| Про задачу забыли | Сессия закрыта, нотификации не видел никто | Ручной путь — штатный (основной кейс поля) |

Состояние документа — источник правды: `stage: deep` во frontmatter или раздел «Бизнес описание» ниже строки-границы означает, что канон уже собран. Тогда прогон — доработка (закрыть `[УТОЧНИТЬ]`, уточнить разделы), а не пересборка с нуля.

## Форма

Блок — последний элемент шапки, сразу после строки-границы `BFT-HEAD-END` (место в документе: `document_assembly.md` §«Область канона»). Состоит из четырёх частей по порядку: заголовок, строка-пояснение, сворачиваемый `<details>` и внутри него fenced-блок с промтом.

Скелет:

````markdown
## ⏳ Полный БФТ — в проработке

Собрана только шапка (bft-fast). Полный БФТ по корпоративному шаблону MTS ещё не построен.

<details>
<summary>▶ Довести до полного БФТ — промт для Claude Code (скопируй в свою сессию)</summary>

```text
<промт — см. «Шаблон промта»>
```

</details>
````

Заголовок и текст `<summary>` — точная строка поиска для `bft-deep-swarm` при обогащении: полный текст обоих есть в скелете выше. Переформулировать нельзя: документ обогащения не найдёт точку вставки канона.

## Шаблон промта

Промт — дословно тело фикстуры `../examples/golden_document.md` (эталон `epic_slug: direct-faq`). Параметризована только одна часть: четыре строки блока «КОНТЕКСТ ЭТОГО БФТ» (`epic_slug`, «Источник Summary», «Confluence», `pin_commit`) заменены на `<…>`-подстановки. Остальной текст промта неизменен.

```text
Ты — обогатитель БФТ (роль bft-deep-swarm, «Обогатитель»). Перед тобой документ БФТ,
у которого собрана только ШАПКА (Цель, How to demo, Открытые вопросы, Границы, критичные
требования на цитатах). Доведи его до ПОЛНОГО БФТ по корпоративному шаблону MTS,
НЕ ПЕРЕПИСЫВАЯ и НЕ ЗАТИРАЯ шапку.

ПЕРЕД СТАРТОМ — проверь состояние документа:
- Ниже строки-границы уже есть раздел «Бизнес описание» (или во frontmatter `stage: deep`)?
  Значит канон собран: это доработка (закрыть [УТОЧНИТЬ], уточнить разделы), а не пересборка.
- Обогащение мог запустить фоновый форк `/bft-fast`. Два прогона на одном документе
  затирают друг друга — оба пишут канон под шапку и обновляют одну Confluence-страницу.
  Если форк ещё идёт (нотификации о завершении не было) — дождись её, не запускай параллельно.

ЧТО СДЕЛАТЬ:
1. Шапку выше сохрани дословно. Вместо блока «⏳ Полный БФТ — в проработке» построй ниже
   полный канон MTS: Бизнес описание → Общая информация → Заинтересованные стороны →
   История изменений → Дополнительные материалы → Проблема которую решаем → Изменение в UJM →
   План демонстрации (акторы + PlantUML) → Бизнес-Требования (Вводные/вопросы + Ценность/БТ) →
   Пользовательские (ПТ) → Интерфейсы (ИТ) + Макеты → Функциональные (ФТ) →
   Нефункциональные (НФТ) → Зависимости → Риски → Ревью требований → Якоря истины.
2. Обогати по 3 осям: ценность (зачем инвестировать), «что если» (стресс How-to-demo),
   явные границы (что не входит).
3. ID из шапки сохраняй (БТ-1 в шапке = БТ-1 в каноне); критичную таблицу разверни в
   типизированные таблицы канона. Новые ID добавляй только в канон, шапку не перенумеровывай.
4. Zero-hallucination: факт без источника → [УТОЧНИТЬ у {кого}], не выдумывай. Высота БФТ:
   без API-контрактов, схем БД, кода — только результат и приёмка.

КОНТЕКСТ ЭТОГО БФТ:
- epic_slug: <epic_slug>
- Источник Summary: <путь или URL источника>
- Confluence: <URL страницы | не опубликовано>
- pin_commit (репо poh-bft-writer): <hash | [УТОЧНИТЬ]>
- Индекс воркспейса: .bft/index/ (если пуст или устарел — сначала /bft-index)
- Открытые вопросы: см. раздел «Открытые вопросы» в шапке выше.

КАК ЗАПУСТИТЬ:
- Если установлен poh-bft-writer: /bft-deep <путь-к-этому-документу>
- Иначе: скопируй ВЕСЬ этот документ в Claude Code и выполни инструкцию выше.
```

## Поля контекста

Подстановки блока «КОНТЕКСТ ЭТОГО БФТ»:

| Поле | Источник | Фолбэк |
|---|---|---|
| `epic_slug` | аргумент запуска `/bft-fast` или slug темы | обязательный параметр пайплайна, пустым не бывает |
| `Источник Summary` | путь или URL входа этого прогона | источник не сохранён / инлайн-вставка → `[УТОЧНИТЬ]` |
| `Confluence` | URL опубликованной страницы | страницы нет → `не опубликовано` |
| `pin_commit` | hash репозитория `poh-bft-writer` на прогоне | недоступен → `[УТОЧНИТЬ]` |
| `Индекс воркспейса` | фиксированный путь `.bft/index/` | константа, не значение прогона |
| `Открытые вопросы` | ссылка на раздел «Открытые вопросы» в шапке (не копия) | константа, не значение прогона |

## Правило грундинга

В промт попадают только реальные значения текущего прогона. Несуществующий путь, URL или hash не выдумывается — вместо него честный фолбэк из таблицы выше (`[УТОЧНИТЬ]`, «не опубликовано» и т.д.). Правило то же, что и во всём документе (zero-hallucination, Global Constraints), применённое к контексту промта.

## Обёртки Confluence

При публикации (`/bft-deliver`, `../../../commands/bft-deliver.md` §«Конвертация ссылок в макросы») `<details>` оборачивается макросом **Expand** (storage: `<ac:structured-macro ac:name="expand">`), fenced-блок с промтом — макросом **Code** (`<ac:structured-macro ac:name="code">`). Так промт копируется как есть, без потери переносов строк.

## Судьба после deep

После `/bft-deep` заголовок `## ⏳ Полный БФТ — в проработке` снимается: на его месте встаёт канон MTS. Открытое поле не исчезает целиком: в конце документа остаётся компактный блок «продолжить/уточнить» — тот же промт (см. «Шаблон промта»), с пометкой, что канон уже собран, и заголовком без снятого `⏳`-плейсхолдера.

Дефолт — снять плейсхолдер, оставить слим-промт (`../../../docs/superpowers/specs/2026-07-22-bft-unified-document-design.md` §15). Конкретную фикстуру этого состояния строит `bft-deep-swarm` (`../../bft-deep-swarm/examples/`, Task 4) — эта спека фиксирует только правило.
