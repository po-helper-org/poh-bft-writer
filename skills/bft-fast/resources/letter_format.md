# Формат письма (letter_format.md)

Результат `/bft-fast` — одно письмо в чат, копируемое в мессенджер как есть. Четыре блока строго в порядке ниже.

## Шаблон

```
Цель: <кто> хочет <что>, чтобы <зачем>. Для этого нужно <ключевой enabler, если есть>.

How to demo:
1. … (нумерованный E2E — см. demo_synthesis.md; дизамбигуации «X, не Y» в скобках у шага)
2. …

Открытые вопросы:
* <ФИО владельца> — <вопрос-развилка кратко>
* <ФИО владельца> — <вопрос кратко>
* [кому?] — <вопрос без явного владельца>

Границы: <in-scope сущности> (<out-of-scope> — не входят в зону БФТ).
Дополнительно, если возможно: <optional-scope пункты>.
<операционная заметка: сроки/эффекты>
```

## Правила сборки

- **Порядок блоков фиксирован:** `Цель` → `How to demo` → `Открытые вопросы` → `Границы`.
- **«Цель»** — 1-2 строки: кто (`для_кого`) хочет что (`что_делаем`/`проблема`), чтобы зачем, и ключевой enabler если он есть в Summary («для этого нужен отдельный поток из Kafka»). Даёт мгновенный intent до демо. Всё из Summary; нет данных о «зачем»/enabler — не выдумывать, оставить короче.
- **В теле письма нет frontmatter, меток пайплайна, идентификаторов `СТ-*`/`ФТ-*`.** Только человекочитаемый текст, копируемый в мессенджер как есть.
- **Точность.** Дизамбигуации из Summary (`дизамбигуации[]`) встраиваются в скобках прямо в свой демо-шаг или строку границ: «(оплачен, не создан)», «(как передают распы по АИС)». Не выносить отдельным пунктом, не выдумывать при отсутствии.
- **Вопросы — плоский сжатый список**, по строке на вопрос: `* <ФИО владельца> — <вопрос кратко>`. Без группировки по ФИО, без чекбоксов; владелец — префикс строки (можно повторять для нескольких вопросов одного человека). Вопрос формулируется кратко — одна развилка на строку. Неатрибутированный вопрос → `* [кому?] — <вопрос>`.
  - **Не делать:** заголовки-группы `ФИО:` со списком под ними; чекбоксы `- [ ]`.
  - **Вопрос — только о том, что реально всплыло на встрече.** Не изобретать технические развилки (алгоритмы ранжирования BM25/TF-IDF, фильтры по типу кухни и т.п.), если участник их не поднимал. Выдуманный вопрос — та же галлюцинация, что и выдуманный факт.
- **«Границы»:** одна строка in-scope сущностей + явное «не входят в зону БФТ» для out-of-scope; строка «Дополнительно, если возможно:» — из `optional_scope_hints` (nice-to-have, отделён от must-have); операционные заметки (сроки, эффекты, интеграции) — отдельными строками. Пусто по out-of-scope / optional / заметкам — соответствующую строку не выдумывать, без пустых скобок.
- **Голос** — по `../../bft-writer/resources/writing_style.md`: деловой русский, без эмодзи, без раздутого bold, без тире-связок, без стоп-слов, без AI-примет. Регистр совпадает с золотыми референсами.

## Гейт перед выводом (hallucination gate — СТ-23)

Пройти по каждому утверждению письма:
- Есть источник в Summary (факт, договорённость, затронутая сущность) → оставить.
- Нет источника → переоформить в вопрос (`* [кому?] — <переформулированное как вопрос>`).

**Правило:** ни одного факта-выдумки. Если что-то уверенно звучит, но нет цитаты в Summary — это не опускается молча, а становится вопросом.

## Канал вывода

- **Основной канал:** текст письма в чат PO (копируется как есть, без служебных маркеров).
- **Опциональная копия:** файл `.bft/documentation/{epic_slug}/letter.md` (`docs_path` из `bft-config.md`, дефолт `.bft/documentation`; создать папку при отсутствии). Нет доступа к папке → файл рядом с источником с пометкой `[УТОЧНИТЬ путь копии]`.
- **После письма:** короткая строка PO: «Ответы получены — запусти глубокую проработку отдельно». Сам deep-запуск команда не делает.
