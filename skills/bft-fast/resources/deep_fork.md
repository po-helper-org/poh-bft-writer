# deep_fork — context-probe + адаптивный форк Deep + нотификация

## Флаг
`--no-deep` → пропустить форк целиком (письмо + документ отданы, открытое поле документа остаётся для ручного доведения `/bft-deep`).

## Context-probe (после emit письма и документа)
Оценить richness контекста:
- JIRA-эпик указан/найден? Есть покрытие в индексе `.bft/index/` по теме? прежние artefacts эпика в `.bft/documentation/`? насыщенность Summary (>8 фактов)?
- **RICH** (есть на что опереться) → форкать Deep СРАЗУ, параллельно (письмо уже отдано; Deep грудится на индексе воркспейса `.bft/index/` — построен `/bft-index`, не ждёт seed).
- **THIN** (опереться не на что) → Deep уже имеет seed = только что отданное письмо; форкать Deep следом (Fast построил скелет).
(В обоих случаях письмо A уже в чате; разница — на чём Deep грудится: индекс `.bft/index/` vs письмо-seed.)

## Запуск фона
Agent tool, `run_in_background`: субагент выполняет `/bft-deep <документ> <epic_slug>` — seed = собранный на Этапе 6 документ `<docs_path>/<epic_slug>/<epic_slug>.md` (bft-deep читает документ, сохраняет шапку, дописывает канон ниже; в RICH дополнительно `.bft/index/`). Pin commit hash.

## Открытое поле как recovery
Форк — оптимизация «сделать сразу». Открытое поле документа (`open_field.md`) — комплементарный ручной путь: если форк отключён (`--no-deep`), упал, или про задачу забыли, любой PO копирует промт из поля и доводит БФТ в своей сессии.

**Пути комплементарны, но не параллельны.** Форк — владелец обогащения по умолчанию; пока он идёт, ручной путь не запускать: оба прогона пишут канон под одну шапку и обновляют одну Confluence-страницу по `pageId`, второй молча затрёт первого. Сигнал завершения — нотификация ниже; до неё документ считается занятым форком. Полная таблица «когда какой путь» — `open_field.md` §«Приоритет путей».

## Нотификация (по завершении фона)
- Успех: `deep БФТ готов: <path> · N [УТОЧНИТЬ]-точек · валидация 🟢/🟡`.
- Провал: `deep БФТ УПАЛ на <стадии>: <ошибка>; шапка документа и открытое поле не затронуты`. Никогда молча.
