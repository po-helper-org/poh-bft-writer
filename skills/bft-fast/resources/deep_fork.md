# deep_fork — context-probe + адаптивный форк Deep + нотификация

## Флаг
`--no-deep` → пропустить форк целиком (только письмо).

## Context-probe (после emit письма)
Оценить richness контекста:
- JIRA-эпик указан/найден? Есть покрытие в индексе `.bft/index/` по теме? прежние artefacts эпика в `.bft/documentation/`? насыщенность Summary (>8 фактов)?
- **RICH** (есть на что опереться) → форкать Deep СРАЗУ, параллельно (письмо уже отдано; Deep грудится на индексе воркспейса `.bft/index/` — построен `/bft-index`, не ждёт seed).
- **THIN** (опереться не на что) → Deep уже имеет seed = только что отданное письмо; форкать Deep следом (Fast построил скелет).
(В обоих случаях письмо A уже в чате; разница — на чём Deep грудится: индекс `.bft/index/` vs письмо-seed.)

## Запуск фона
Agent tool, `run_in_background`: субагент выполняет `/bft-deep <seed> <epic_slug>` (seed = письмо; в RICH дополнительно `.bft/index/`). Pin commit hash.

## Нотификация (по завершении фона)
- Успех: `deep БФТ готов: <path> · N [УТОЧНИТЬ]-точек · валидация 🟢/🟡`.
- Провал: `deep БФТ УПАЛ на <стадии>: <ошибка>; письмо не затронуто`. Никогда молча.
