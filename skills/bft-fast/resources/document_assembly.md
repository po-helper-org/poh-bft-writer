# Скелет документа БФТ (document_assembly.md)

## Назначение

Единственный источник правды о скелете единого документа БФТ: frontmatter-ключи, порядок блоков шапки, строка-граница, замороженная область, путь файла. Документ растёт в два такта — `bft-fast` собирает шапку и сохраняет файл, `bft-deep-swarm` дописывает канон MTS ниже границы, не трогая шапку. Оба навыка читают этот файл как контракт; эталон шапки — `../examples/golden_document.md`. Правила содержимого блоков этот файл не задаёт — только форму и порядок.

## Frontmatter

Десять ключей, в этом порядке:

| Ключ | Правило |
|---|---|
| `source` | URL опубликованной страницы Confluence; не опубликовано → `[УТОЧНИТЬ — не опубликовано]` |
| `space` | ключ пространства из `wiki_space` (`bft-config.md`); не задан → `[wiki_space не задан]` |
| `pageId` | id страницы Confluence после публикации; страницы ещё нет → `pending` |
| `version` | `0.1` на fast; на deep — инкремент (`0.2`, …) |
| `synced` | дата последней синхронизации, `YYYY-MM-DD` |
| `jira` | ключ эпика в трекере; эпика нет → `[СОЗДАТЬ эпик]` |
| `status` | короткий текстовый статус стадии |
| `epic_slug` | слаг эпика; неизменен на весь путь fast → deep |
| `stage` | `fast` \| `deep` |
| `pin_commit` | hash репозитория `poh-bft-writer` на прогоне; недоступен → `[УТОЧНИТЬ]`. В golden-фикстуре показан стенд-ин `[hash прогона]` — реальный hash в фикстуру не вписывается |

## H1

```
# [БФТ] <epic_slug>: <Название>
```

## Строка-статус

Блок-цитата сразу под H1, обновляемая на каждой стадии:

- **fast:** `> Статус проработки: ⚡ Шапка (bft-fast). Полный БФТ по шаблону MTS ещё не собран — см. блок «Полный БФТ — в проработке» внизу.`
- **deep:** заменяется на статус полного БФТ; конкретный текст задаёт `bft-deep-swarm`.

## Шапка

Заголовок и порядок подблоков фиксированы:

```
## Шапка (сутевое описание запроса)

Цель: <1-2 строки>.

### How to demo
### Открытые вопросы
### Границы
### Документация          ← только если у письма есть этот блок
### Критичные требования (скелет на цитатах)
```

`Цель` — бесзаголовочный абзац сразу под «## Шапка», не отдельный `###`-блок. `Документация` — условный блок: письмо его опускает, когда источников нет (`letter_format.md`); тогда его нет и в шапке, пустой заголовок не ставится. Содержимое и правила сборки каждого блока этот файл не задаёт:

- `Цель`, `How to demo`, `Открытые вопросы`, `Границы`, `Документация` — по `letter_format.md` (пять блоков письма, порядок тот же).
- Персоны и таблица требований в «Критичные требования» — по `requirements_table.md`. В шапке они markdown-таблицами; те же строки уходят в машиночитаемое вложение `personas.csv` / `requirements.csv`.

## Строка-граница

Байт-точная константа, ровно одна на документ, сразу после раздела «Критичные требования»:

```
<!-- BFT-HEAD-END · ГРАНИЦА ШАПКИ · выше bft-fast, ниже bft-deep · шапку не затирать -->
```

Не переформулировать и не переносить в другое место. Одинакова в `bft-fast` (пишет) и `bft-deep-swarm` (ищет).

## Замороженная область

От строки `## Шапка (сутевое описание запроса)` до строки-границы включительно. `bft-deep-swarm` не меняет здесь ни байта — ни формулировки, ни порядок ID, ни таблицы. Frontmatter и строка-статус — обновляемые, в заморозку не входят: они лежат выше замороженной области.

## Область канона

Всё ниже строки-границы:

- **До deep:** плейсхолдер-заголовок `## ⏳ Полный БФТ — в проработке` + открытое поле по `open_field.md`.
- **После deep:** полный канон MTS в порядке `../../bft-writer/resources/bft_standards.md` §«Порядок разделов», вместо плейсхолдера.

## Порядок якорей поиска границы

`bft-deep-swarm` ищет точку вставки канона в этом порядке:

1. HTML-комментарий `BFT-HEAD-END`.
2. Заголовок `## ⏳ Полный БФТ — в проработке`.
3. Заголовок «Бизнес описание» — первый раздел канона, его наличие означает, что документ уже обогащён. Искать в обеих формах разметки: ATX (`## Бизнес описание`) и Setext (строка `Бизнес описание`, под ней линия `===`). Эталоны канона MTS используют Setext (`../../bft-writer/examples/ideal_bft.md`), поэтому проверка только по `#`-заголовкам даёт ложный «не обогащён».
4. Ничего не найдено → канон дописать в конец файла, ничего не удалять, вывести предупреждение.

## Путь файла

```
<docs_path>/<epic_slug>/<epic_slug>.md
```

`docs_path` из `bft-config.md`, дефолт `.bft/documentation`.
