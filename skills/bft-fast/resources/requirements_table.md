# Вложение — таблица требований на согласование границ (requirements_table.md)

Второй артефакт `/bft-fast` (после письма) — **два csv-файла**: `personas.csv` (контекст о стейкхолдерах) + `requirements.csv` (их ключевые требования в структуре БФТ: БТ/ПТ/ИТ/ФТ/НФТ). Назначение — согласование границ задач на этапе первичного брифинга.

**Пишутся всегда** (не флаг), на диск в `{docs_path}/{epic_slug}/` — открываются в Excel/Sheets. Тело письма остаётся чистым для пересылки; csv отдельными файлами. Сериализация — см. «Форма вывода».

**Главное отличие от полного БФТ:** таблица содержит **только то, что сказали люди на встрече**. Каждая строка формируется из **цитаты** участника. Никакого обогащения, порогов, приоритетов, выдуманных параметров, домысленного ASIS — это скелет на цитатах; детальная проработка и обогащение происходят на следующем этапе (deep `bft-*`).

## Блок персон (домен знаний)

Перед таблицей требований — краткое описание участников: **не каждая цитата является достоверным требованием**, вес реплики зависит от роли и зоны ответственности говорящего (реплика владельца требования весомее реплики вне его зоны). Блок даёт читателю основу для оценки достоверности.

| Колонка | Правило |
|---|---|
| ФИО | из `участники[]` (frontmatter/упоминания) |
| Роль | из явного упоминания в тексте PO; только по контексту встречи → пометить (напр. «PO инициативы»); неизвестно → `[роль не подтверждена]`. Индекс стейкхолдеров на стадии fast не читается — сверку делает `/bft-deep` |
| Влияние | одним предложением — за что этот участник отвечает **в этом БФТ**: что решает, чью зону закрывает, какие вопросы снимает своей репликой; из сказанного на встрече, не из должности; не прозвучало → `[не указано]` |

Правила: ФИО не выдумывать; роль — из сказанного; влияние — только из того, что человек реально решил/озвучил на этой встрече (не общая должностная функция), домысел из поведения помечать, полностью неизвестное → `[не указано]`/`[роль не подтверждена]`. Персоны — кандидаты на сверку с `.bft/index/stakeholders.md` на этапе `/bft-deep` (fast индекс не открывает); это тот самый «домен знаний», по которому взвешивается достоверность цитат — «Влияние» и есть операционализация этой весомости для конкретного документа, не общий департамент.

**Частая ошибка (не делать):** влияние не звучало на встрече, но проставлено по догадке о должности («отвечает за Backend», «QA») — это то же самое, что раньше был выдуманный департамент. Не сказано → `[не указано]`. Формулировка должна быть о **вкладе в этот БФТ** («закрывает вопросы по видимости на сайте»), не о позиции в оргструктуре («Frontend-разработчик»). То же для роли: если человек только подал реплику, но его роль не названа и не в индексе стейкхолдеров → `[роль не подтверждена]`, а не выдуманная «Backend Lead».

## Колонки

| Колонка | Что | Правило |
|---|---|---|
| ID | `{ТИП}-{N}` (локальный) | `БТ-1`, `ПТ-1`, … — тип из префикса; N без ведущих нулей (`БТ-1`, не `БТ-001`) |
| ASIS (сейчас) | как работает сейчас | **только из цитаты**; не озвучено на встрече → `[ASIS не озвучен]`, не додумывать |
| TOBE (после) | как будет после изменения | из цитаты; целевое состояние, которое проговорили |
| Связанные | **только ID** других строк (`БТ-1`, `ПТ-1`), не свободный текст; нет связи → пустая ячейка (не `[не указано]`) | каскад `БТ ← ПТ ← ИТ`, `БТ ← ФТ ← НФТ`; только где связь видна из встречи |
| Источник (цитата) | транскрипт → `ФИО: «…»`; `#summary`-заметка → `Summary: «…»` | обязателен; без цитаты/строки-источника строки нет |

## Фиксированный порядок иерархии

Строки **всегда** в этом порядке (тип — из префикса ID):

1. **Бизнес-требование (БТ)**
2. **Пользовательские требования (ПТ)**
3. **Требование к интерфейсам (ИТ)**
4. **Функциональные требования (ФТ)**
5. **Нефункциональные требования (НФТ)**

Различение типов:
- **БТ** — ценность/зачем (бизнес-требование).
- **ПТ** — что хочет пользователь.
- **ИТ** — что видит/делает актор на экране (интерфейс приёмки), не API.
- **ФТ** — поведение системы на уровне результата.
- **НФТ** — измеримое -ility, **но только если озвучено** (не выдумывать пороги вроде «≤2000ms»).

## Правила грунтования (zero hallucination — критично на брифинге)

1. **Строка ← цитата.** Нет реплики участника, из которой прямо следует требование — строки нет. «Источник» обязателен и непуст.
2. **ASIS только из сказанного.** Текущее состояние — лишь если его проговорили. Не проговорили → `[ASIS не озвучен]`. Не реконструировать «как оно наверное сейчас».
3. **Без обогащения.** Не добавлять пороги, приоритеты, параметры, негативные сценарии, если их не проговорили. Это работа следующего этапа.
4. **Тип по факту.** Включать тип, только если под него есть цитаты. ИТ/НФТ на discovery часто пусты — тогда их в таблице нет, не добивать.
5. **Цитата верна.** Дословно или максимально близко к источнику; ASR-искажения чинить осторожно, смысл не менять. Атрибуция — по говорящему. **Таймстемпы не цитировать** (формат `ФИО: «текст»`, без `(18:37:97)`).
6. **out-of-scope не в таблицу.** Что отнесли к «не делаем»/следующему кварталу — не требование этой итерации (уходит в «Границы» письма, не в таблицу).

## Форма вывода — два csv-файла

Пишутся на диск (не в тело письма). Кодировка **UTF-8 с BOM** (Excel корректно читает кириллицу), разделитель **запятая** `,`, кавычки **RFC-4180**: ячейку с `,`, `"` или переносом строки обернуть в `"…"`, внутренние `"` удвоить (`""`). Первая строка каждого файла — заголовок колонок. Пустая «Связанные» → пустое поле.

### personas.csv — контекст о стейкхолдерах

Колонки: `ФИО,Роль,Влияние`. Одна строка на участника. Неизвестное — `[роль не подтверждена]` / `[не указано]` (правила блока персон выше).

```csv
ФИО,Роль,Влияние
Анастасия Яковлева,PO площадок,Согласовывает открытые вопросы по блоку «Вопрос-ответ» на площадках
Дмитрий Ананьев,Разработка,Реализует блок «Вопрос-ответ» в Direct и на витрине сайта
```

### requirements.csv — их требования

Колонки: `ID,ASIS (сейчас),TOBE (после),Связанные,Источник (цитата)`. Порядок строк БТ→ПТ→ИТ→ФТ→НФТ. Только зафиксированное на встрече; ASIS без реплики → `[ASIS не озвучен]`; без обогащения.

```csv
ID,ASIS (сейчас),TOBE (после),Связанные,Источник (цитата)
БТ-1,[ASIS не озвучен],"Контент-менеджер создаёт, редактирует и скрывает вопросы на карточках без релиза",ПТ-1,"Summary: «добавить вопрос, отредактировать, поменять порядок, скрыть отдельный вопрос»"
ПТ-1,[ASIS не озвучен],"Когда открываю карточку события, площадки или персоны в Direct — добавляю, правлю и скрываю вопросы",БТ-1,"Summary: «В карточке события (а также площадки и персоны) в Direct — раздел «Вопрос-ответ»»"
```

Файлы — часть вложения, отдельно от тела письма (письмо остаётся самодостаточным для пересылки). В чат после письма — строка-ссылка на оба файла (см. `letter_format.md`, «Канал вывода»).

Эти два csv — **единственное** место, где живёт скелет-на-цитатах: в тело документа он не дублируется (ЗМ-018, блок «Критичные требования» из шапки снят). ID здесь — те же, что в каноне после обогащения: `/bft-deep` читает csv и разворачивает каждый ID в типизированную таблицу канона, csv при этом не перенумеровывает.
